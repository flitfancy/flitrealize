# 0.2 处理反复失败

同一问题需要多轮观察、测量或修改才能判断时读取。一次检查能解决的失败直接处理。

## 确定下一项观察

适用情况包括：实际结果与设计不符，资料或回读冲突，相似修改反复失败，或必须通过实验区分几种解释。

再次修改前明确：

- 实际观察、已确认结果和最近改动；
- 仍然成立的几种解释；
- 能排除至少一种解释的最小测试。

优先复用已有日志、测量和文件。证据足够时直接修复；问题只影响局部时，不重查完整项目。

## 实验与恢复

说明本次改变或观察什么、不同结果如何解释，以及需要恢复哪些修改。避免同时改变多个可能原因；没有新信息时不重复类似尝试。

涉及 EDA 现场或未决结果时按 [0.3 共同恢复规则](0.3-easyeda-pro.md#失败与恢复)，本页只组织问题、假设和实验。

原因确认、修复通过，或已经形成明确样机测试后，继续当前设计。工具无法观察、需要实物测量或缺少必要外部信息时，说明下一项最小观察，不继续增加变量。

## 跨任务继续

活动问题、当前判断、下一项测试和需保留／恢复的修改写入同一份 `CURRENT_HANDOFF.md` 的相关章节。原始日志和测量留在项目证据目录。

问题解决后更新该章节和顶部交接，保留判断依据及未验证范围。
