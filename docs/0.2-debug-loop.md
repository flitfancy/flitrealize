0.2 处理反复失败
同一问题需要多轮观察或实验才能判断时读取。一次检查能解决的问题直接处理。

定位问题
先找到失败发生在哪一步，以及最后一个已确认成功的结果。复用已有输入、日志和回执，从失败处继续，不重做已经成功的部分。
区分实际操作失败和检查程序报错；结果不明确时，按 0.3 核对现场后再决定是否重试。

确定下一步
根据现有证据列出仍可能成立的原因，选择能区分这些原因的最小检查或实验。证据已经足够时直接修复。
每轮明确改变什么、观察什么、不同结果说明什么。尽量一次只改变一个可能原因；没有获得新信息时，不重复同样的尝试。

修到对应位置
项目参数或输入有误，修正项目来源；公共工具有误，修正负责该行为的模块；软件接口行为不明确，先做最小复现。
优先使用已有入口。临时方法确有必要时，说明它解决的具体缺口；需要反复使用的处理收回公共工具，避免每个项目重新拼装。

检查与结束
按最初失败的条件验证修复，并检查直接受影响的部分。已有问题、本次增量及失败恢复统一按 0.3 处理。
每轮留下结论：确认了什么、排除了什么、下一步是什么。原因确认且修复通过后，回到当前任务；缺少资料、工具观察能力或实物条件时，记录具体缺项，停止重复尝试。
继续未完成的问题

把当前现象、判断依据、下一项检查及需要保留或恢复的修改，写入 CURRENT_HANDOFF.md 的相关章节。原始日志和测量留在项目证据目录。
解决后更新结论和当前交接，不另建一套问题记录。
