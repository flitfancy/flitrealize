# 0.3 共同执行规则

开始时记录现状、已有问题、本轮改动范围、修复目标和验收要求。与本轮无关且保持不变的旧问题报告但不阻断；本次不新增、不加重，指定修复目标按约定验收。

检查包含相关外部对象及跨界影响。非加重按对象、规则和前后事实逐条比较，不能用总数或总分替代。证据不足时指出缺项和影响，定向补查；身份或来源不可靠、所需规则或几何缺失、本轮硬要求未满足，不能当作可保留旧违规。

本页统一共同原则和继续、停止、完成、恢复条件。具体计算、判定方法、证据和支持范围由各步骤说明规定，各入口的实现与差异由对应操作说明维护。

## 先找实际入口

首次现场执行、目标或通道变化、执行边界需确认或结果未决时读取本页；同一任务复用已确认规则。普通离线计算不以连接 EDA 为前置。

按用途查询本地能力清单，查询不连接 EDA：

```text
node <skill>/scripts/action-runner.mjs list --domain <schematic|pcb|system> --query <用途短词>
```

按返回的操作说明、入口、模式和支持边界选用已有方法；调用与写入参数按对应说明，已有授权不重复询问。发现结果和执行字段见[执行数据约定](../schemas/execution.md#发现返回与路径)，无命中时核对用词及已有入口，再查[阶段导航](0.0-overview.md)。软件接入见 [0.4-r](providers/easyeda-pro/0.4-r-environment.md)。

## 现场边界与验证

操作前核对项目、目标文档、范围和预期增量，以权威源文件或结构化回读为依据，画布只作视觉检查。已有违规比较、期间现场变化对候选的影响、失败与未知结果恢复分别判断，不能合成一个放行条件。

现场变化后重新读取，按差异及依赖判断候选是否仍适用。能证明无干涉的范围外变化保留并继续；影响本次写入或无法判断时，停止写入并补查或重新规划。候选保持原始绑定，只写相对原输入的授权增量，核对本轮结果及范围外保留，不覆盖期间用户修改。

预检到修改、修改到保存期间发现变化时，先停止后续写入并对账，再按影响和对应入口重验或续接。执行期间避免第二个写入者。

现场修改沿已有入口完成 `读取 → 计划 → 修改 → 回读 → 保存 → 保存后核对`。按公共入口的保存回执和保存后核对结果确认完成；结果缺失或矛盾时，只补查对应问题。结果完整一致且本轮验收满足时收尾。

写入、保存和各项验证分别记录范围与证据，局部通过不替代其他验收。保存已确认的事实不因后续回读失败抹除，此时只补查回读；回读也不单独证明保存。只读检查不要求修改或保存。

### 代表核验

新入口或原生方法、相关通道或政策变化、证据失效时核验代表对象。条件与版本仍一致时复用证据，不每轮重跑；代表证据不代替本轮目标与实际结果核对。

## 失败与恢复

先保留报告、原请求和会话，核对绑定目标及提交内容，查询原请求终态并对照现场。明确失败或非零退出码不证明零写入；超时、查询不到、回执缺失或矛盾也不证明未写入或保存。终态未明时停止冲突写入，不得重放旧写入、换新批次或删占用记录绕过。

- 已证实零写入失败：原请求已终结，证据确认修改未开始、保存未启动时，可对当前现场重新预检；不能把所有失败都视为零写入。
- 已确认部分结果：按本次对象与回读证据补齐必要增量，保留用户修改。
- 仅保存失败：确认修改已成功且现场仍匹配后，只续保存链，不重做修改。
- 撤销：仅处理能证明由本次创建的对象；来源、目标或恢复完整性不明时不删除、不报告回滚完成。

来源或实现绑定变化时说明差异、影响和下一步，不自动重绑候选。迟到结果只作补充证据，不改写旧回执或自动释放占用；续接与关闭按对应操作说明。备份只用于对账和有范围的恢复，不整图覆盖后续修改。

原请求查询方式见对应软件说明；EasyEDA Pro 见 [0.4-r](providers/easyeda-pro/0.4-r-environment.md#查询中断的请求)。查询不重放代码。

## 完成范围

只交付本次要求及验证范围。稳定结论按 [0.1 文稿约定](0.1-continuation.md)同步拥有事实的制品和相关正文，不擅自展开后续阶段。
