# 0.5 文稿工具与续接记录

使用事实表生成工具、首次建立结构化记录或排查本地引用时读本页。文稿内容与更新方式见 [0.1](0.1-continuation.md)，面板标记见 [项目状态面板](../schemas/project-records.md#面板标记)。普通文字续接不需要采用下列工具或格式。

## 按需生成原理图事实表

[handoff-sync.mjs](../scripts/handoff-sync.mjs) 只消费已有电路设计稿 v1、可选现场快照 v1 或成功的 `schematic-inspect` 报告，生成器件、引脚网络、NC／DNC 和延期项表格。它不连接 EDA、不调用连线规划器，也不更新其他项目状态。

```text
node <skill>/scripts/handoff-sync.mjs --project-root <项目> --contract design/contract.json [--snapshot evidence/inspect.json] [--connections design/connections.json]
```

路径从项目根目录解析，须为项目内文件。`--connections` 只读取已有配置的预期目标、`deferredComponents` 和 `providerPinNoConnect`，不读取布局或连线策略。

| 参数 | 行为 |
| --- | --- |
| 默认 | 输出简短预览摘要，不写文稿 |
| `--print` | 在默认预览中输出完整拟生成区，不能与检查或写入模式并用 |
| `--check` | 只比较现有生成区与输入；退出码 1 表示缺失、变化或人工编辑，2 表示输入或调用错误 |
| `--apply` | 本次需要更新时，替换已有文稿中唯一的生成区 |

初次采用时选择插入位置，按[事实表标记约定](../schemas/project-records.md#自动事实表标记)放入空区域；脚本不自动创建文稿或追加区域。

写入保留区域外文字。内容相同不写文件、不刷新时间；生成区被人工编辑时拒绝覆盖。默认预览和检查不产生报告、缓存或状态文件。输入或文稿在生成期间变化时停止写入；项目外输入、链接文稿和异常生成区按现有检查拒绝，写入文稿须为单链接的普通文件。

表格分列设计意图和快照观察，保留输入指纹、目标及快照原始时间。缺少映射、型号、封装或实际网络时显示未提供／未核验；快照未报告网络不等于引脚未连接。工具不解析任意 DRC 或保存报告、不推断库存，也不验证电路语义。

## 可选结构化记录

长流程可在同一份 `CURRENT_HANDOFF.md` 顶部保留一个 `flitrealize-handoff` 块，记录当前入口、输入版本、证据和检查范围。技术字段可折叠；它不代替正文中的设计、引脚和布局表，已有纯文字文稿不必迁移。实际引用检查由 [handoff-check.mjs](../scripts/handoff-check.mjs)完成。

## 最小格式与字段

记录示例、目标身份、路径、指纹和检查引用统一见[项目记录数据约定](../schemas/project-records.md#结构化交接记录)。

## 读取指纹

```text
node <skill>/scripts/handoff-check.mjs fingerprint --project-root <项目绝对路径> --file <项目相对文件>
node <skill>/scripts/handoff-check.mjs fingerprint --project-root <项目绝对路径> --root skill --file scripts/<入口>
node <skill>/scripts/handoff-check.mjs inspect --project-root <项目绝对路径>
```

`inspect` 的退出码 0 表示结构和本地指纹一致，1 表示引用缺失或变化，2 表示旧格式、缺少记录或输入无效。`fingerprint` 只读取指定文件的哈希。这些命令不改写文稿或哈希、不执行记录中的入口、不连接 EDA；本地引用一致不证明检查结论真实。

文件变化后按 [0.1](0.1-continuation.md#信息归属与更新)核对受影响事实，再更新记录。现场变化、保存和未知结果按 [0.3 共同规则](0.3-easyeda-pro.md#失败与恢复)处理。
