# 2.1 原理图设计与电路设计稿

拿到当前方案和器件选择，把功能、电源、接口和保护要求落实为电路。电路设计稿保存连接意图和约束，EDA 文件保存实际实现，主文稿说明方案与理由。已有单项操作直接进入对应说明，从本次缺口继续。

## 上游提供什么

| 来源 | 本次需要的内容 |
| --- | --- |
| [需求与架构](1.1-requirements-and-architecture.md) | 功能块、工作条件、电源、接口和机械限制 |
| [器件选择](1.2-parts.md) | 当前器件或规格、封装、资料依据及未决项 |

会改变本次电路成立条件的架构、器件或引脚缺口先处理；其他已明确部分可以继续。

## 设计本次电路

按功能块说明工作方式，确定器件用途、引脚连接、网络、电源域、接口和默认状态。保护、启动、故障关断及固件依赖要对应当前器件资料和实际使用条件。关键计算保留条件、结果和设计余量。

选型允许按规格替代时，保留完整规格和替代条件；依赖具体型号行为时，核对准确型号。封装与身份分别确认，未决项说明影响及继续条件。需要填写电路设计稿时才读[字段与检查器参考](technical/schematic-contract.md)，字段格式以结构定义为准。

实现使用 [EasyEDA 原理图操作](providers/easyeda-pro/2.2-schematic-workflow.md)，按已接受选择绑定符号、封装和引脚。现场目标、写入、保存及未知结果沿 [0.3 共同规则](0.3-easyeda-pro.md)，不在本页另设执行流程。

## 新器件命名

保留 R/C/U 等类型前缀，位号尽量体现功能块、电气用途或簇归属。默认不超过 4 字符，不必写满；保证项目内唯一，块码和用途码在项目中统一对照。

“类型＋块码＋用途码＋区分”是可选编码思路，不要求所有器件固定四段，也不把区分符限制为一位数字。歧义、编号容量等情况可有少量必要例外，明确理由，并按实测丝印尺寸排布和核验，不默默缩小字体。

完整关系保留在结构化记录中，使用稳定对象身份、引脚和网络来源核对。共享器件不硬归单芯片，不能凭位号推断电气连接；位置变化不触发自动改名。

已有工程改名时，先评审新旧位号映射，再同步原理图、PCB、电路设计稿、项目配置、生成器引用和对应文字属性，并核对一致性。命名规则本身不触发自动迁移。

## 引脚调整

需要调整引脚时，核对候选引脚的功能复用、电气能力、上电默认状态、调试用途及固件依赖，并遵守项目已有固定要求。

确定调整后，同步电路设计稿端点、软件适配层映射、实际原理图和受影响的固件接口，在主文稿记录理由。

## 向 PCB 传递什么

交出功能块、器件与引脚网络、接口、电源关系，以及会影响布局和走线的电气要求。去耦、采样、功率路径等关系说明服务对象、端点、网络和依据；器件用途本身不产生距离数值。

要求与来源留在电路设计稿和设计计算中；必要布局字段见[布局输入参考](technical/pcb-layout-inputs.md)。接口侧别、安装空间与装配要求归项目 PCB 配置，实际位置和焊盘几何由 PCB 回读取得。布局中形成的新电气决定补回电路意图。

## 检查与交接

先核对本次器件、引脚、网络、NC／DNC、电源和接口关系，再核对拓扑、额定值、默认状态与保护行为。结构检查器的调用和结果范围见[技术参考](technical/schematic-contract.md#检查器调用与结果)；结构通过不能替代电路判断。

按本次实现范围确认器件、封装、引脚与连接是否具备。未决条件不能只因结构报告允许继续就当作已解决；探索性工作说明输入和假设，实际求解或写入仍满足对应入口要求。

实现后，对照电路设计稿与实际器件、引脚、网络及属性，差异回到拥有错误事实的一侧修正。交给 PCB 的是当前电路设计稿、对应原理图与保存状态、连接核对、相关电气要求及未决项。

主文稿保留电路工作方式、关键计算、完整可读器件／引脚表和当前检查结论。按 [0.1](0.1-continuation.md#信息归属与更新)更新受影响部分，再进入[转 PCB 并核对](3.1-pcb-review.md#从原理图转-pcb-并核对)。
