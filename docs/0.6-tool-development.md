# 0.6 工具开发说明

修改工具、能力发现或软件适配层时读本页。

## 各层负责什么

| 层 | 负责内容 |
| --- | --- |
| `SKILL.md` | 本次范围、项目续接与阶段导航 |
| `docs/` 专项文档 | 工程流程、用法、支持范围与验收 |
| CLI／manifest | 发现能力、解析输入、衔接执行并保留结果 |
| 实现模块 | 计算、检查与软件原生操作 |

数据格式与字段集中在 [schemas](../schemas/README.md)；事实归属与文稿更新按 [0.1](0.1-continuation.md#信息归属与更新)，执行、失败与恢复按 [0.3](0.3-easyeda-pro.md)。本页只说明开发分工和验证要求。

## 改动放在哪里

| 改动 | 位置 |
| --- | --- |
| 命令入口、输入解析与流程衔接 | `scripts/*.mjs`；能力登记在 `scripts/actions/manifest.json` |
| 公共布局与走线算法 | `scripts/pcb-layout/`、`scripts/pcb-routing/` |
| EasyEDA 原生转换与操作 | `scripts/providers/easyeda-pro/`、`scripts/actions/easyeda-pro/` |
| 连接、会话与传输 | `scripts/eda-host.mjs`、`scripts/providers/easyeda-pro/cli-channel.mjs` 及内置 `adapters/easyeda-pro/` |

公共算法使用[布局标准化接口](../schemas/pcb-layout.md#布局标准化与原生观察)，原生身份、坐标、层和网表由软件适配层解释。项目参数与器件例外留在项目，通用模块不写入某块板的位号、UUID 或安装路径。原生文件与实现一并纳入发布清单和实现指纹。

EasyEDA 通道由原宿主调度，高层入口复用注册配置与会话；API 资料更新和 DOCHEAD 源码规范化见[内置适配器 README](../adapters/easyeda-pro/README.md#来源与-api-资料)。登记其他软件前，先完成对应实现与验证。

## 复用现有入口

先按 [0.3 的能力查询](0.3-easyeda-pro.md#先找实际入口)查用途和支持范围；内部项用 `node scripts/action-runner.mjs list --full` 查看，不另建能力目录。发现元数据、状态与回执见[执行数据约定](../schemas/execution.md)。查询只读本地文件，不连接 EDA 或生成项目报告。

操作应能独立验证。输入输出稳定且需要重复衔接时，用薄入口连接已有操作，不新增通用工作流语言。布局范围、块模板与候选验收分别复用 `scopeLayoutModel()`、`createRigidBlockAtlas()` 和 `validatePlan()`；后端 model／IR 是派生结果。

模块兼作 CLI 时，用 `scripts/lib/cli-entrypoint.mjs` 的 `isDirectExecution(import.meta.url)` 控制启动，导入时不执行命令；验证入口为 `tests/repository/cli-entrypoints.test.mjs`。纯启动脚本或服务没有导入接口时，无需增加这层判断。

## 如何验证

在仓库根目录运行 `python scripts/validate.py`，再按改动选择 `node --test tests/<功能分类>/<相关文件>.test.mjs` 或 `python -m unittest discover -s tests -p "test_*.py"`；完整 Node 测试入口为 `node scripts/run-tests.mjs`，统一收集顶层 `tests/` 下的功能分类，包括 View State。共享样例留在 `tests/fixtures/`，辅助代码留在 `tests/helpers/`；`manual/` 不进入自动收集。

- 输入与发现：覆盖转换、缺项、冲突，以及入口存在、用途命中、域隔离和无结果情况。
- 计算与验收：检查约束是否生效，用独立验收核对候选及范围外对象，不能只看求解器成功。
- 失败与恢复：检查状态映射、原请求／会话、对象归属和分步回执，验证实现能支撑 [0.3 的恢复规则](0.3-easyeda-pro.md#失败与恢复)；未实现的恢复方式不登记为能力。
- 原生改动：先用隔离样例，再按 [0.3 的代表核验](0.3-easyeda-pro.md#代表核验)验证适用现场；会话探测不代替原生写入验证。

沿一条实际流程核对说明、入口、实现和报告是否一致。分别报告自动测试、现场只读及真实写入后的验证范围与未覆盖项。运行输入与分步报告留在项目运行目录，需要恢复或追溯时保留；稳定证据按 [0.1](0.1-continuation.md#信息归属与更新)归档并引用，`handoff-check` 只检查引用完整性。
