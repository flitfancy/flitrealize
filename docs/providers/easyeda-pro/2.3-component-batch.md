# 2.3 已确认器件的批量放件与续接

只在需要批量放入原理图，或恢复这条入口中断的器件批次时读取。普通设计与连线沿用 [2.2 原理图工作流](2.2-schematic-workflow.md)。

## 实际入口与范围

使用 [schematic-components.mjs](../../../scripts/schematic-components.mjs)，不要临时拼装多步命令，也不要把流程名称当操作名称：

```text
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --input-file <项目内输入 JSON> --window-id <实际窗口>
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --input-file <项目内输入 JSON> --window-id <实际窗口> --apply
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --resume <原 runDir> --window-id <实际窗口>
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --resume <原 runDir> --window-id <实际窗口> --apply
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --resume <原 runDir> --window-id <实际窗口> --close
```

默认模式读取当前 EDA、生成计划，并在项目 `evidence/` 中保存本地制品；“不写 EDA”不等于“不产生本地文件”。`--apply` 才允许本次放件和保存；续接不继承旧调用的写权限。用户当前请求已经包括写入时由执行者按范围传参，不新增审批。

入口使用现有操作，顺序是：电路设计稿结构检查 → 已选器件绑定 → 功能块放置计划 → 源码备份 → 首个代表器件放置与回读 → 分批放置与回读 → 保存后再回读。

本轮只完成放件，不自动连线、修改已有器件、整图几何重排或运行整图 DRC。批量前器件身份、封装和映射须已按项目需求确认；该入口不替代库存匹配、选料或引脚电气判断。绑定缺失时复用 resolver 的唯一准确匹配规则，歧义仍阻止写入。新入口通过隔离模拟测试，尚未完成真实 EDA 集成验收；首次用于现场先核验代表批次。

## 输入

新器件位号按[通用命名规则](../../2.1-schematic-contract.md#新器件命名)在电路设计稿中确定。本入口按本次 `designators` 和电路设计稿写入并回读位号，不重新命名已有对象。

文件路径与目标身份的解释见[批量放件路径约定](../../../schemas/schematic-operations.md#批量放件路径)。

请求示例、成员与绑定字段见[批量放件数据约定](../../../schemas/schematic-operations.md#批量放件输入)。

- 无已确认创建记录时，先单独放置并验证第一个器件，再扩展到批量。陌生器件类型需要额外身份核验时，先把对应代表项作为独立小批次。
- 整份电路设计稿的结构审计为 `passed` 或 `conditional` 后，只为 `designators` 范围解析绑定和布局。本批器件需具备准确库绑定、引脚映射，以及用于显示 Value 的 `identity.value` 或 `identity.mpn`；只有 `description` 的通用规格需先补齐本次实现所需数据。其他器件尚未确定或没有绑定可保留在电路设计稿中。
- 布局仍使用现有生成器的几何估计，不会为已有画布自动避障。执行前用默认计划和现场确认新区有空间；已有位号冲突会直接拒绝，不尝试覆盖或自动认领。
- 旧计划遇到现场外部变化时，放行还需每个目标的 `catalog.<位号>.symbol.occupancy`：`unit: "easyeda-schematic"`、准确 `libraryUuid/deviceUuid`、`value`、本次 `rotation/mirror`、`includesAttributes: true`，以及该朝向下包含实际属性占位的 `bounds: {minX,maxX,minY,maxY}`，边界相对于 Provider 创建参数的锚点。使用已确认的原生几何，不能填布局估计。`position` 直接传给 Provider，布局器的中心矩形仅用于排版，单独 width/height 不能证明原生符号居中；occupancy 已对应本次原生旋转/镜像，入口不猜变换规则或换算单位。现场还需原生 `sch_Primitive.getPrimitivesBBox`、完整引脚和原生源码归属回读。缺数据时分别报 `LOCAL_TARGET_GEOMETRY_UNAVAILABLE`／`LOCAL_OCCUPANCY_UNAVAILABLE`，不以半径或重新布局替代证明。普通无变化批次不新增几何输入要求。

## 输出和证据归属

输出文件、状态及保存字段见[批次结果约定](../../../schemas/schematic-operations.md#批次结果与制品)。

每个批次只把稳定结论、当前证据入口和最小下一步同步到 `CURRENT_HANDOFF.md` 对应章节，按 [0.1 续接规则](../../0.1-continuation.md) 维护。不要把整份事务日志复制进主文稿，也不要只把创建 ID 放在聊天里。

## 中断后的判断

先用原 `runDir` 的 `--resume` 只读核对。即使输入、脚本或现场已经变化，也保留 `reconciliation` 差异报告，不在读取前一概拒绝。确认旧计划仍适用才加 `--apply`：JSON 空白和键顺序变化不挡续放；电路设计稿按本批选定位号所需内容比较。脚本仍用字节指纹，脚本变更或实质输入变更后需要新计划，不猜测代码语义。

若决定放弃旧计划，用 `--resume <runDir> --close`（与 `--apply` 互斥）。入口核对现场，确认没有未知/执行中的写入后记录差异，结束本地事务并释放活动标记；不会删除、改名或认领 EDA 对象，也不宣称整批完成或已保存。关闭后不能继续旧 apply；按当前事实另建增量计划。旧批次缺少语义快照时，仍可只读核对或安全关闭，不推测原输入来续写。

| 情况 | 入口行为 |
| --- | --- |
| 有确定的部分失败回执 | 回读并匹配已创建 ID、位号、几何和可取得的库身份；后一次 `--resume --apply` 只补确认缺失的部分 |
| 组件创建后位号设置失败 | 保留刚取得的 ID，发现对象不符合计划时停止，供人工核对；不重复创建来替代异常对象 |
| 只在保存步骤失败 | 已验证放件保留；续接先回读，再保存，不重做放件 |
| 进程断在操作已落盘回执之后 | 读取该步骤真实终态回执，核对现场，再继续 |
| 超时且没有确定终态 | 即使当前有部分对象，也不能证明旧操作结束；记录只读回读后停止新写入，不盲重试 |
| 原有范围外器件移动、属性变化或新增对象 | 准确目标矩形与完整原生占位证明无干涉时保留并继续；在 `reconciliation.preservedChanges`／结果 `preservedChanges` 中记录，不改原计划与来源指纹，也不认领新增对象 |
| 目标位号被占用、重复位号、目标位置冲突，或已创建对象身份／属性／引脚网络变化 | 记录冲突并阻止旧 apply；证据不足同样停止。已知终态的旧事务可 close 后重规划，不自动删除、改名或覆盖 |

`evidence/.schematic-components.lock` 防止两个入口同时运行；进程被强杀后可能保留锁，不自动按 PID 或时长抢锁。`evidence/.schematic-components-active.json` 指向仍有未解决写入的批次，防止另建批次绕过未知结果。这两个文件只是本地事务保护，不证明浏览器没有其他写入者。

遇到遗留锁，先确认本机旧进程及远端 EDA 操作已经停止，再由执行者只移除已核实的锁并续接。未知写入没有确定终态时不能 close；不伪造 report、删活动指针或改状态来强行续跑。此入口不提供 `--force`，也不能保证断电/超时后完全自动恢复。

## 底层操作的边界

放件操作仍支持原有单步接口和受指纹约束的显式回滚。批量封装给计划传 `failurePolicy: preserve`：失败保留已创建对象与证据，不自动回滚整个批次。读取失败不再当空图；取得 ID 后先确认不是原有或本批已创建 ID，再立即记录所有权；不因接口返回已有 ID 而修改或删除原有对象；目标切换时不在新文档继续修改或回滚。

放行后另记本轮 `executionBaseline`，原始 `prepared.json` 和创建回执不刷新。每次写入使用本轮 `executionSource`；底层在创建／属性修改前及回读时保护源码，入口写后同时对照已创建对象和本轮范围外内容。预检之后新出现的外部变化仍停止，不沿循环重新认定为无关变化。创建或属性写入抛异常且结果未知时保留占用，不因部分回读看似正常而重放。

外部变化放行的代表回读还确认实际原生边界没有超出已声明的锚点相对边界；不符时报 `LOCAL_TARGET_GEOMETRY_MISMATCH` 并停止扩批。此回读是再次核验，不代替写入前已有准确几何依据的要求。纯线／文字源码未知或解析失败同样明确阻断，不能因器件列表没变而忽略。

现场占位也单独读取源码 `ATTR` 的原生边界，器件本体包围盒不能代替文字属性的范围。属性边界读取缺失时停止；远处器件的文字属性侵入目标位置仍是冲突。

保存操作默认仍保存并检查 DRC；仅此放件入口显式传 `runDrc: false`，避免把尚未连线的原理图当完成图来验收。保存前后保护完整的本轮源码，范围外内容被改回旧基线也会报错；保存已发生和整批通过分别记录。后续完成连接后仍按 2.2 运行完整保存/DRC 流程。

无变化批次仍是原入口的已读取属性检查；变化放行只覆盖已完整读取且符合准确目标几何约定的情况，不声称未知图元已安全。原生 API 没有跨读取／写入的原子版本锁，回读保护不能替代单写入者约束。源码备份只用于对账和有范围的恢复，不自动整图导入覆盖。
