# 2.1-r 原理图连接与收尾入口

电路设计稿、器件和引脚映射已确认，准备生成端点短线与网络标识，或复核这种原理图的完成情况时读取。入口复用现有操作，适用于不同器件、网络、功能分组与项目。

```text
node <skill>/scripts/schematic-connect.mjs --project-root <project> --input-file <input.json> --path-base project --window-id <window>
node <skill>/scripts/schematic-connect.mjs --project-root <project> --input-file <input.json> --path-base project --window-id <window> --apply
node <skill>/scripts/schematic-connect.mjs --project-root <project> --input-file <input.json> --path-base project --window-id <window> --check
```

- 默认：只读现场、生成缺项计划和证据，不修改 EDA。
- `--apply`：执行缺少的连接，验证，按配置重排，保存并执行严格 DRC，再对照保存后的实际端点和标签。
- `--check`：对照电路设计稿检查已有连接、NC、标签及严格 DRC；配置了重排时也检查布局是否收敛。不会保存，不能据此宣称本次确认了保存。

## 输入

输入文件与电路设计稿的路径基准见[连接路径约定](../../../schemas/schematic-operations.md#连接路径解释)。

请求示例、成员范围、延期项、NC／DNC 和重排字段见[连接数据约定](../../../schemas/schematic-operations.md#连接请求)。

## 哪些步骤保证执行

入口每次计算导线、标识和 NC 的适用性与实际缺项。没有 NC 时记录 `not-applicable`；已有标识通过实际位置、网络与显示属性检查后复用。必需步骤无缺项时不重复创建对象。

```text
电路设计稿 + 当前引脚/导线/标识
→ 缺项计划与冲突检查
→ 分批补齐导线与标识、处理声明的 NC
→ 对照端点/网络/NC/可见标签
→ 配置要求的 complete 重排与再次对照
→ 保存 + 严格 DRC
→ 保存后端点与标签复核
```

网络标识创建固定使用 `showName: false`，导线 `NET` 为可见网络名称。已有重复显示会明确报出，布局阶段不承担隐藏或修补职责。

重排使用本项目已有 `reflow` 配置，不猜布局偏好。未提供配置时明确记录未请求重排；也可写 `{"mode":"preserve","reason":"本次只补 NC，保留已确认布局"}`。需要初排时，在连接前调用现有 `schematic-reflow initial`。

自动生成目前支持直端点短线和标识。实际导线更长、连接多个引脚、含总线或层次关系时，会报告当前自动化范围不匹配；可按 [原理图实现](2.1-r-schematic-workflow.md) 使用相应方法完成。该限制属于这个端点短线入口，不限制 Skill 的电路或画图方法。

连接复核支持完整重排生成的标准接地折线，以及原生线段顺序和方向变化。固定折线规则见[原理图重排说明](2.1-r-schematic-workflow.md#2-按电路设计稿完成连接)，接受长度及开关见[接地路线数据约定](../../../schemas/schematic-operations.md#接地路线选项)。同器件、同网络且重合的物理端点共用一条短线和一个标识；不同网络或跨器件接触仍阻止写入。

## 证据与恢复

每次运行把输入、逐步请求、操作报告和最终结果保存在项目 `evidence/schematic-connect/`；写入前另存原生源码备份。不会自动重写电路设计稿或项目主文稿。

局部预检比较本次器件的完整回读属性、引脚身份／位置／网络及相关网络的完整成员。范围外且不属于相关网络的 BOM／PCB 包含标志可保留；已有对象的纯坐标／旋转／镜像变化和远处文字增改，只有原生符号、属性和文字边界证明未进入本次符号、引脚短线及已有相关导线区域时才继续。结果记录 `preservedChanges`；采用最新现场作为本轮执行保护，保留原 `wirePlan.source`、路径和计划指纹。目标、相关连线／端口／成员变化、重复目标、设置变化、电气属性变化或缺少可靠边界仍停止。

连接计划在 `wirePlan.source.nativeSource/localDependencies` 冻结原生源码、对象／网络依赖、必要区域及原生占位。带源码的读取复用放件入口的原生边界读取，并核对两次读取的来源一致。空间差异同时检查变化前后的实际边界，不能因对象已移出目标区便认定原先无关。`schematic-wire-create.analyzePlan()` 独立比较原始来源与现场差异，必要时重读原生边界；不会用最新全图几何指纹替换原 `source.geometryFingerprint`。旧 WirePlan 缺少这些证据时仍采用全图严格检查；删对象、新增电气图元、未知源码类型及无法证明的变化仍阻断。

写入批次和保存前后保护本轮源码：导线／标识只排除该批有回执的新建 ID，NC 只允许已声明引脚的 Boolean 或原生 `NO_CONNECT` 属性增量。预检以后出现的新变化停止后续写入；保存后的范围外内容同样必须保持。`schematic-net-flag.applyNameVisibility()` 为隐藏 Name 和修正标识方向仍调用整份 `setDocumentSource()`，输出基于本次最新源码，导入前再次核对该完整源码、导入后完整回读；导入异常结果未明时保留占用，不重放。原生接口没有原子比较并导入能力，最后读取至导入之间仍需单写入者，不能宣称对并发覆盖已有原子保护。

整图 reflow 涉及全部源码，继续采用整图未变化预检与原有源／计划指纹保护，不使用局部放行规则。

重复运行通过现场重新计算缺项；已有正确导线与标识不会再次生成。已知失败保留已完成结果，下一次只在重新对账后处理缺项。布局已完成但保存/DRC 失败时，仍报告各阶段真实状态，不把 `saved: true` 当成全部成功。

首次写入前通过现有 `schematic-save-verify inspect` 捕获源码绑定的完整 DRC baseline，沿逐步回执传到保存请求 `drcBaseline`。前后完整记录按多重集对应对象、规则及全部原始内容；相同旧项可保留，已消除项可减少，同数换问题、新增或重复增加均阻断。`drc.passed` 保持严格零违规语义，`drc.comparison.passed` 单独表示本轮增量验收。当前没有已核实的原生测量比较字段，任何记录内容变化（包括测量变化）均需对账；不按总数或猜测严重程度放行。计数、布尔值、缺少对象／规则、来源或完整 baseline 时退回严格零违规。`--check` 没有旧执行 baseline，仍严格检查当前整图。

保存明确返回成功后即保留 `saved: true`；后续回读或 DRC 失败只阻断完成结论。明确返回 `false` 的仅保存失败，确认现场仍匹配后续保存，不重做连接。保存抛异常或没有确定返回值时记录 `outcome-unknown, saved:null, uncertainWrite:true`，继续保留占用并停止，不当作普通保存失败重试。

通信丢失或写入终态不明会保留同目标的占用文件，并阻止新的写入批次绕过。按 [软件适配层恢复](../../0.3-easyeda-pro.md#失败与恢复) 查询原请求、核对现场后处理；本入口不会自行清除未知写入或整图回滚。`--check` 仍可作只读诊断。

只有所选范围的连接审计、要求的布局检查、保存与 DRC 增量验收均成功，`--apply` 才返回 `ok: true`。连接审计的明确修复目标仍须达标，不能用相同旧 DRC 豁免。局部范围、明确延后器件及未请求重排仍在结果中保留，电气功能与硬件性能需单独验证。
