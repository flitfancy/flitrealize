# 3.6 PCB 布线规则与优先级

整理网络分类、宽度与布线顺序，或从已有规则生成改宽／配色输入时读取。设计依据见 [3.1 PCB 设计](../../3.1-pcb-review.md)。本页是本地规划；用途与配色的布局前流程只在 [3.4](3.4-pcb-net-color.md#布局前的配色顺序)维护，需要改宽时再读 [3.7](3.7-pcb-trace-width.md)，无需读取布局说明。

## 网络规则与优先级

`pcb-routing-plan` 是本地操作，不需要 Bridge：

输入、分类、宽度与排序字段见[网络规则数据约定](../../../schemas/pcb-routing.md#网络规则规划输入)。

规划输出状态见[数据约定](../../../schemas/pcb-routing.md#规划输出状态)。后续执行者按序完成关键组，回读拓扑、线宽、连接和 DRC，再继续普通网络；交接中留相应证据。**有序计划不等于自动布线器执行顺序已设置**。

分类覆盖、配色要求及兼容语义见[数据约定](../../../schemas/pcb-routing.md#分类与配色覆盖)。

通过命令取得配色输入：

```text
node <skill>/scripts/action-runner.mjs run --action pcb-routing-plan --project-root <项目> --input-file <布线配置.json> --report-file <项目内规划报告.json> --full
```

确认命令成功后，按[派生请求的读取位置](../../../schemas/pcb-routing.md#派生配色请求的读取位置)取得配色输入，再调用：

```text
node <skill>/scripts/pcb-edit.mjs --project-root <项目> --action pcb-net-color --window-id <窗口> --input-file <配色输入.json> --apply
```

已有 PCB 规则配置作为源时，配色输入为派生产物；分类变化后重新生成，不独立编辑第二套成员。上述例子只展示结构，包含 GND 不代表规划器会生成铺铜。

既有线段角色、改宽与配色派生请求见[数据约定](../../../schemas/pcb-routing.md#线段角色与派生请求)。执行前读取实际线段，并核对网络类成员。

本入口不写 EDA 网络类、不创建线路、不调用自动路由器。via、差分间距、逃逸最大长度和敏感性约束保留为设计与后续检查要求；改线宽脚本不会自动执行这些约束。

需要实际自动走线时，转到 [EasyEDA Pro 分层自动布线](pcb-autorouting.md)的 `pcb-route.mjs`。该入口消费项目角色规则并执行 FR，支持主干与后续支路接续；本页规划器仍只负责其上述输出，不把 planned 当作已执行。

## 同步项目交接

在主文稿“网络规则”的“布线规则与优先级”小节记录网络分类及用途、线宽／过孔依据、执行顺序和权威规则配置；派生输入引用对应来源版本。生成计划仍标 planned，不写成已经布线、改宽或配色。按 [0.1 项目主文稿](../../0.1-continuation.md#pcb-主题与面板对应)同步网络汇总表中受影响的行、该主题的 `ViewState:` 和顶部交接，注明表中数值的来源与计划／实际状态；保留改宽和配色的独立执行证据。
