# 3.5-r PCB 布局与空间

准备布局输入、生成候选、检查空白区域或移动明确器件时读取。布局依据见 [3.1 PCB 设计](../../3.1-pcb-review.md)，输入归属和字段见 [布局输入](../../technical/pcb-layout-inputs.md)。板框创建另见 [3.2 板框、层叠与禁区](3.2-r-pcb-foundation.md)。

## 选择入口

任务按 [3.1](../../3.1-pcb-review.md#本次布局任务)分流，本页维护其在 EasyEDA Pro 中的执行入口。调用前核对本页[块内布局复用能力与已有铜](#块内布局复用能力与已有铜)及所选入口的支持条件。

| 任务 | EasyEDA Pro 执行入口 | 行为 |
| --- | --- | --- |
| 只读检查 | `pcb-placement` 的 `inspect` 模式 | 读取现场；空白分析按需提供边界和约束，见[明确移动与空白分析](#明确移动与空白分析) |
| 明确移动、旋转 | `pcb-edit.mjs --action pcb-placement` | 使用显式移动计划并核验，见[明确移动与空白分析](#明确移动与空白分析) |
| 区域重排 | `pcb-layout.mjs fine` | 公共候选直接应用；外部完整计划经 `adopt` 验收后接同一应用、续存与复核链，见[执行接口](../../technical/pcb-fine-layout-execution.md) |
| 整体安排 | `pcb-layout.mjs --mode semantic`；`pcb-layout.mjs --mode solve --backend cpsat` | 前者仅转换并核对块成员，不生成布局候选；后者执行功能块布局求解。参数及范围见[布局求解参考](../../technical/pcb-layout-inputs.md#布局求解入口与后端) |

求解输入由 `pcb-layout.mjs --mode prepare` 整理；已有选定候选按 `--mode apply` 写入、保存并独立回读。CP-SAT 及 `pcb-block-layout.mjs` 的开放块／带铜模板研究继续按布局求解参考调用。

请求中的 `expectedProjectUuid`、`expectedDocumentUuid` 和窗口由本项目输入绑定。脚本坐标单位为 mil，界面显示单位不改变接口约定。共同目标、保存回读与恢复规则见 [0.3](../../0.3-easyeda-pro.md)。

软件来源字段见[布局数据约定](../../../schemas/pcb-layout.md#软件来源选择)。

## 布局准备与配色检查

生成或刷新布局求解输入时，先拿到 [3.3 布局输入与规则转置](../../3.3-pcb-layout-inputs.md)交出的有效输入。配色的首次准备与后续复用按 [3.4 网络配色](3.4-r-pcb-net-color.md#布局前的配色顺序)执行。用最新实际 PCB 或注明来源的快照准备候选。

颜色不能代替实际 PCB 和网表的连接核对。纯离线或只读 prepare/solve 不附带 EDA 写入；无法完成的配色步骤须记录原因、范围和未完成状态。实际改色仍按本次授权及对应入口执行。

## 输入准备与候选求解

以下依次为输入准备、普通搜索与已有候选应用示例。普通搜索一行省略了 `--backend`，默认使用 `search`；功能块求解须明确使用上表的 `--mode solve --backend cpsat`。

```text
node <skill>/scripts/pcb-layout.mjs --project-root <当前项目> --mode prepare --window-id <窗口>
node <skill>/scripts/pcb-layout.mjs --project-root <当前项目> --mode solve --window-id <窗口>
node <skill>/scripts/pcb-layout.mjs --project-root <当前项目> --mode apply --window-id <窗口> --from <候选目录> --candidate <稳定候选ID>
```

默认模式为 `prepare`。`prepare` 和 `solve` 也可用 `--snapshot <快照文件>` 代替窗口读取，离线结果必须注明来源。`apply` 必须连接当前现场；候选使用报告中的稳定 ID，展示顺序或排名不是 ID。

已有准备结果可用 `--prepared <前次报告目录>` 重放冻结输入，校验内容指纹及实现版本后离线执行，不重新读取 EDA。主入口不提供自动初始化位号选项；准备不会顺带改变现场。

位号命名见[通用命名规则](../../2.1-schematic-contract.md#新器件命名)。本页的位号调整处理位置、朝向和几何验收；文字值以原理图、电路设计稿和现场核对为准。

准备层读取电路设计稿、原生器件／焊盘／位号及项目配置，输出输入包、回执和诊断。AI 根据缺项补充工程意图；身份、网络与坐标由脚本关联。字段见 [布局输入](../../technical/pcb-layout-inputs.md)。

现场归属来自[器件关联焊盘](https://prodocs.lceda.cn/cn/api/reference/pro-api.pcb_primitivecomponent.getallpinsbyprimitiveid.html)及父器件 ID，贯穿规划与写入回读。原生网表作独立交叉核对，形状和孔等[焊盘属性](https://prodocs.lceda.cn/en/api/reference/pro-api.ipcb_primitivepad.html)保留原始观测；输入回执说明未覆盖的范围。

求解配置和有效参数保存在本次证据中。已有起点控制包括 `--start-mode fresh|existing|mixed`、`--starts`、`--start-seed`、`--exploration`、`--start-gap-mil`；`--iterations` 控制搜索预算，`--catalog-count` 控制候选集合规模，权重通过 `--weights-file` 或 `--weight` 显式覆盖。它们是搜索设置，不代替电气或机械要求。从已有布局继续时采用最新现场快照，不用旧候选覆盖用户中间修改。

评分项与权重见[布局输入](../../../schemas/pcb-layout.md#间距和搜索设置)。报告展示分项指标与变化，供比较候选。

候选池的位置去重参数见[布局数据约定](../../../schemas/pcb-layout.md#候选池位置去重)。

当前支持边界：

CP-SAT 和带铜功能块的范围见 [布局求解参考](../../technical/pcb-layout-inputs.md#布局求解入口与后端)。下列为原搜索及原生移动的边界；已有铜的处理见 [块内布局复用能力与已有铜](#块内布局复用能力与已有铜)。

- 原搜索后端支持多起点、局部平移/旋转、位号换侧、局部组和间距调整。任意柔性变形、成员交换和全局电气最优布局仍未实现。
- 当前只接受顶层、正交角度并具有原生可见位号的器件；独立焊盘须关联已纳入 PCB 的单引脚电路设计稿对象。未声明对象、排除却仍存在的对象、已有布线或 Region 会在准备阶段报错，不进入求解。
- 支持固定矩形边界：从原生板框读取，或由 `hard.boardBounds` 指定；两者同时存在须一致。EasyEDA 当前识别单一闭合、轴对齐的矩形折线；其他轮廓或孔槽明确报不支持，不按外接矩形近似。没有板框时继续使用器件包络。
- 固定板框参与起点生成、平移、旋转、组移动及防撞修复，贴边器件直接按真实板边生成位置。位号优先换侧；不能满足空间与固定条件时报告失败，不扩大板框或移动固定件。写回前后核对板框和实际占位，脚本不创建或修改板框。
- 几何求解使用封装和焊盘的轴对齐包围盒。装配边界由明确规则派生，操作空间须提供；精确形状、孔槽和三维干涉不在当前检查范围内。
- 连接距离和网络跨度是布局代理指标。实际铜路径、回流、Kelvin 取样、热设计及整板 DRC 仍需后续检查。输入回执会保留尚未编译或仅部分覆盖的要求。
- 对不支持的输入或未确定的规则报告缺口，不静默转成无约束。不会因零次报错就把未检查范围标为通过。

候选绑定原始快照、有效规则和实现指纹。现场变化由写回预检按本次修改及其依赖核对：可证明无干涉的范围外变化保留并继续；影响本次写入或无法判断时停止。冻结输入或实现指纹不匹配时，按入口提示重新准备或生成候选。候选与回读覆盖器件、位号和焊盘，几何检查仍只说明本次范围。

共同恢复判断见 0.3；本入口的保存恢复参数为：

```text
node <skill>/scripts/pcb-layout.mjs --project-root <当前项目> --mode apply --window-id <窗口> --resume-save <layout-execution-result.json或layout-apply-receipt.json>
```

续存只恢复保存链，不重放移动。`pcb-edit` 与 `pcb-layout` 各自处理对应的恢复报告。

## 明确移动与空白分析

以下命令及输入属于 `pcb-edit`，与上面的求解输入分开。

```text
node <skill>/scripts/pcb-edit.mjs --action pcb-placement --project-root <当前项目> --window-id <窗口> --input-file <plan-input.json>
node <skill>/scripts/pcb-edit.mjs --action pcb-placement --project-root <当前项目> --window-id <窗口> --input-file <plan-input.json> --candidate <唯一候选名> --apply
```

使用 [pcb-edit.mjs](../../../scripts/pcb-edit.mjs) 和下文的 plan 输入，不另造参数格式。默认只读 EDA，但会把计划、输入、源码备份和报告写入本项目 `evidence/pcb-edit/<唯一运行目录>/`。先检查候选 issues 和证据；多候选写入须明确唯一候选名，冲突方案不能执行；普通单方案不填 `--candidate`。

`--apply` 由 `pcb-edit` 衔接完整执行链。需要 inspect 或单独一步时使用 `action-runner.mjs run --action pcb-placement`，沿返回的 `applyRequest`、`verifyRequest`、`saveRequest` 传递；普通完整流程无需手工拆装请求，写入参数按 0.3。

### 移动计划与空白检查

明确移动按已给定的位置和朝向生成计划。需要利用空白区重排时，再固定机械接口与关键功率／敏感功能块，比较允许移动的小块及目标空白区。布局脚本不替你决定电源环路、电气隔离或哪个块重要。

移动计划的输入示例、旋转、固定范围和预留字段见[明确移动数据约定](../../../schemas/pcb-operations.md#明确移动输入)。

- `inspect` 只给目标即可读取完整器件快照；需要空白分析时再给上述边界/约束，不需给移动项。
- 最大空白矩形仅基于网格中的器件/Region 包围盒，不代表可压缩面积或可用布线面积；网格越粗越保守。对侧器件也保守计入，不自动假设可重叠。
- 仅支持明确矩形边界，不处理异形轮廓、孔槽或复杂三维干涉；这些条件不满足时改用真实几何检查，不伪造矩形验收。
- 每批最多 100 个器件、最多 20 个候选、网格最多 100000 格。先比较少量有依据的候选，不枚举任意坐标。
- **已有铜时不执行器件移动**；拒绝范围及处理规则见 [块内布局复用能力与已有铜](#块内布局复用能力与已有铜)。源备份不能解除这项限制。

计划输出见[移动计划数据约定](../../../schemas/pcb-operations.md#明确移动计划输出)。包围盒检查不替代电气与整板验收。

### 明确移动的结果与失败恢复

结果与只读复核的保存字段见[PCB 编辑结果约定](../../../schemas/execution.md#pcb-编辑复核字段)；保存恢复仍按下文执行。

applyRequest 绑定当前源码和已读对象指纹；用户修改、换板或目标错误会被拒绝。调用期间保持单一写入者；本入口没有跨进程事务锁，也没有原理图批量入口的自动续接机制。

保存得到确定失败结果后，使用本项目成功 apply 报告或 result.json 续存：

```text
node <skill>/scripts/pcb-edit.mjs --project-root <当前项目> --window-id <窗口> --resume-save <本项目成功apply报告或result.json> --apply
```

此恢复接口核对原 apply 回执及当前指纹，仅执行 verify → save → verify，不重放 apply；不匹配或未决时按 0.3。

同一成功 apply 的保存尝试会在 `evidence/pcb-edit/save-attempts/` 留下占用记录，防止通过 result、原报告或副本重复发起未决保存。确定终态后释放，未知或进程中断时保留；不要删记录绕过，先确认旧执行结束并核对现场。此记录只保护该保存链，不证明其他 EDA 写入者不存在，也不是新交接文档。

写入失败返回 `apply-failed`、写入前快照、已尝试 ID 及可取得的回读；本入口不自动回滚或保存。未决结果与源码备份的处理按 [0.3](../../0.3-easyeda-pro.md#失败与恢复)。

布局移动使用 [PCB_PrimitiveComponent.modify](https://prodocs.lceda.cn/cn/api/reference/pro-api.pcb_primitivecomponent.modify.html)，读取原生 PrimitiveLock。方法存在不证明当前版本行为，仍执行回读验证。

## 块内布局复用能力与已有铜

| 可复用能力 | 当前边界 |
| --- | --- |
| `pcb-layout.mjs --mode prepare`、现有搜索/CP-SAT 后端 | 关联上游与快照，编译明确关系、固定/旋转及几何规则；调用与字段见[布局与空间](#选择入口)和[功能块求解](../../technical/pcb-layout-inputs.md#布局求解入口与后端) |
| `pcb-layout.mjs fine` | 明确区域、成员和允许让位邻居后，公共入口已衔接全模型求解、独立位号、范围外保持和完整候选验收；已有完整计划接入、试走线、应用、续存和只读复核按[块内布局执行接口](../../technical/pcb-fine-layout-execution.md)分别调用。自动按走线失败选择并移动器件尚未实现 |
| `pcb-preroute.mjs` | 在明确的 board/policy/options 下生成离线出口/路径候选、有限诊断并独立验收；自动把失败定位到该移动的器件并执行移动尚未形成通用闭环 |
| 原生写回 | 完整受支持候选沿现有布局/明确移动入口应用、保存、回读；独立开放块或部分位号候选不能直接当作完整写入计划 |

当前布局几何主要是二维轴对齐包围盒及明确的装配规则。原生 Region 不会自动转换成有用途的布局禁区，准备入口可能拒绝；不能删字段绕过限制。真实高度、三维装配、回流、Kelvin、热和 EMI 不是这些模型的自动验收项。离线带铜模板验证也不代表原生带铜移动已实现。

已有铜时，先只读盘点相关走线、过孔、铺铜和共享连接，区分保留与允许撤回的范围。当前公共布局准备/移动入口拒绝铜层走线、圆弧、折线、过孔或铺铜，块外铜也不豁免。入口不会带动导线、自动清线或重布；离线带铜模板装入和只清理本块铜都不能解除这一限制。

原生移动前，须在已授权范围内用适合的已有工具处理受影响铜，重新读取并确认现场符合所用入口的支持条件。需要扩大撤回范围时先说明受影响对象，按当前授权决定是否继续；不能默认清空整板。无法满足时保留只读/离线分析，或转适合已布线调整的工具。离线分析保留实际障碍和未覆盖项，不通过删铜计数、隐藏 Region 或替换板框伪装可写入现场。共同目标与恢复规则见[0.3](../../0.3-easyeda-pro.md)。
