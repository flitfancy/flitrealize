# 0.4-r EasyEDA Pro 软件通道

首次连接当前主机、选择或确认通道、连接中断或需查询原请求时读取本页。已有连接与确认记录按下文复用；普通离线计算不要求连接 EDA。

本页维护 EasyEDA Pro 的 CLI／Bridge 通道选择、注册、传输、会话复用和请求查询方式。目标确认、保存回读、代表核验触发条件与未知结果处理统一见 [0.3 共同执行规则](../../0.3-easyeda-pro.md)。

## 选择执行通道

客户端 CLI 与网页 Bridge 是同一 EasyEDA 软件适配层的两种通道，仍由原宿主 `eda-host.mjs` 调度，不另建 Skill 或业务入口。

`--channel cli|bridge` 和 `--cli-executable PATH` 是宿主层参数；`pcb-layout`、`pcb-edit`、`pcb-route` 等高层命令仍使用原参数，通过已注册宿主配置选择通道。临时环境配置可用 `FLITREALIZE_EDA_CHANNEL` 和 `FLITREALIZE_EASYEDA_CLI`。路径与会话状态属于本机配置，不写入项目电路设计稿。

客户端可用时先检查其 `doctor`，再检查或复用会话；不要每次操作重新初始化客户端。网页或明确选用 API Gateway + Node Bridge 时才做下方 Bridge 准备，已有连接直接复用。多窗口未明确目标时，可给 `--window-id`，不随意挑选窗口。

## CLI 注册与传输

注册或临时探测使用原宿主参数：

```text
node <skill>/scripts/eda-host.mjs register --eda easyeda-pro --adapter-root <skill>/adapters/easyeda-pro --channel cli --cli-executable <已确认的客户端CLI路径>
node <skill>/scripts/eda-host.mjs status --eda easyeda-pro --channel cli --cli-executable <已确认的客户端CLI路径>
node <skill>/scripts/eda-host.mjs ensure --eda easyeda-pro --channel cli --cli-executable <已确认的客户端CLI路径> --require-eda
```

CLI 的 `register` 用不调用 EDA API 的 UTF-8 脚本核验文件传输，能力记录绑定客户端文件身份、Bridge 版本和已接受字节预算，保存在本机宿主配置。已有注册缺少或失去该记录时，`ensure` 在连接就绪后补齐；仍匹配的确认记录直接复用。

确认后 execute 使用压缩文件上传，返回 `transport.delivery` 和实际上传次数；未确认或身份失配时仍用参数分片并保留原因。代码中存在文件传输、注册成功和实际启用是不同事实，按现场能力回执与实际交付方式核对。传输提速不省略目标绑定、回执、保存或回读，也不重放未知写入。

## Bridge 首次准备

在网页版或使用 Bridge 的桌面编辑器安装并启用 API Gateway 扩展，允许外部交互；同一台电脑以 Node.js 22+ 运行本机 Bridge。EDA 客户端和 Gateway 扩展不包含在 Skill；连接源码位于 `<skill>/adapters/easyeda-pro`。

```text
cd <skill>/adapters/easyeda-pro
npm install
node <skill>/scripts/eda-host.mjs register --eda easyeda-pro --adapter-root <skill>/adapters/easyeda-pro --channel bridge
node <skill>/scripts/eda-host.mjs ensure --eda easyeda-pro --channel bridge --require-eda
```

已注册且配置正确时不重复注册；已连接且目标不变时复用会话。适配器路径保存在本机配置，不写项目电路设计稿。

## 复用与恢复连接

CLI 复用原宿主已确认的客户端与会话，按实际失败点检查 `doctor`、宿主状态与客户端错误；不因每轮聊天重新注册或初始化。

EasyEDA/Bridge 仍可达、网关仍连接且当前项目/文档未切换时直接使用已有通道，不每轮聊天重新 ensure。切换目标按 0.3 核对；手工修改通常只需重新读取文档，不必重连。

连接失败时按实际失败点检查适配器路径、Bridge 状态、Gateway、窗口/文档及本次能力，只恢复受影响的一层；没有新证据时不重复相同重连。连接问题不阻止离线设计或计算。

## 查询中断的请求

原报告带请求 ID 和原会话时，用原宿主及原通道查询：

```text
node <skill>/scripts/eda-host.mjs request --eda easyeda-pro --channel <原通道cli或bridge> --request-id <原请求ID> --session-id <原会话ID>
```

CLI 复用原会话与不可变阶段回执。Bridge 查询使用当前认证读取原会话记录，不自动 ensure、重连或执行代码；不改写操作报告、批次状态或保存占用记录。旧 Bridge 缺少 `request-status` 时保留未决记录，不为升级强行重启。恢复判断按 [0.3](../../0.3-easyeda-pro.md#失败与恢复)，Bridge 请求机制见 [bridge-recovery.md](../../../adapters/easyeda-pro/references/bridge-recovery.md)。

## API 查询

补充原生调用时，先用 `scripts/api-reference.mjs search/show` 定向查看签名、类型及限制；内置语料固定到官方版本与提交，查询返回来源和日期，不证明目标编辑器已支持。新版调用还要核对实际编辑器定义与行为。已有操作正常运行时不重复加载底层 API 文档；修改工具时才读 [操作开发](../../0.6-tool-development.md)。查询筛选、资料来源和更新方式留在 [软件适配器说明](../../../adapters/easyeda-pro/README.md#来源与-api-资料)。
