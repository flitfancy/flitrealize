# 项目初始化、采购与制造交接

新项目根目录、库存/采购身份或制造/下单候选需要处理时读取本参考。跨对话状态归属见 [continuation.md](continuation.md)。

## 只初始化明确的新项目

概念讨论不会创建文件。用户要求初始化时：

1. 使用用户或宿主明确提供的准确目标。只有仍存在多个合理目标时，才询问一个窄的位置问题。保护任何源项目。
2. 选择描述性且不冲突的子目录。目标可能已有工作时停止，不合并进去。
3. 只创建当前需要的文件。只有工作需要跨任务继续时才添加 `CURRENT_HANDOFF.md`；工作进入相应阶段时才创建阶段目录，不建立空占位目录。
4. 只记录本项目已经建立的事实。派生项目可以复用方法或选定源材料，但不能继承基线项目的状态、决策或已通过闸门。

项目结构可按需扩展为：

```text
project/
├── README.md
├── CURRENT_HANDOFF.md       # 仅在需要续接时
├── design/
├── parts/
│   └── datasheets/
├── eda/
│   └── <provider>/
├── evidence/
└── .flitrealize/
    └── runs/
        └── <run-id>/
            ├── inputs/
            ├── bridge/
            └── reports/
```

根目录只作为人类入口。稳定需求、架构、计算、器件决策、测试和机器可读 Contract 放入 `design/`；项目 BOM、库存匹配、批准替代和关键数据手册放入 `parts/`；权威 EDA 源文件与受控导出放入 `eda/<provider>/`；只有被当前项目状态引用的保留证据放入 `evidence/`。

`.flitrealize/runs/<run-id>/` 是可丢弃工作状态，用于生成的 Action 输入、Provider bridge 片段、plan、Snapshot 和瞬态报告。它不得拥有设计意图、权威 EDA 源文件或耐久证据的唯一副本。事务完成对账且不再需要 rollback 前保留该 run；之后删除，除非把选定结果提升到 `evidence/` 并由当前状态引用。通用 bridge server 和 Action runner 留在 Skill 或 Provider adapter 中，不复制到单个项目。

只有相关工作实际存在时才创建 `mechanical/`、`firmware/`、`manufacturing/` 或项目专用 `automation/`。避免 `misc/`、`temp/`、`old/`、`backup/`、`generated/` 等泛化堆放目录。只有外部资料的精确版本支持实质决策或未来可复现性时才归档；普通器件不需要本地保存整份手册。

需要续接时，初始 handoff 只需要：

- 项目身份、明确目标和排除项；
- 来源关系以及未继承旧项目状态这一事实；
- 当前阶段和会改变架构的未知项；
- 一个主要下一决策及成功判据。

本项目产生证据前，不得声称已有活动版本、已通过闸门、已验证器件或权威 EDA 制品。

## 保持制品身份可复现

对已评审基线或下单候选，记录足以可靠配对源和输出的信息：

- 版本/状态、生成时间和时区；
- 源和导出文件名、大小与 SHA-256；
- EDA/工具版本及适用规则/配置身份；
- 板尺寸、层数、有用对象计数和钻孔摘要；
- 评审结果、已接受偏差和证据限定词；
- 实际下单时的订单状态、商城选项和订单号。

不得用后续导出覆盖已评审候选。下载目录是传输位置，批准制品归档到项目根目录。

## 声明共享输入而不复制

项目依赖工作区库存或其他共享 catalog 时，把解析后的路径记录在 `CURRENT_HANDOFF.md` 的 `## Shared inputs` 下；不要把工作区专属路径写死到本 Skill 或可移植 Contract。对于库存，应区分：

- 真值源工作簿或数据库；
- 用于器件匹配的 AI 可读 catalog；
- 数量快照（如果是独立制品）；
- 派生可读文件的刷新命令；
- 允许的访问权限；除非用户授权外部写入，否则默认为只读。

最终选型或采购匹配前读取声明的 AI 可读 catalog。它缺失、不可访问或比真值源更旧时，保持匹配未决；只有刷新命令处于当前可写范围时才执行。不要把整份共享库存复制进项目，只保存项目专属结果，通常为 `parts/inventory-match.csv`，并附足够的来源身份或时间戳以检测过期。

引用共享库存不会自动预留、扣减、购买或编辑库存。这些都是外部状态变更，需要明确授权。

## 分开采购身份

保持以下身份独立：

- 电气作用/数值；
- 制造商器件与批准替代；
- 符号与物理封装；
- 只用于验证 land pattern 的几何 donor；
- 库存记录及实际在手证据；
- 采购动作和数量；
- EDA BOM/PCB 包含标志。

几何 donor 不是采购推荐。购买、预留、扣库存或修改外部库存系统都需要对该动作的授权。

## 按请求层级建立制造包

纯 PCB 订单包含匹配的 Gerber/钻孔包和必要 fab 说明。PCBA 还要按适用范围检查受控 BOM、替代、CPL 面/旋转、极性/pin-1 图、DNP 变体、基准点/工装假设、传感器处理和测试/序列号访问。

付款前，把板厂当前预览/DFM 与归档候选比较。制造包可以对原型达到 `manufacturing-checked`，但这不证明产品或量产准备完成。
