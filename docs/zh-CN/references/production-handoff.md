# 项目初始化、采购与制造交接

新项目根目录、库存/采购身份或制造/下单候选需要处理时读取本参考。跨对话状态归属见 [continuation.md](continuation.md)。

## 只初始化明确的新项目

概念讨论不会创建文件。用户要求初始化时：

1. 使用 `SKILL.md` 的完整根目录/范围锁定。使用用户或宿主明确提供的工作区父目录；如果尚未提供且目标位置会改变结果，只询问一个窄的位置问题。保护任何源项目。
2. 选择描述性且不冲突的子目录。目标可能已有工作时停止，不合并进去。
3. 只创建当前需要的文件：通常是一份指向 `CURRENT_HANDOFF.md` 的简短 `README.md` 和初始 handoff。工作进入相应阶段时再创建更深的 EDA、测试、capture、生成或制品目录。
4. 只记录本项目已经建立的事实。派生项目可以复用方法或选定源材料，但不能继承基线项目的状态、决策或已通过闸门。

项目结构可按需扩展为：

```text
project/
├── README.md
├── CURRENT_HANDOFF.md
├── DESIGN.md 或 project.config.*
├── references/
├── captures/
├── tests/
├── generated/
└── artifacts/
    ├── source/
    ├── gerber/
    ├── assembly/
    └── preview/
```

生成文件保持可重建，不拥有设计意图。只有外部资料的精确版本支持实质决策或未来可复现性时才归档；普通器件不需要本地保存整份手册。

初始 handoff 只需要：

- 项目身份、明确目标和排除项；
- `NEW_PROJECT + FAST_PROTOTYPE`，除非用户选择其他模式；
- 未继承旧项目状态这一已验证事实；
- 会改变架构的未知项和当前证据状态；
- 一个主要下一决策及成功判据。

本项目产生证据前，不得声称已有活动版本、已通过闸门、已验证器件或权威 EDA 制品。

## 保持制品身份可复现

对已评审基线或下单候选，记录足以可靠配对源和输出的信息：

- 版本/状态、生成时间和时区；
- 源和导出文件名、大小与 SHA-256；
- EDA/工具版本及适用规则/配置身份；
- 板尺寸、层数、有用对象计数和钻孔摘要；
- 评审结果、已接受偏差和证据限定词；
- 实际下单时的订单状态、商城选项和订单号。

不得用后续导出覆盖已评审候选。下载目录是传输位置，批准制品归档到项目根目录。

## 分开采购身份

保持以下身份独立：

- 电气作用/数值；
- 制造商器件与批准替代；
- 符号与物理封装；
- 只用于验证 land pattern 的几何 donor；
- 库存记录及实际在手证据；
- 采购动作和数量；
- EDA BOM/PCB 包含标志。

几何 donor 不是采购推荐。引用库存不会自动预留或扣减。购买、预留、扣库存或修改外部库存系统都需要对该动作的授权。

## 按请求层级建立制造包

纯 PCB 订单包含匹配的 Gerber/钻孔包和必要 fab 说明。PCBA 还要按适用范围检查受控 BOM、替代、CPL 面/旋转、极性/pin-1 图、DNP 变体、基准点/工装假设、传感器处理和测试/序列号访问。

付款前，把板厂当前预览/DFM 与归档候选比较。制造包可以对原型达到 `manufacturing-checked`，但这不证明产品或量产准备完成。
