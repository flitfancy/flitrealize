# 2.1 原理图设计与契约

需求、架构和主要器件已经基本确定，需要建立原理图意图、检查连接或准备进入 EDA 时读取本参考。

本阶段把设计转换为准确、可检查的电路连接，不重新展开产品需求和整体架构。

## 输入来自设计阶段

开始原理图前，应已经具有当前任务需要的：

- 产品目标和明确非目标；
- 功能框图；
- 电源树；
- 外部接口；
- 主要工作条件；
- 已确认器件和仍保留的候选；
- 关键计算；
- 尚未确认但准备在样机阶段测试的问题。

如果当前问题会改变功能块、电源结构、主要接口或关键器件路线，应先返回设计阶段处理，而不是通过局部原理图修改绕过。

## 建立机器可读契约

使用 `design/SCHEMATIC_CONTRACT.v1.json` 保存当前原理图的可移植设计意图。

对应格式由：

```text
<skill>/schemas/schematic-contract.v1.schema.json
```

定义。

Contract 是机器权威，用于生成、检查和对比原理图。它不依赖具体 EDA，也不保存画布坐标和显示样式。

Contract 应根据项目实际需要记录：

- 功能块；
- 电源域和主要电源轨；
- 元件作用；
- `exact` 器件的制造商、MPN、后缀和封装；
- `generic` 器件的数值、必要额定值、公差、封装和允许范围；
- 接口方向和电压域；
- 语义引脚；
- 引脚到网络的连接；
- 上拉、下拉、使能和安全默认状态；
- NC、DNC、散热焊盘和必须连接的裸露焊盘；
- 保护器件和故障关断路径；
- 测试点；
- 当前仍需样机确认的问题。

不要为了格式完整加入当前设计不需要的字段，也不要把讨论过程和被否决方案写入 Contract。

## 保持引脚事实清楚

不同事实由不同来源负责：

```text
制造商数据手册
    → 器件原始引脚和电气事实

Schematic Contract
    → 当前项目怎样使用这些引脚

EDA Provider Binding
    → 当前 EDA 符号怎样对应这些引脚

EDA 原理图回读
    → 实际画出的连接
```

Contract 使用稳定、易理解的语义引脚名称，例如：

```text
VIN
GND
SCL
SDA
EN
SW
FB
```

EDA Provider 可以把语义引脚映射到实际符号引脚：

```json
{
  "bindings": {
    "easyedaPro": {
      "libraryUuid": "...",
      "deviceUuid": "...",
      "pinMap": {
        "VIN": ["1", "2"],
        "GND": ["3"]
      }
    }
  }
}
```

Provider Binding 只负责 EDA 身份映射，不能改变 Contract 中的电气设计。

如果准确符号、引脚编号或映射存在歧义，应暂停该器件的 EDA 连接，先确认器件身份或引脚关系。不要根据名称相似、图形位置或搜索结果第一项自动推断。

## 限制引脚调整范围

默认引脚映射保持固定。只有 MCU、FPGA 或其他明确支持复用的器件，才允许在 PCB 粗布局后考虑尚未分配的可配置引脚。

引脚调整只使用两种策略：

- `fixed`：保持当前引脚，不允许自动调整；
- `unused_configurable_only`：只允许改用同一器件上尚未分配、并且已经确认支持目标功能的引脚。

电源、地、复位、晶振、启动、调试、固定模拟、差分对、NC、DNC 和保留引脚不进入候选。已经分配的其他信号也不通过连锁换脚腾出位置。

目标只是解决明显的交叉、绕行、拥挤或过孔，不搜索全部排列。没有明显更好的安全候选时保留当前映射。实际调整后同步更新 Contract、原理图和受影响的固件接口。

在 Contract v1 尚未提供专用字段时，可把这项策略记录在对应组件或接口的 `constraints` 或 `extensions` 中；后续扩展 Schema 时再把它变成正式可检查字段。

## 记录初步 PCB 意图

原理图阶段可以为重要网络记录后续 PCB 需要的电气条件，例如：

- 网络类别；
- 连续和峰值电流；
- 电压和允许压降；
- 开关节点或敏感模拟节点；
- 差分、阻抗或长度关系；
- 是否需要减少过孔、缩短路径或保持连续参考。

这些内容用于指导 PCB 阶段，不在这里强制锁定最终线宽。实际线宽、间距、过孔和铺铜仍由真实层叠、铜厚、长度、散热和制造能力决定。

## 派生人类可读引脚表

需要逐引脚人工审阅时，可以从 Contract 派生：

```text
design/PIN_NET_MAP.md
```

它可以列出：

- 元件；
- 语义引脚；
- 数据手册引脚名称；
- 当前项目作用；
- 所连接网络；
- 电源域；
- 安全默认状态；
- 必连、NC 或 DNC 状态。

`PIN_NET_MAP.md` 是方便阅读的派生文件，不应独立维护另一套连接事实。连接变化时先更新 Contract，再重新生成或同步人类视图。

小型项目如果 Contract 已经足够容易阅读，不强制生成额外总览。

## 按功能检查原理图

### 电源入口

检查：

- 输入范围和极性；
- 连接器额定值；
- 反接、浪涌和 ESD；
- 输入限流或保险行为；
- 电源接入、断开和异常状态；
- 电流返回路径。

### 稳压器和电源轨

检查：

- 输入和输出工作范围；
- 最大负载和峰值负载；
- 压差、效率、损耗和温升；
- 电感、电容和反馈网络；
- 电容的额定电压和必要降额；
- 启动、软启动和关闭行为；
- 使能引脚默认状态；
- 稳压器稳定性要求；
- 电源轨之间的启动关系。

### 控制和安全默认状态

检查：

- 复位期间的输出状态；
- 主控未初始化时的使能状态；
- 上拉和下拉所在电压域；
- 开关、MOSFET 和驱动器失电后的状态；
- 开路、短路或控制信号丢失时的行为；
- 保护和关断路径是否能够独立生效。

### 接口和电压域

检查：

- 信号方向；
- 主从或源宿关系；
- 逻辑阈值；
- 电平转换方向；
- 上拉电源域；
- 总线地址；
- 热插拔和断线状态；
- 外部接口的 ESD 和误接路径；
- 线缆和连接器的准确针脚。

### 传感器和负载

检查：

- 数据手册推荐外围电路；
- 输入、输出和负载范围；
- 偏置、增益和滤波；
- 启动和故障状态；
- 裸露焊盘；
- NC、DNC 和保留引脚；
- 校准或样机测试需要的节点。

### 器件和封装

检查：

- 当前器件应为 `exact` 还是 `generic`；
- `exact` 器件的准确制造商、MPN、后缀和功能版本；
- `generic` 器件的数值、额定值、公差和允许范围；
- 封装；
- 引脚编号；
- 额定值；
- 必要公差；
- 当前采购身份；
- 允许的替代范围。

器件选择和数据手册处理见 [1.2-parts.md](1.2-parts.md)。

## 运行 Contract 检查

Contract 完成后，运行不依赖具体 EDA 的结构检查：

```text
node <skill>/scripts/action-runner.mjs run \
  --action schematic-contract-audit \
  --input-file <schematic-contract.json>
```

检查内容包括：

- JSON 结构；
- 元件、网络和功能块身份；
- 交叉引用；
- 引脚到网络的归属；
- NC 和 DNC 状态；
- 电源域；
- 差分对和接口引用；
- Provider Binding 的基本边界。

这个检查只能发现 Contract 内部结构和引用问题。

它不能单独证明：

- 电路拓扑正确；
- 器件参数满足要求；
- 数据手册理解正确；
- EDA 原理图已经实现；
- 实物电路能够工作。

## 与 EDA 原理图对照

进入 EDA 后，Provider 根据 Contract 完成器件解析、放置和连接。

写入后应从实际 EDA 文档回读：

- 使用的器件；
- 实际引脚；
- 实际网络；
- 电源标识；
- 未连接引脚；
- 关键属性；
- 保存状态。

Contract 表示设计意图，EDA 回读表示实际实现。两者不一致时，应修正拥有错误事实的一侧，不默认让其中一方覆盖另一方。

使用 EasyEDA Pro 时，具体操作见：

[2.2-schematic-workflow.md](providers/easyeda-pro/2.2-schematic-workflow.md)

## ERC 的作用

ERC 用于发现已经配置规则能够识别的连接问题，例如：

- 未连接引脚；
- 电源类型冲突；
- 输出冲突；
- 缺少电源标识；
- 有意例外之外的警告。

ERC 不负责判断拓扑、额定值、保护行为和系统功能。

有意保留的 ERC 例外应说明原因和影响范围，不通过隐藏大量警告来获得表面通过。

## 进入 EDA 实现前

满足以下条件后，可以进入 EDA 原理图实现：

- 当前架构已经完整映射到原理图；
- 需要 `exact` 的关键器件身份、封装和引脚已经确认；
- 普通 `generic` 器件已经具有完整规格和封装要求；
- 电源轨、接口和主要网络连接清楚；
- 控制和保护电路具有明确默认状态；
- 未连接引脚已经分类；
- 影响实际连接的关键资料已经确认；
- Contract 结构检查没有未解决错误；
- 剩余不确定项不会改变当前连接，并已转化为明确样机测试。

如果仍存在会改变器件、引脚、电源结构或保护行为的问题，保持在原理图设计阶段继续处理。

## 进入 PCB 前

完成 EDA 原理图后再确认：

- 当前原理图已经保存；
- 实际器件、引脚和网络已经与 Contract 对照；
- 未连接引脚和有意例外已经解释；
- 原理图 DRC 没有未解释的当前问题；
- 剩余不确定项不会改变当前连接。

这些条件不属于进入 EDA 前的要求，避免让 Contract 阶段依赖尚未生成的 EDA 结果。
