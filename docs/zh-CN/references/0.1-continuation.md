# 0.1 继续现有项目

继续已有项目，或者需要把当前进度交给下一次任务时读取本参考。

目标是快速恢复仍然有效的状态，然后继续用户当前要求的工作。

## 恢复当前状态

1. 确认当前项目根目录。
2. 读取根目录中的 `CURRENT_HANDOFF.md`。
3. 根据当前目标、主要决策和下一步，只读取本次任务需要的设计文件。
4. 检查 handoff 中列出的文件是否仍然存在，并确认它们对应当前项目版本。
5. 用户的新要求与现有状态兼容时直接继续；只有写入目标无法确定，或会覆盖已经确认的重要修改时才询问。

不同信息分别负责不同事实：

- 用户当前请求决定本次目标、范围和授权；
- `CURRENT_HANDOFF.md` 说明项目当前采用的决策和入口；
- 当前设计文件、EDA 源文件和实际回读说明已经实现的内容；
- `DEBUG_NOTES.md` 只说明一个仍在反复实验的局部问题。

出现冲突时，检查负责该事实的当前文件，不从同级项目、旧聊天、文件名或回忆推断项目状态。

## CURRENT_HANDOFF.md 记录什么

每个项目根目录只保留一个 `CURRENT_HANDOFF.md`，用于告诉下一次工作：

- 这是什么项目；
- 当前目标和范围；
- 已经确定的主要决策；
- 当前使用的设计、EDA 和验证文件；
- 尚未解决的问题或假设；
- 下一步最值得完成的工作。

它记录当前状态，不保存完整历史。旧方案、讨论过程和已经失效的结论交给版本历史或单独记录，不继续堆在 handoff 中。

可以使用下面的简单结构：

```markdown
# <项目名称>

Updated: <时间>
Project root: <路径>

## 当前目标
## 已确认决策
## 当前文件
## 未解决问题
## 下一步
```

只写已经建立的事实。暂定值、假设和待测项目应明确说明，不把它们写成已确认结果。

## 什么时候更新

出现会影响后续工作的稳定变化时更新，例如：

- 当前目标或阶段改变；
- 主要架构、器件或接口已经确定；
- 权威原理图、PCB 或制造候选改变；
- 一个重要问题已经解决；
- 新的实物测量推翻或确认了原有判断；
- 下一步已经改变。

普通查看、一次性命令、临时输出和没有改变项目判断的过程不需要写入 handoff。

更新时直接整理当前内容，删除已经失效的结论，不追加聊天式时间线。

## 与调试记录的关系

只有一个局部问题需要多轮实验时，才在 handoff 之后读取 `DEBUG_NOTES.md`。它不能改变项目身份、整体范围或其他已经稳定的设计结论。

问题稳定后，把必要结论和证据入口简要写回 handoff，再删除或归档调试记录。具体方法见 [0.2-debug-loop.md](0.2-debug-loop.md)。

## 完成续接

恢复状态后，应能够明确：

- 当前正在修改哪个项目；
- 哪些文件是当前入口；
- 哪些结论已经确认；
- 哪些问题仍然开放；
- 本次任务准备完成什么；
- 完成后怎样判断成功。

这些内容已经足够时停止读取历史资料，进入当前阶段。
