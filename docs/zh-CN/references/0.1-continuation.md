# 0.1 项目主文稿与续接

新建项目、继续现有项目，或者把当前进度交给下一次任务时读取本参考。

`CURRENT_HANDOFF.md` 是项目的人类主文稿。它保存当前设计全景，并把需求、器件、原理图、PCB、制造和样机验证连接成一条连续主线。

## 新建项目

确认用户指定的项目根目录后，根据当前需求建立 `CURRENT_HANDOFF.md`。

第一版只需要写入当前已经进入的内容，通常包括：

- 项目目标和边界；
- 当前需求；
- 初步功能架构和电源关系；
- 已知器件条件；
- 当前未决事项；
- 下一步。

不读取或继承同级项目的设计状态。其他项目只能在用户明确要求时作为参考来源。

## 继续现有项目

已有 `CURRENT_HANDOFF.md` 时：

1. 读取顶部“当前交接”；
2. 确认当前项目、目标、阶段和主要下一步；
3. 定位本次任务对应章节；
4. 读取拥有相关事实的 Contract、EDA、制造或测试文件；
5. 当前请求与已有设计一致时直接继续。

没有 `CURRENT_HANDOFF.md` 时，从当前项目根目录恢复第一版主文稿：

1. 确认当前项目根目录；
2. 查找当前需求、设计、器件、Contract、EDA、制造和测试制品；
3. 判断各文件负责的事实和当前版本；
4. 把能够确认的内容整理进主文稿；
5. 无法确认的内容保持未决；
6. 不从文件名、旧聊天、同级项目或回忆补全缺失事实。

普通续接不需要每次重新扫描整个项目。只有缺少主文稿、发生全局架构变化或发现实际冲突时，才扩大读取范围。

## 信息归属

不同文件负责不同事实：

- 用户当前请求决定本次目标、范围和授权；
- `CURRENT_HANDOFF.md` 组织当前项目的人类可读设计；
- `SCHEMATIC_CONTRACT.v1.json` 保存原理图的机器设计意图；
- EDA 源文件和实际回读说明已经实现的内容；
- 制造文件说明当前制造候选；
- 原始测量、波形、照片和日志说明实际样机表现；
- `DEBUG_NOTES.md` 只保存一个仍在反复实验的局部问题。

出现冲突时，读取拥有该事实的当前文件并完成对账。主文稿负责说明结论，不根据旧文字覆盖当前机器制品。

## 主文稿结构

按项目实际进入的阶段逐步建立下面的章节：

```markdown
# <项目名称>

Updated: <时间>
Project root: <路径>

## 0. 当前交接

- 当前阶段：
- 当前目标：
- 当前版本或样机状态：
- 本次相关章节：
- 当前主要阻塞：
- 最小有用下一步：
- 当前权威文件：

## 1. 需求、架构与器件

### 1.1 产品目标与边界

### 1.2 功能架构

### 1.3 电源树与接口

### 1.4 器件决策

## 2. 原理图设计

### 2.1 电路分块

### 2.2 元器件、引脚与网络

### 2.3 关键计算

### 2.4 测试点与样机确认项

### 2.5 EDA 实现状态

## 3. PCB 设计

### 3.1 板框和机械约束

### 3.2 功能分区和器件布局

### 3.3 网络分类、线宽和过孔

### 3.4 关键拓扑和回流路径

### 3.5 keepout、散热和装配要求

### 3.6 当前 PCB 实现与检查状态

## 4. 制造交接

## 5. 样机验证与改版

## 6. 产品化与正式发布

## 当前 OPEN
```

没有进入的阶段不需要提前填充内容。

## 当前交接

顶部“当前交接”用于快速续接，应保持简短。

它只回答：

- 现在做到哪里；
- 当前准备完成什么；
- 哪些文件是本次入口；
- 有什么真正阻止继续的问题；
- 下一步是什么。

详细设计保存在下面对应章节，不在顶部重复展开。

## 需求、架构与器件

这一部分保存：

- 产品目标和明确非目标；
- 使用条件和验收方式；
- 功能框图；
- 电源树；
- 外部接口和电压域；
- 默认和故障状态；
- 已确认器件；
- 器件选择理由、资料状态和允许替代；
- 仍待确认的主要器件。

资料路径可以记录在这里，但不复制数据手册正文。

## 原理图设计

这一部分保存：

- 每个电路块的用途和关系；
- 每个元器件的作用；
- 引脚、网络、默认状态和必连要求；
- 允许重新分配的未使用可配置引脚；
- 关键计算；
- 测试点；
- 样机确认项；
- 当前 EDA 实现状态。

Contract 建立后，引脚和网络内容从 Contract 派生。连接变化时先更新 Contract，再同步主文稿中的人类视图。

## PCB 设计

这一部分保存：

- 板框和机械条件；
- 功能分区；
- 器件布局关系；
- 网络类别；
- 线宽、间距和过孔策略；
- 关键拓扑和回流；
- keepout、散热和装配要求；
- 当前布局、布线、铺铜和 DRC 状态。

完整几何和实际连接仍由 PCB 源文件保存。

## 制造、验证和改版

制造章节保存当前制造候选、输出文件、板厂配置和下单状态。

样机章节保存测试条件、实测结果、异常和改版结论。原始波形、照片和日志保存在项目证据目录，只在主文稿中记录结论和入口。

如果样机结果改变了需求、器件、原理图或 PCB，同时更新对应的前面章节，不让新的设计结论只停留在测试记录中。

## 更新方式

形成会影响后续工作的稳定结果时更新主文稿，例如：

- 当前目标或阶段改变；
- 架构、接口或主要器件已经确定；
- 原理图或 PCB 设计发生实质变化；
- 新的 EDA 或制造候选成为当前版本；
- 实物测量确认或推翻了设计判断；
- 当前未决事项或下一步改变。

一次性命令、临时输出和没有改变项目判断的过程不需要写入。

更新时只修改受影响章节和顶部当前交接。删除已经失效的结论，不追加聊天式时间线，也不为了保持格式完整重写无关章节。

## 与调试记录的关系

只有一个局部问题需要多轮实验时，才在主文稿之外使用 `DEBUG_NOTES.md`。

问题稳定后，把结论更新到主文稿中拥有该事实的章节，并同步顶部当前交接。随后删除或归档调试记录。

具体方法见 [0.2-debug-loop.md](0.2-debug-loop.md)。
