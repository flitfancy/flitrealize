# 0.3 EasyEDA Pro Provider

任务需要创建、修改、检查或导出 EasyEDA Pro 文件时读取本参考。

本文件只说明 EasyEDA Pro 的共同入口、实际文档边界和失败恢复。具体设计与操作方法由当前阶段的文档负责。

## 使用当前实际文档

执行前确认：

- 当前项目和目标文档；
- 当前文档类型；
- 实际保存状态；
- 本次准备修改的对象；
- 当前任务要求的结果。

器件、引脚、网络、焊盘、层和几何等事实来自实际源文件或结构化回读。画布外观可以帮助理解，但不能替代对象身份和属性。

如果文档经过手工修改、重新打开或长时间中断，应重新读取当前状态，不继续使用旧的操作计划。

## 优先复用已有工具

如果 Skill 已有适合当前任务的脚本、Action 或 Provider 流程，优先直接使用。

现有工具不支持当前操作时，可以使用 EasyEDA Pro 当前可用的接口完成必要工作。不要把未经验证的方法登记成稳定能力，也不要因为方法名称存在就假定它适用于当前对象。

Action、manifest 和 Provider 的开发方法见维护者文档，不属于普通项目流程。

## 执行与确认

普通写入按照下面的顺序进行：

```text
读取当前状态
    ↓
执行目标修改
    ↓
回读受影响对象
    ↓
确认结果
    ↓
保存
```

只修改当前任务涉及的对象，并保留范围外的已有内容。批量操作前先验证一个代表对象；确认方法、对象身份和回读结果正确后再扩大。

保存必须明确执行。操作返回成功但没有回读到目标结果，不能视为已经完成。

## 失败与恢复

写入失败、超时或返回状态不明确时，先重新读取当前文档和受影响对象，判断是否已经产生部分结果，再决定补齐、撤销或重新执行。

不要直接重复可能已经执行过的写入请求。撤销只处理本次操作能够准确识别的对象，不删除无法证明归属的已有内容。

一次失败且原因明确时，修正后继续。同一问题需要多轮观察或实验时，只对该问题进入 CURIOUS_MODE，并读取 [0.2-debug-loop.md](0.2-debug-loop.md)。

连接或环境问题只阻止依赖实时 EasyEDA 的工作。需求、器件选择、Contract 和其他离线设计可以继续。

## 导出与制造文件

EasyEDA 可以执行导出，但制造文件的版本配对、内容检查、板厂预览和原型下单属于 [4.1 制造文件与原型下单](4.1-production-handoff.md)。

导出结果不能因为来自当前文档就自动视为制造候选，仍需确认保存版本和输出内容一致。

## 完成当前操作

结束本次 EasyEDA 工作前确认：

- 当前项目和文档正确；
- 本次目标修改已经写入；
- 受影响对象已经回读确认；
- 范围外内容没有被意外改变；
- 当前文档已经保存；
- 下一阶段需要的文件或状态已经明确。

完成用户当前要求的阶段后停止，不提前展开后续 EDA 工作。
