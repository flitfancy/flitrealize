# 聚焦的硬件故障循环

一个子系统结论会随着重复聚焦实验变化时读取本参考。它不会扩大可写范围，也不改变项目意图。

## 判断是否需要 battle log

普通实现、一次已理解的失败或已完成工作不创建 battle log。活动且不稳定的子系统可保留一个 `BATTLE_LOG.md`：

```markdown
# 活动子系统与边界
# 当前假设或结论
# 直接证据
# 下一实验、预期结果与停止条件
```

先读 `CURRENT_HANDOFF.md`。handoff 拥有项目身份和稳定状态；battle log 临时拥有其命名子系统。

## 运行最小可区分实验

按成本排序证据：已有一手失败、最小探针、最后才是推断。

1. 读取活动结论、最新直接证据，以及本故障所需的最少源文件/配置。
2. 写出一个主假设，以及能把它与其余合理解释区分开的观察。
3. 执行最小已授权局部变更或探针。
4. 运行针对性红/绿检查并保存原始结果。
5. 简短更新结论和下一实验。

受影响边界未变化时，不重复完整 BOM、库存、网表、布局、ERC 或 DRC 扫描。证据跨越边界或稳定里程碑需要回归时再扩大。

用户操作的 EDA 重试只交付一个当前脚本、所需活动文档、预期可见结果和停止条件，不要求用户在多个实验版本间选择。

## 停止补丁堆积

失败后先使用新证据，再改变另一个假设。实质相似的尝试反复出现却没有区分性证据时，暂停并构建最小复现、共享不变量或人工观察，不继续堆变体。停止点由风险和成本决定，不使用任意固定次数。

实时 EDA 使用 [easyeda-pro.md](easyeda-pro.md) 的事务与回滚契约。可行时 diagnose、apply、verify 共用决策/几何核心。

## 干净退出

结论稳定后，把带证据链接的结果合并进 `CURRENT_HANDOFF.md`，再在授权范围内归档或删除 battle log。每个动作保留一个当前入口，把过期实验标记为历史或不安全。

只有实验产生真实绿/红证据时才记录可复用方法候选。晋升规则归知识 catalog，不归本地故障日志。
