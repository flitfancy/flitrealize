# 硬件生命周期闸门

只有用户明确要求完整生命周期跟踪、制造候选评审或正式发布时，才读取本详细模型。

## 分开跟踪项目路线与证据阶段

- **项目路由：**NEW_PROJECT 或 EXISTING_PROJECT。
- **证据阶段：**活动版本真实推进到哪里。

普通原型使用 `SKILL.md` 的三个检查点即可：

| 原型检查点 | 详细阶段 |
| --- | --- |
| 设计与原理图 | 0 问题、1 架构、2 原理图契约 |
| PCB 与制造准备 | 3 封装、4 布局、5 布线、6 制造包 |
| 样机验证与改版 | 7 上电/EVT |
| 独立产品化路径 | 8 产品化 |

不要把两套表示都变成重复项目流程。

## 闸门状态与证据限定词

- **OPEN：**所需证据缺失、过期或冲突。
- **CONDITIONAL：**缺失证明有明确后果、负责人和精确复查/到货触发条件。
- **PASSED：**闸门所需证据存在、与活动版本一致并完成必要层级评审。

证据限定词相互独立：

- `automated-green`：已配置测试/capture/ERC/DRC 通过；
- `visual-accepted`：真实布局/方向/访问/布局意图被接受；
- `manufacturing-checked`：匹配输出与板厂当前预览/DFM 完成交叉检查；
- `physical-verified`：测得的原型满足已定义标准。

普通原型可以把有边界的缺口转为明确样机测试，但假设或较低限定词不能被改名为已通过工程或生产闸门。

## 阶段决策

| 阶段 | 证据支持的决策 | 闸门问题 |
| --- | --- | --- |
| 0 问题边界 | 用途、环境、主机/电源/外壳、成本和排除项 | 产品边界是否一致？ |
| 1 架构 | 功能块、电源树、稳定接口、故障、测试意图和主要供应风险 | 每个需求是否映射到可测试功能块/接口？ |
| 2 原理图契约 | 精确电路、额定值、器件/封装、pin/net、ERC 和 BOM 草案 | 连通和元件意图是否内部一致？ |
| 3 封装/约束 | land pattern、pin 1、板框/孔、配对与物理 keepout | 关键物理接口是否已证明？ |
| 4 布局 | 分区、环路、旁路、机械/装配访问和碰撞证据 | 布线前布局是否可辩护？ |
| 5 布线/平面 | 网络类、关键拓扑、回流、平面、过孔和已配置 DRC | 几何是否合法且电气合理？ |
| 6 制造候选 | 匹配源/输出、所需 BOM/CPL、预览和 manifest | 是否有一个可复现原型候选可制造？ |
| 7 上电/EVT | 安全上电、电源/接口/负载/故障测试和有效日志 | 测得原型是否满足功能标准？ |
| 8 产品化 | 证据链接改版、生产测试、校准、外壳/合规和追溯 | 适用产品证据是否完整？ |

阶段 6 可以批准原型制造，但不证明量产准备。正式准备度需要实物证据和适用的阶段 8 工作；受监管/高风险领域还需要当前标准和专业评审。

## 只记录影响决策的证据

活动闸门记录版本/时间、输入制品、检查/工具版本、有用数值、阻塞项、已接受风险、负责人/复查触发条件和下一步。不要创建不改变决策的生命周期文书。

继承项目时读取当前状态、检查所列源/导出身份、运行已配置针对性状态检查，并把闸门声明与制品比较。过期或不受支持的声明降级；文件名不能证明阶段通过。

分类发现：

- **Blocker：**可能功能错误、安全问题、制造输出错误，或请求决策所需制品缺失。
- **Accepted prototype risk：**有边界限制并有计划测试/复查。
- **Future improvement：**有用改进，但没有证据要求当前构建等待。
