# 0.0 Reference map

Numbers identify the stage a reference belongs to. They do not define approval gates.

| Number | Scope |
| --- | --- |
| 0.x | Project continuation, focused debugging, and EDA Provider entry |
| 1.x | Requirements, architecture, parts, and specialized design |
| 2.x | Schematic Contract and EDA schematic |
| 3.x | PCB design, physical foundation, return paths, and review |
| 4.x | Manufacturing files and prototype ordering |
| 5.x | Prototype bring-up, testing, and revision |
| 6.x | Repeatable production and formal release |

## Main flow

```text
CURRENT_HANDOFF.md
  |
  v
1.1 Requirements and architecture
  -> 1.2 Part selection and sources
  -> 2.1 Schematic design and Contract
  -> 2.2 EDA schematic
  -> 3.2 Layers, outline, and functional keepouts
  -> 3.1 Placement and critical routing
  -> 3.2 Repour and confirm reference copper
  -> 3.3 Return paths and grounding
  -> 3.1 Whole-board review
  -> 4.1 Manufacturing preparation
  -> 5.1 Prototype validation and revision
  -> 6.1 Productization, only when requested
```

`CURRENT_HANDOFF.md` is the human-readable manuscript that follows the project from beginning to end. Each stage updates its stable conclusions in the corresponding section. Machine facts remain in the Contract, EDA source, manufacturing outputs, and raw test records.

Use [0.1](0.1-continuation.md) for project continuation, [0.2](0.2-debug-loop.md) when one problem needs multiple experiments, [0.3](0.3-easyeda-pro.md) when entering EasyEDA Pro, and [1.3](1.3-audio-systems.md) only for audio hardware.

The main Skill owns the full workflow and shared rules. Each reference owns one stage or one bounded problem. Stop loading references once the current task can continue or finish.
