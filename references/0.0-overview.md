# 0.0 参考文档总览

编号用于定位参考文档：`0.x`～`6.x` 组织通用流程，`D.x` 表示跨阶段的专项领域（Domain），均不构成审批闸门。

| 编号 | 范围 |
| --- | --- |
| 0.x | 项目续接、聚焦调试和 EDA Provider 入口 |
| 1.x | 需求、架构与器件 |
| 2.x | 原理图 Contract 和 EDA 原理图 |
| 3.x | PCB 设计、物理基础、回流和检查 |
| 4.x | 制造文件与原型下单 |
| 5.x | 样机上电、测试和改版 |
| 6.x | 重复生产和正式发布 |
| D.x | 特定项目按需读取的专项设计知识 |

## 当前阶段从哪里进入

只选择本次任务所在行；下列入口指向现有实现，不维护第二份 Action 清单。查询中的路径都相对于 Skill 根目录。

| 当前工作 | 先读说明 | 能力与执行入口 |
| --- | --- | --- |
| 项目续接、阶段交接与证据对账 | [0.1](0.1-continuation.md) | 顶部当前交接；有结构化记录时用 `scripts/handoff-check.mjs inspect --project-root <项目绝对路径>` 只读核对 |
| 需求、架构、接口 | [1.1](1.1-requirements-and-architecture.md) | 根据当前需求形成设计，不为找工具提前连接 EDA |
| 库存、器件、资料 | [1.2](1.2-parts.md) | `scripts/parts/parts-resolver.mjs --help`；库存来源和项目输入从当前交接定位 |
| 原理图 Contract | [2.1](2.1-schematic-contract.md) | `scripts/action-runner.mjs list --domain schematic --query "契约检查"` |
| EDA 原理图、放件、重排、连线、配色 | [0.3](0.3-easyeda-pro.md) → [2.2](providers/easyeda-pro/2.2-schematic-workflow.md) | `scripts/action-runner.mjs list --domain schematic --query <用途短词>` |
| PCB 基础、布局、布线、接地、检查 | [3.1](3.1-pcb-review.md)，再按需读 Provider | `scripts/action-runner.mjs list --domain pcb --query <用途短词>`；[3.4 布局](providers/easyeda-pro/3.4-pcb-placement.md)、[3.5 规则](providers/easyeda-pro/3.5-pcb-routing-plan.md)、[3.6 改宽](providers/easyeda-pro/3.6-pcb-trace-width.md)、[3.7 配色](providers/easyeda-pro/3.7-pcb-net-color.md)按当前任务选择 |
| EDA 连接与能力探测 | [0.4](providers/easyeda-pro/0.4-environment.md) | `scripts/action-runner.mjs list --domain system`；只有实际 EDA 操作需要时才连接 |
| 制造、样机、产品化 | 对应 [4.1](4.1-production-handoff.md)、[5.1](5.1-prototype-validation.md)、[6.1](6.1-production-release.md) | 使用该阶段文档及项目已有入口；没有登记通用自动化不等于阶段无法推进 |

上述 JavaScript 入口用 `node` 执行。`schematic`、`pcb`、`system` 是当前注册域；资料解析器不属于这些域，不调用不存在的 `--domain parts`。

## 主流程

```text
CURRENT_HANDOFF.md
  ↓
1.1 需求与架构
  → 1.2 器件选择与资料
  → 2.1 原理图设计与 Contract
  → 2.2 EDA 原理图
  → 3.2 层、板框和功能性 keepout
  → 3.1 布局与关键布线
  → 3.2 重铺并确认参考铜
  → 3.3 回流与接地
  → 3.1 整板检查
  → 4.1 制造准备
  → 5.1 样机验证与改版
  → 6.1 产品化，仅在用户要求时
```

`CURRENT_HANDOFF.md` 是贯穿整个项目的人类主文稿。每个阶段把稳定结论更新到对应章节，机器事实仍由 Contract、EDA 源文件、制造输出和原始测试记录保存。

项目续接使用 [0.1](0.1-continuation.md)；一个问题需要多轮实验时使用 [0.2](0.2-debug-loop.md)；进入 EasyEDA Pro 时使用 [0.3](0.3-easyeda-pro.md)。

涉及音频硬件时，按需读取 [D.1 音频系统](domains/D.1-audio-systems.md)，在当前相关阶段应用其专项要求，不将它视为所有项目都要经过的步骤。

主 Skill 负责全流程和共同规则，每份参考只负责一个阶段或一个有边界的问题。当前任务已经能够继续或完成时，停止加载更多参考。
