# 0.0 Reference map

The number shows where a reference belongs. It does not create an approval gate.

| Number | Scope |
| --- | --- |
| 0.x | Continuation, focused debugging, and EDA Provider entry |
| 1.x | Requirements, architecture, parts, and specialized design |
| 2.x | Schematic Contract and EDA schematic |
| 3.x | PCB design, physical foundation, return paths, and review |
| 4.x | Manufacturing files and prototype ordering |
| 5.x | Prototype bring-up, testing, and revision |
| 6.x | Repeat production and formal release |

## Main route

```text
1.1 Requirements and architecture
  → 1.2 Parts and source material
  → 2.1 Schematic Contract
  → 2.2 EDA schematic
  → 3.2 Layers, outline, and functional keepouts
  → 3.1 Placement and critical routing
  → 3.2 Repour and confirm reference copper
  → 3.3 Return paths and grounding
  → 3.1 Whole-board review
  → 4.1 Manufacturing preparation
  → 5.1 Prototype validation and revision
  → 6.1 Productization, only when requested
```

Use [0.1](0.1-continuation.md) for continuation, [0.2](0.2-debug-loop.md) for one problem that needs repeated experiments, [0.3](0.3-easyeda-pro.md) when entering EasyEDA Pro, and [1.3](1.3-audio-systems.md) only for audio hardware.

The main Skill owns routing and shared rules. Each reference owns one stage or one bounded problem. Stop loading references once the current task can continue or finish.

The design-draft template, Contract Schema extensions, and automatic `PIN_NET_MAP.md` generation remain future work.
