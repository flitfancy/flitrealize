# 2.3 已确认器件的批量放件与续接

只在需要批量放入原理图，或恢复这条入口中断的器件批次时读取。普通设计与连线沿用 [2.2 原理图工作流](2.2-schematic-workflow.md)。

## 实际入口与范围

使用 [schematic-components.mjs](../../../scripts/schematic-components.mjs)，不要临时拼装多步命令，也不要把 Workflow 名称当 Action 名称：

```text
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --input-file <项目内输入 JSON> --window-id <实际窗口>
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --input-file <项目内输入 JSON> --window-id <实际窗口> --apply
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --resume <原 runDir> --window-id <实际窗口>
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --resume <原 runDir> --window-id <实际窗口> --apply
node <skill>/scripts/schematic-components.mjs --project-root <项目绝对路径> --resume <原 runDir> --window-id <实际窗口> --close
```

默认模式读取当前 EDA、生成计划，并在项目 `evidence/` 中保存本地制品；“不写 EDA”不等于“不产生本地文件”。`--apply` 才允许本次放件和保存；续接不继承旧调用的写权限。用户当前请求已经包括写入时由执行者按范围传参，不新增审批。

入口使用现有 Action，顺序是：Contract 结构检查 → 已选器件绑定 → 功能块放置计划 → 源码备份 → 首个代表器件放置与回读 → 分批放置与回读 → 保存后再回读。

本轮只完成放件，不自动连线、修改已有器件、整图几何重排或运行整图 DRC。批量前器件身份、封装和映射须已按项目需求确认；该入口不替代库存匹配、选料或引脚电气判断。绑定缺失时复用 resolver 的唯一准确匹配规则，歧义仍阻止写入。新入口通过隔离模拟测试，尚未完成真实 EDA 集成验收；首次用于现场先核验代表批次。

## 输入

输入文件和 Contract 都位于当前项目内。`contractFile` 相对于项目根目录，不是输入文件所在目录。示例中的 UUID 必须替换为现场实际值；这里只示意已有 Contract 中的位号，不是可直接放置的器件样本。

```json
{
  "contractFile": "design/SCHEMATIC_CONTRACT.v1.json",
  "expectedProjectUuid": "<实际项目 UUID>",
  "expectedDocumentUuid": "<实际原理图 UUID>",
  "designators": ["R1", "R2", "C1"],
  "batchSize": 10,
  "selections": {
    "R1": {
      "libraryUuid": "<已确认的库 UUID>",
      "deviceUuid": "<已确认的器件 UUID>",
      "pinMap": {"1": ["1"], "2": ["2"]}
    }
  },
  "layout": {"originX": 600, "originY": 500, "blockGap": 180}
}
```

- `designators` 明确本次已确认的器件，必须唯一且属于 Contract。Contract 自带的 `bindings.easyedaPro` 优先；已有绑定时通常不再填写 `selections`。显式选择和 `pinMap` 的键依照当前 Contract，不照抄示例。
- 可选 `selections`、`pinMaps`、`searchMapping` 直接传给现有绑定 resolver；可选 `catalog`、`layout` 直接传给现有布局生成器。按位号索引的参数仅包含本批次器件，布局字段的单位/语义沿用原生成器。
- `batchSize` 为 1–50，默认 10。无已确认创建记录时，先单独放置并验证第一个器件，再扩展到批量。陌生器件类型需要额外身份核验时，先把对应代表项作为独立小批次。
- 全 Contract 先通过结构审计，随后只为 `designators` 范围解析绑定和布局；不因其他器件尚无 EDA 绑定而重新选料。相关输入结构错误不能用忽略诊断的方式绕过。
- 布局仍使用现有生成器的几何估计，不会为已有画布自动避障。执行前用默认计划和现场确认新区有空间；已有位号冲突会直接拒绝，不尝试覆盖或自动认领。

## 输出和证据归属

一次运行返回 `runDir`，位于 `evidence/schematic-components-<唯一 ID>/`，其中：

- `transaction.json`：该次事务的输入/脚本版本、步骤和创建回执索引；新批次同时保留原输入、Contract 快照和 JSON 语义指纹，不刷新旧证据。
- `prepared.json`：冻结的绑定与放置计划及原有器件基线。
- `before.esch`：写入前完整源码备份。
- 按步骤编号的 `*-input.json` / `*-report.json`：可核对输入、确定终态、创建 ID、回读、保存结果。
- `after-*.esch`：保存后的源码回读。

默认计划成功是 `planned`，放置和保存成功是 `placed-saved`。成功记录被再次续接且现场仍匹配时返回 `already-completed`，不重复放件或保存。只读返回 `saved: null, saveChecked: false`；`recordedSaved: true` 只表示历史保存回执，不证明当前保存状态。`verification` 保留实际库身份覆盖的 `unknown` 等限制，`drc: not-run` 明确未验收整图；脚本成功不是网络连接或板级功能证明。

每个批次只把稳定结论、当前证据入口和最小下一步同步到 `CURRENT_HANDOFF.md` 对应章节，按 [0.1 续接规则](../../0.1-continuation.md) 维护。不要把整份事务日志复制进主文稿，也不要只把创建 ID 放在聊天里。

## 中断后的判断

先用原 `runDir` 的 `--resume` 只读核对。即使输入、脚本或现场已经变化，也保留 `reconciliation` 差异报告，不在读取前一概拒绝。确认旧计划仍适用才加 `--apply`：JSON 空白和键顺序变化不挡续放；Contract 按本批选定位号所需内容比较。脚本仍用字节指纹，脚本变更或实质输入变更后需要新计划，不猜测代码语义。

若决定放弃旧计划，用 `--resume <runDir> --close`（与 `--apply` 互斥）。入口核对现场，确认没有未知/执行中的写入后记录差异，结束本地事务并释放活动标记；不会删除、改名或认领 EDA 对象，也不宣称整批完成或已保存。关闭后不能继续旧 apply；按当前事实另建增量计划。旧批次缺少语义快照时，仍可只读核对或安全关闭，不推测原输入来续写。

| 情况 | 入口行为 |
| --- | --- |
| 有确定的部分失败回执 | 回读并匹配已创建 ID、位号、几何和可取得的库身份；后一次 `--resume --apply` 只补确认缺失的部分 |
| 组件创建后位号设置失败 | 保留刚取得的 ID，发现对象不符合计划时停止，供人工核对；不重复创建来替代异常对象 |
| 只在保存步骤失败 | 已验证放件保留；续接先回读，再保存，不重做放件 |
| 进程断在 Action 已落盘回执之后 | 读取该步骤真实终态回执，核对现场，再继续 |
| 超时且没有确定终态 | 即使当前有部分对象，也不能证明旧操作结束；记录只读回读后停止新写入，不盲重试 |
| 回执无法解释的新增对象、重复位号或原有对象变化 | 记录差异并阻止旧 apply；已知终态的旧事务可 close 后重规划，不自动认领、删除、改名或覆盖 |

`evidence/.schematic-components.lock` 防止两个入口同时运行；进程被强杀后可能保留锁，不自动按 PID 或时长抢锁。`evidence/.schematic-components-active.json` 指向仍有未解决写入的批次，防止另建批次绕过未知结果。这两个文件只是本地事务保护，不证明浏览器没有其他写入者。

遇到遗留锁，先确认本机旧进程及远端 EDA 操作已经停止，再由执行者只移除已核实的锁并续接。未知写入没有确定终态时不能 close；不伪造 report、删活动指针或改状态来强行续跑。此入口不提供 `--force`，也不能保证断电/超时后完全自动恢复。

## 底层 Action 的边界

放件 Action 仍支持原有单步接口和受指纹约束的显式回滚。批量封装给计划传 `failurePolicy: preserve`：失败保留已创建对象与证据，不自动回滚整个批次。读取失败不再当空图；取得 ID 后先确认不是原有或本批已创建 ID，再立即记录所有权；不因接口返回已有 ID 而修改或删除原有对象；目标切换时不在新文档继续修改或回滚。

保存 Action 默认仍保存并检查 DRC；仅此放件入口显式传 `runDrc: false`，避免把尚未连线的原理图当完成图来验收。保存后的目标与快照变化会报错。后续完成连接后仍按 2.2 运行完整保存/DRC 流程。

入口仅验证本批次器件以及原有器件的已读取属性，不声称检查所有非器件图元。源码备份只用于对账和有范围的恢复，不自动整图导入覆盖。
