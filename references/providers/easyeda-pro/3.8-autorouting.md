# 3.8 分层自动布线

已有 PCB 和明确的网络规则，准备自动走线、接续同网支路、离线比较或写入候选时使用。统一入口是 `scripts/pcb-route.mjs`；查询 `action-runner.mjs list --domain pcb --query "自动布线"` 可发现入口。默认只准备/生成候选；用户要求写入时带 `--apply`，不重复征求已有授权。

## 输入和职责

布局阶段的两层A*预走线、全层孔位扫描、联合扇出、过渡规划、实际铜路径和有限回退已收录在[3.8预走线](../../3.8-prerouting.md)，入口为 `pcb-preroute.mjs`。它生成离线候选和诊断，复用已有几何；不替代这里的原生FR写入/保存流程。潜在地空间另见[3.3地空间](../../3.3-ground-space.md)。

项目保存设计规则，Provider 读取实际 PCB，FR 负责寻路。机器完成批次执行与验收；AI 处理设计意图和报告中的工程问题。大文件、几何和完整日志留在运行目录，通常只读命令摘要、`workflow.json` 与相关失败任务。

沿用项目的 `design/PCB_ROUTING_EXECUTION.v2.json`：`units: mil`、目标 `projectUuid/pcbUuid`、按物理顺序声明的 `layers`、`nets[].endpoints`、`roles`、宽度/过孔及 `clearances`。不重抄网表或坐标。其他项目可通过 `--policy` 指定同一结构的输入。

- 角色给出 `name`、`endpoints`、`allowedLayers`、`widthMil`，功率主干还可给出 `localWidthMil` 和网络 `via`。
- `policy.layers[]` 可给 `{id,signalRoutingAllowed:false}` 禁止该层自动trace；实际允许层由角色 `allowedLayers` 或网络 `primaryAutoLayers` 明确声明，不凭15/16等原生层号猜地/电源用途。`ground_plane` 角色委托既有铺铜/接地流程。
- `load_current_main` 允许多个走线层时，角色必须给 `viaTransition:{sourceLayer,targetLayer}`，两者为允许集合中不同的声明层ID；同网 `via.minParallelLoadVias` 必须为正整数。缺失过渡或数量会明确拒绝，不使用某项目层号和隐含数量替代。角色只允许单层时可不声明过渡。
- 同网去耦、逻辑供电和小电流支路自动加入已有主干端点作为连接上下文；主干未连接时，小电流支路返回 `LOAD_PATH_NOT_READY`，不能替代负载通路。
- Kelvin 给出 `junctionEndpoint`、`destination` 和 `kelvinBranches[].pickup`。取样点必须位于实际源焊盘内，生成的支路不得在源焊盘外接触已有负载铜。
- Kelvin 求解时，原有同网负载铜及过孔也作为轮廓障碍，仅在源焊盘处留下取样窗口，其他同网端点不产生新的连接任务；原生写入仍保留全部原铜，并独立检查是否在焊盘外重接负载铜。
- `ordinaryCopperMil` 是硬性铜净空；`minimumSensitiveToSwitchCopperMil` 是可选硬性敏感线净空，`sensitiveToSwitchCopperTargetMil` 是优化目标。目标与最小值分别记录，不能靠文字状态猜测。优化目标未达到时报告警告，硬性约束不得放宽。
- 已审定引出沿用 `design/PCB_ROUTING_SEEDS.v1.json`，或用 `--escapes` 指定。引出写进同一临时求解模型并检查；缺少合法出口、并联过孔或可用空间时返回阻塞原因，不让 AI 临场拼坐标。
- 分阶段换层可给出 `transitionLayerWidthMil[net]`、`layerBridges[]` 和 `routingAnchors[]`。局部过渡不得低于该角色 `localWidthMil`；锚点必须与主干同宽，并由真实铜线段实现，不能成为实际 PCB 的虚构焊盘。普通引出/路径引出被 SES 回写时只计一次，重复过孔不能冒充并联数量。

FR验收检查合并后的实际铜：同网目标层出现达到该角色主干宽度的线段时，才核对源层接触到目标层铜的并联孔数量；已有目标层接触的焊盘不追加该过渡要求。纯同层主干不会被强制换层。该检查是声明过渡的铜拓扑验收，不代表载流、温升或回流性能已验证。

2.0兼容调整：旧规则若依赖隐含的15/16层用途，补充层权限和角色允许层；允许多层的载流主干补充过渡与并联数量。层权限缺失时仅按已声明角色层处理并保留兼容诊断，不自动推断预留层。

角色状态从实际铜连接计算，不相信规划中的 completed 字段。`already-connected` 只表示本角色端点连接；不会把它当成载流、回流或制造验收完成。

非任务网络的焊盘在临时输入中各自保留为单端点障碍，已有走线/过孔转为铜轮廓禁布区，原生 PCB 网表和铜保持。直线轮廓采用向外包络的圆角多边形，可能略保守；敏感线禁布区按明确的最小值/目标分别扩展。这样不会把范围外未完支路交给 FR；命令中的按类忽略仅为辅助过滤，SES 仍须独立通过范围检查。

## 调用

```text
node <skill>/scripts/pcb-route.mjs --project-root <项目> --mode prepare --window-id <窗口>
node <skill>/scripts/pcb-route.mjs --project-root <项目> --mode run --prepared <准备目录> --net <网络> --role low_current_branch
node <skill>/scripts/pcb-route.mjs --project-root <项目> --mode run --prepared <准备目录> --net <网络> --role low_current_branch --apply
```

`--net`、`--role` 可重复使用；省略时按规则生成队列。软件连续处理任务，记录无法布通或违反约束的候选，继续独立任务；已通过的候选合成一批写入、保存及独立回读。传输结果未知、原生操作未确认、保护内容变化或无法证明恢复时停止写入，保留请求回执。

离线读取历史导出用 `--from <目录>`，目录内有 `export-result.json` 和 `pad-map-inspect-with-footprints.json`；它代表该次导出的基线，不代表编辑器当前状态。也可用 `--snapshot <原生capture结果>`。准备时冻结目标和实现指纹；实现变化后重新准备。写入前仍核对真实 PCB 基线，不能用离线通过绕过现场核对。

`--rework-net <网络>` 明确允许局部网络重新求解，其他铜固定。第一版限单角色网络，不移器件，不改已锁定图元；多角色电源网需要明确整个角色集合，不能仅用细支路重布整网。原生恢复验证铜几何，恢复创建可能改变原图元 ID，后续必须重新读取。

重布范围在临时输入中移除旧铜，由真实端点重新生成；旧过孔不得再转换成固定虚拟焊盘，否则过孔位置实际上仍被锁住。新候选须同时完成主任务及所有重布网络的端点连接，才允许写入。

## FR 运行环境

固定 FR 2.4.1，使用 Java 25+。首次实际寻路按需安装；已有兼容 Java 直接复用。Windows 缓存在 `%LOCALAPPDATA%/FlitRealize/runtimes`，macOS/Linux 使用用户缓存目录；可用 `FLITREALIZE_RUNTIME_DIR` 指定。一个用户的所有项目共用运行文件，skill 发布包不包含 JAR/JRE。

```text
node <skill>/scripts/pcb-route.mjs --mode runtime --install
node <skill>/scripts/pcb-route.mjs --mode runtime --runtime <已有runtime.json>
```

下载校验固定 JAR 哈希及官方 JRE 包校验值。`--no-install` 禁用自动安装。运行可用 `--heap 2g`、`--passes 5`、`--timeout-ms 180000` 设置预算；`--no-optimize` 和 `--fanout` 显式调整。依据板规模测量后修改，不把默认值当成每块板的性能保证。

## 输出和验收

- `prepared.json`：冻结的 PCB、规则、引出与实现版本。
- 每个任务目录：DSN、SES、FR JSON/日志、候选和机器验收结果。
- `candidate-set.json`：有归属的写入对象及允许重布范围。
- `workflow.json`：每任务状态、警告/阻塞、各阶段计时、保存和回读结果。

验收按网络、层、线宽、过孔、实际端点连接和稳定终端铜判断。线段可拆分、合并，终端铜内的冗余中心线可省略；不能因此接受真正断路、缩窄、错层、错网、额外铜或钻孔变化。几何与原生 DRC 是独立证据。

这是布线意图与终端连接的验收，并非完整铜区域的布尔等价证明。线段数量不参与通过条件；回归样本必须同时包含坐标/方向/网络名/拆段变化和断点、错网、错层等反例。端点连通不能代替载流和温升验收。

原生写入使用 Line/Via API，以保留候选宽度；先保护设计和范围，再写入、回读、重铺、物理 DRC，最后保存和独立回读。不会把 FR 的 COMPLETED 当作整板完成。

当前支持 EasyEDA 的扁平 DSN、圆形/多边形焊盘、直线铜和普通通孔过孔。铜弧/铜折线不支持时在准备阶段报告；铺铜和局部地回流继续由现有接地工具处理。孔槽/板厂专用规则以原生 DRC 为最后检查，不能宣称全部已经映射进 FR。去耦局部回路、内层载流、Kelvin 成对环境与最终制造验证仍需相应工程检查。

本入口的原生写入和恢复已做隔离模拟；项目历史实板样本用于离线回放。新项目第一次真实写入仍需代表任务验收，不把历史项目的成功当作新目标已经通过。
