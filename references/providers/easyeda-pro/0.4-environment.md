# 0.4 EasyEDA Pro 网页 Bridge 环境

仅在网页或明确选用 API Gateway + Node Bridge、首次连接当前主机、连接中断或需确认该通道时读取。客户端 CLI 的 doctor、会话复用与宿主通道选择见 [0.3](../../0.3-easyeda-pro.md#选择执行通道)，不经过本页。

本页只维护 Bridge 的安装、连接和请求查询方式。目标确认、保存回读与未知结果处理统一见 [0.3 共同执行规则](../../0.3-easyeda-pro.md)。

## 首次准备

在网页版或使用 Bridge 的桌面编辑器安装并启用 API Gateway 扩展，允许外部交互；同一台电脑以 Node.js 22+ 运行本机 Bridge。EDA 客户端和 Gateway 扩展不包含在 Skill；连接源码位于 `<skill>/adapters/easyeda-pro`。

```text
cd <skill>/adapters/easyeda-pro
npm install
node <skill>/scripts/eda-host.mjs register --eda easyeda-pro --adapter-root <skill>/adapters/easyeda-pro --channel bridge
node <skill>/scripts/eda-host.mjs ensure --eda easyeda-pro --channel bridge --require-eda
```

已注册且配置正确时不重复注册；已连接且目标不变时复用会话。Adapter 路径保存在本机配置，不写项目 Contract。

## 复用与恢复连接

EasyEDA/Bridge 仍可达、网关仍连接且当前项目/文档未切换时直接使用已有通道，不每轮聊天重新 ensure。切换目标按 0.3 核对；手工修改通常只需重新读取文档，不必重连。

连接失败时按实际失败点检查 Adapter 路径、Bridge 状态、Gateway、窗口/文档及本次能力，只恢复受影响的一层；没有新证据时不重复相同重连。连接问题不阻止离线设计或计算。

## 查询中断的请求

原报告带请求 ID 和 Bridge 会话时，用原宿主查询：

```text
node <skill>/scripts/eda-host.mjs request --eda easyeda-pro --channel bridge --request-id <原请求ID> --session-id <原会话ID>
```

查询使用当前 Bridge 认证读取原会话记录，不自动 ensure、重连或执行代码；不改写 Action 报告、批次状态或保存占用记录。旧 Bridge 缺少 `request-status` 时保留未决记录，不为升级强行重启。恢复判断按 [0.3](../../0.3-easyeda-pro.md#失败与恢复)，通道细节见本机 Adapter 的 `references/bridge-recovery.md`。

运行依赖按功能查 [首跑指南](../../../docs/first-run.md#数值与路由环境)。连接可用后返回本次操作说明，不继续加载其他阶段。
