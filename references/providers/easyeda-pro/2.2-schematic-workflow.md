# 2.2 EasyEDA Pro schematic implementation

Read this reference when an accepted schematic design and Contract must be placed, connected, checked, or saved in EasyEDA Pro.

This flow implements the electrical intent from [2.1 Schematic design and Contract](../../2.1-schematic-contract.md) in the current EasyEDA document. It does not reopen part selection or circuit design.

## Confirm inputs

Before writing, confirm:

- current project and target schematic document;
- a structurally audited `SchematicContract`;
- selected parts, packages, and pin mappings;
- existing schematic content that must remain;
- the block or connection scope for this task;
- current EasyEDA connection and required capabilities.

If identity, package, or pin mapping is ambiguous for one part, pause only that part and resolve its fact. Other clear blocks may continue.

After manual edits, reopening, or a long interruption, read current state again instead of reusing an old placement or connection plan.

## Use the existing workflow

The public schematic workflows are:

```text
easyeda-schematic-components
    → easyeda-schematic-connect
    → easyeda-schematic-finalize
```

They handle components, connections, and final save/check respectively. Current Action manifest, capability checks, and results define what is actually supported.

Reuse the flow when it completes the needed operation. If automation covers only part of the work, use that result as a starting point and finish the bounded remainder through current EasyEDA methods. Missing automation for long wires, buses, hierarchical labels, or special objects must not stop the entire schematic task.

## 1. Bind and place parts

For each Contract component, confirm the actual EasyEDA object:

- designator;
- manufacturer and exact MPN for an `exact` part, or complete specification for a `generic` part;
- symbol;
- package;
- semantic-pin to symbol-pin mapping;
- BOM and PCB inclusion state.

Select an exact part automatically only when identity and required fields match uniquely. Do not use the first fuzzy result when several candidates, missing fields, or unclear pin relations remain.

Generic resistors, capacitors, and similar parts may bind from their accepted value and package without a full purchasing audit.

Place by block and signal flow:

- make connector, protection, power, and load relationships clear;
- keep bypass, feedback, pull, and configuration parts near their owner;
- make power entry, outputs, and page interfaces easy to identify;
- leave practical room for wires and labels;
- do not break function for decorative alignment.

Read back created or moved components and confirm designator, position, orientation, and critical properties. Automatic placement is only a first arrangement; adjust it from actual symbols and connections when useful.

## 2. Implement Contract connections

Connect the Contract's nets and endpoints, including:

- part pins;
- power and ground;
- net labels, ports, and page connections;
- pullups, pulldowns, feedback, and sensing;
- enable, reset, protection, and fault shutdown;
- test points;
- NC, DNC, and exposed pads that must connect.

Matching net names alone do not prove endpoint connection. Read actual wires, labels, and pin relations after writing.

If an automated flow creates only endpoint stubs or a subset of nets, complete the remainder. Use wires, labels, ports, or hierarchy as appropriate without changing the Contract's electrical relationship.

Keep the drawing readable:

- avoid unnecessary detours and crossings;
- keep labels clear of designators, values, and pins;
- use consistent power and signal direction where practical;
- keep related circuits together;
- make complex bus or page boundaries explicit.

## 3. Compare the actual schematic

After a block or net group, read the EasyEDA document and compare it with the Contract:

- all required components exist without duplicate designators;
- value, model, and package are correct;
- pin mappings match the actual symbol;
- net endpoints are complete;
- power symbols and interface directions are correct;
- NC, DNC, and unconnected pins match intent;
- enable, reset, and protection retain their expected defaults;
- the change did not alter unrelated existing content.

When a difference appears, decide whether the Contract, Provider binding, or EDA implementation owns the error. Do not allow the Contract or canvas to overwrite the other by default.

## 4. Save and run schematic DRC

After the current increment:

1. Confirm the target document again.
2. Save the schematic.
3. Run the configured schematic DRC.
4. Inspect actual issues.
5. Correct errors or record intentional exceptions.
6. Confirm the saved document still reads back the result.

DRC finds connectivity issues covered by current rules. It does not replace rating, topology, or system-behavior review.

Saving is explicit. A check that did not save does not prove that the EDA source was updated.

## Failure and recovery

Follow [0.3 EasyEDA Pro Provider](../../0.3-easyeda-pro.md) and read current state again before recovery. Schematic recovery may complete or undo only the components, wires, and markers that this operation can identify precisely. Stop the affected operation when document, part identity, pin relation, or write result cannot be confirmed.

## Finish this stage

Before PCB work, confirm:

- required Contract blocks are present in the schematic;
- critical parts, pins, and nets match the actual document;
- unconnected pins are classified;
- control and protection paths retain the intended defaults;
- the schematic is saved;
- DRC has no unexplained current issue;
- remaining uncertainty will not change connectivity and is expressed as a clear test.

If a question still changes a part, pin, power structure, or protection behavior, return to [2.1 Schematic design and Contract](../../2.1-schematic-contract.md).
