# 3.6 PCB 指定线段改宽

修改已有铜层直线的明确线段宽度时读取。宽度的电气依据见 [3.1 PCB 设计](../../3.1-pcb-review.md)；只有需要从网络规则生成改宽输入时，才读 [布线规则与优先级](3.5-pcb-routing-plan.md)。

## 调用、回读与保存

所有 EDA 请求必须给出现场确认的 `expectedProjectUuid`、`expectedDocumentUuid`；线宽和坐标单位为 mil，不猜测 mm，不复制其他项目的目标或参数。现场连接、写入与恢复边界见 [Provider 入口](../../0.3-easyeda-pro.md)。

```text
node <skill>/scripts/action-runner.mjs run --action pcb-trace-width --project-root <当前项目> --window-id <窗口> --input-file <inspect-input.json>
node <skill>/scripts/pcb-edit.mjs --action pcb-trace-width --project-root <当前项目> --window-id <窗口> --input-file <plan-input.json>
node <skill>/scripts/pcb-edit.mjs --action pcb-trace-width --project-root <当前项目> --window-id <窗口> --input-file <plan-input.json> --apply
```

inspect 输入包含 `mode: "inspect"` 和上述实际目标 UUID；默认摘要不展开全部线段，完整 `state.lines` 从该次报告读取，或在确需完整输出时加 `--full`。使用 [pcb-edit.mjs](../../../scripts/pcb-edit.mjs) 和下文的 plan 输入，不另造参数格式。默认只读 EDA，但会把计划、输入、源码备份和报告写入本项目 `evidence/pcb-edit/<唯一运行目录>/`；先检查计划范围和证据。

`--apply` 衔接 plan → apply → verify → save → 保存后 verify，逐步保留证据，任何失败即停。单独调用 Action 时沿返回的 `applyRequest`、`verifyRequest`、`saveRequest` 传递，写入加 `--allow-write`；普通完整流程无需手工拆装这些请求。

## 指定线段改宽

```json
{
  "mode": "plan",
  "expectedProjectUuid": "<实际项目 UUID>",
  "expectedDocumentUuid": "<实际 PCB UUID>",
  "rules": [{"net": "PWR", "primitiveIds": ["<主干线段 ID>"], "targetWidthMil": 25}]
}
```

inspect 返回 `state.lines` 中的 ID、网络、层、端点、线宽和锁定状态。必须显式选择 ID，最多 200 段，不接受“全部同网统一加粗”的隐式范围。拒绝重复 ID、网络不符、非铜层对象和锁定线段。可加宽或减窄，因此每次目标值必须有设计依据。

plan 记录当前配置 DRC 的详细问题基线，允许带已有问题制定修复计划。apply 前基线必须仍一致；修改后和保存前允许原问题保留或消失，但拒绝新增或变化的问题。比较完整记录的多重集合，不只比较数量；未知返回仍停止。仍有旧问题时 `drc.passed: false` 如实保留，改宽/保存成功不等于 DRC 全通过。

apply 也检查未选中直线属性。旧请求缺少 `drcBaseline` 时需重新计划；DRC 返回结构或文字变化可能保守地触发对账，不自动忽略。局部读回与 DRC 差异检查不代表全网最窄截面、焊盘、过孔和载流能力已合格。

## 结果与失败恢复

`result.json` 汇总本次结果并引用分步证据；将实际检查范围和稳定结论同步到同一份 `CURRENT_HANDOFF.md`。只读 verify 不查询编辑器保存状态，返回 `saved: null, saveChecked: false`；结合独立 save 报告和保存后的现场指纹判断，不把 verify 当作保存或整板验收。

applyRequest 绑定当前源码和已读对象指纹；用户修改、换板或目标错误会被拒绝。调用期间保持单一写入者；本入口没有跨进程事务锁，也没有原理图批量入口的自动续接机制。

保存得到确定失败结果后，使用本项目成功 apply 报告或 result.json 续存：

```text
node <skill>/scripts/pcb-edit.mjs --project-root <当前项目> --window-id <窗口> --resume-save <本项目成功apply报告或result.json> --apply
```

入口核对项目归属、目标、请求及当前指纹，再 verify → save → verify，绝不重放 apply。现场已变化、保存结果未知或仍在执行时，先对账，不强行续存。

同一成功 apply 的保存尝试会在 `evidence/pcb-edit/save-attempts/` 留下占用记录，防止通过 result、原报告或副本重复发起未决保存。确定终态后释放，未知或进程中断时保留；不要删记录绕过，先确认旧执行结束并核对现场。此记录只保护该保存链，不证明其他 EDA 写入者不存在，也不是新交接文档。

写入失败返回 `apply-failed`、写入前快照、已尝试 ID 及能取得的当前回读，不自动回滚或保存。超时且没有确定终态时，先确认旧执行停止并核对现场，再计划受影响增量；未收到成功不等于未写入。源码备份不应整图导入覆盖后续用户修改。

线宽操作复用当前 Provider 的直线属性 API。方法存在不证明当前版本行为，仍执行回读验证。

## 同步项目交接

在主文稿“网络规则”的“线宽调整”小节记录本次网络与线段范围、目标宽度、实际回读、保存结果、DRC 检查范围与时间及未解决限制，附分步证据；完整线段清单留在报告。规则值变化时同步“布线规则与优先级”的来源。按 [0.1 项目主文稿](../../0.1-continuation.md#pcb-主题与面板对应)更新汇总表的受影响行、网络规则 `ViewState:` 和顶部交接；表中说明规划或实际值，局部改宽不能写成整网统一宽度，保留分段差异。
