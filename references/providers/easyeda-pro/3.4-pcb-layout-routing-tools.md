# 3.4 PCB 布局、线宽、优先级与配色入口

需要比较功能块布局、检查空白区域、调整指定线段宽度、整理布线顺序或设置 PCB 网络颜色时读取。设计依据仍见 [3.1](../../3.1-pcb-review.md)，不是用几何脚本代替电气判断。

这些入口由项目内的放置、功能块平移、空白网格检查、线宽和配色脚本提炼而来；未继承任何项目 UUID、位号、板框、电流、线宽值或调色板。旧项目脚本保留。通用版已通过隔离模拟和打包测试，首次接入真实 EDA 仍须验证代表对象，不把历史项目成功等同于新入口已验收。

## 先发现，再选择实际操作

```text
node <skill>/scripts/action-runner.mjs list --domain pcb --query "布局优化"
node <skill>/scripts/action-runner.mjs list --domain pcb --query "线宽"
node <skill>/scripts/action-runner.mjs list --domain pcb --query "走线优先级"
node <skill>/scripts/action-runner.mjs list --domain pcb --query "配色"
node <skill>/scripts/action-runner.mjs list --domain pcb --query "板框"
```

矩形板框创建见 [3.2](3.2-pcb-foundation.md) 的 `pcb-board-outline`（layer 11 Polyline），不走本页的 `pcb-edit` 封装。

| Action | 输入 | 实际产出 |
| --- | --- | --- |
| `pcb-placement` | 目标、矩形边界、固定器件、预留区、明确移动/候选 | 包围盒冲突、最大器件空白矩形、候选计划、指定移动与回读 |
| `pcb-routing-plan` | 已确定的网络分类/宽度/优先级；可选线段角色 | 离线有序布线计划、指定线段改宽请求、可选配色请求 |
| `pcb-trace-width` | 目标、网络、明确线段 ID、目标线宽 | 只修改指定线段宽度，保留其他线段，配置 DRC 和回读 |
| `pcb-net-color` | 目标、已有网络类的完整成员及颜色 | 重建选定网络类并回读不透明颜色，保留成员和规则 |

除 `pcb-routing-plan` 只有 `generate` 外，均支持 `inspect → plan → apply → verify → save`。前两步和 verify 只读 EDA；apply 与 save 是独立写入。薄封装负责衔接，不提供失败修改的自动重放或 rollback。

## 共用调用和证据

所有 EDA 请求必须给出现场确认的 `expectedProjectUuid`、`expectedDocumentUuid`。参数坐标、线宽单位均为 mil，不自动猜测 mm。不要从另一块板复制值。

```text
node <skill>/scripts/pcb-edit.mjs --action pcb-placement --project-root <当前项目> --window-id <窗口> --input-file <plan-input.json>
node <skill>/scripts/pcb-edit.mjs --action pcb-placement --project-root <当前项目> --window-id <窗口> --input-file <plan-input.json> --candidate <唯一候选名> --apply
node <skill>/scripts/pcb-edit.mjs --project-root <当前项目> --window-id <窗口> --resume-save <本项目成功apply报告或result.json> --apply
```

统一入口是 [pcb-edit.mjs](../../../scripts/pcb-edit.mjs)，`--action` 也可选 `pcb-trace-width` 或 `pcb-net-color`。直接使用本页已有 Action 的 plan 输入，不新增一套参数格式；普通单方案不填 `--candidate`。默认只读 EDA 并把计划、输入和报告写入本项目 `evidence/pcb-edit/<唯一运行目录>/`，不是纯本地无副作用查询。

1. 检查计划范围、候选 issues 和报告中的源码备份。多候选写入必须明确给唯一候选名；冲突方案不能执行。
2. `--apply` 衔接 plan → apply → verify → save → 保存后 verify，逐步保留输入与报告，任何失败即停。
3. 保存得到确定失败结果时使用 `--resume-save`：验证项目内成功 apply 报告的项目归属、目标、请求及当前指纹，再 verify → save → verify，绝不重放 apply。现场已变化或保存仍未知/在执行时先对账，不强行续存。
4. `result.json` 汇总本次结果并引用分步证据。只读 verify 的成功不是整板验收；将实际检查范围和稳定结论同步到同一份 `CURRENT_HANDOFF.md`。

需要 inspect 或单独一步时仍可使用 `action-runner.mjs run --action <name>`，沿返回的 `applyRequest`、`verifyRequest`、`saveRequest` 传递；写入加 `--allow-write`。不必在普通完整流程中手工拆装这些 JSON。

只读 verify 不查询编辑器的保存状态，返回 `saved: null, saveChecked: false`。这既不证明未保存，也不覆盖之前独立 save 报告的结果；结合 save 报告和保存后的现场指纹判断。

返回的 applyRequest 绑定当前源码和已读对象指纹。用户修改、换板或输入目标错误会被拒绝。调用期间不要有第二个写入者；这些 Action 不提供跨进程事务锁，也不具备原理图批量入口的自动续接机制。

薄封装会为同一成功 apply 的保存尝试保留本地占用记录（`evidence/pcb-edit/save-attempts/`），避免通过 result、原 apply 报告或其副本重复发起未决保存。确定终态后释放，未知或进程中断时保留；不要靠删记录绕过，先确认旧执行结束并核对现场。它只保护这条保存链，不证明其他 EDA 写入者不存在，也不是新的项目交接文档。

若写入失败，报告返回 `apply-failed`、写入前快照、已尝试 ID/网络以及能取得的当前回读，不自动回滚或保存。超时且没有确定终态时先确认旧执行已停止，核对现场后再计划受影响增量；不能假设“没收到成功就没写入”。源码备份不应整图导入覆盖后续用户修改。

## 布局和空白检查

先固定机械接口与关键功率/敏感功能块，再把允许移动的小块作为候选移向空白区。布局脚本不替你决定电源环路、电气隔离或哪个块重要。

示例只展示字段，不是任何实际电路的推荐尺寸：

```json
{
  "mode": "plan",
  "expectedProjectUuid": "<实际项目 UUID>",
  "expectedDocumentUuid": "<实际 PCB UUID>",
  "boardBounds": {"minX": 0, "minY": 0, "maxX": 2000, "maxY": 1200},
  "lockedDesignators": ["J1", "U1", "L1"],
  "reservedRegions": [{"name": "display", "bbox": {"minX": 1400, "minY": 800, "maxX": 1900, "maxY": 1100}}],
  "clearanceMil": 5,
  "cellMil": 50,
  "scenarios": [
    {"name": "move-control-left", "groups": [{"designators": ["U3", "C8", "R9"], "dxMil": -100, "dyMil": 0}]},
    {"name": "move-control-down", "groups": [{"designators": ["U3", "C8", "R9"], "dxMil": 0, "dyMil": 100}]}
  ]
}
```

- 单方案不用 `scenarios`，直接给 `groups` 或 `placements: [{designator, x, y, rotation?}]`。未给 rotation 时保留当前旋转，不默认归零；组内只平移，保持相对关系。旋转仅支持相对当前角度的 90° 整数倍。
- `lockedDesignators` 和 `reservedRegions` 必须显式给出，确认没有约束时才用空数组。EDA 自身已锁定器件也不能移动；先核对锁定对象，不通过脚本解除锁。
- 现场所有 Region 的包围盒也作为保守障碍，可能比实际禁布范围大。尚未体现在 Region 中的屏幕、装配、天线、散热预留必须通过输入提供。
- `inspect` 只给目标即可读取完整器件快照；需要空白分析时再给上述边界/约束，不需给移动项。
- 最大空白矩形仅基于网格中的器件/Region 包围盒，不代表可压缩面积或可用布线面积；网格越粗越保守。对侧器件也保守计入，不自动假设可重叠。
- 仅支持明确矩形边界，不处理异形轮廓、孔槽或复杂三维干涉；这些条件不满足时改用真实几何检查，不伪造矩形验收。
- 每批最多 100 个器件、最多 20 个候选、网格最多 100000 格。先比较少量有依据的候选，不枚举任意坐标。
- **存在铜层线路、圆弧、折线、过孔或铺铜时，不执行器件移动**，因为本入口不会带动导线或自动清线。已布线板先按用户意图单独处理受影响走线，或使用适合已布线调整的工具。当前源备份不能替代这项约束。

plan 返回每个候选的 `issues`、`changedCount`、`space` 和可用的 applyRequest。apply 回读目标及未移动器件的已读属性；包围盒无冲突不等于焊盘间距、连通性、热设计或整板 DRC 合格。

## 网络规则与优先级

`pcb-routing-plan` 是本地 Action，不需要 Bridge：

```json
{
  "mode": "generate",
  "expectedProjectUuid": "<实际项目 UUID>",
  "expectedDocumentUuid": "<实际 PCB UUID>",
  "rules": {
    "units": "mil",
    "generalClearanceMil": 6,
    "qfnEscape": {"widthMil": 6, "maxLengthMil": 60},
    "classes": [
      {"name": "power", "priority": 1, "nets": ["PWR"], "trunkWidthMil": 25, "localWidthMil": 12, "viaHoleMil": 12, "viaDiameterMil": 24, "color": "#E64B4B"},
      {"name": "control", "priority": 2, "nets": ["CTRL"], "widthMil": 8}
    ],
    "routingOrder": ["power", "control"]
  },
  "segmentAssignments": [{"net": "PWR", "role": "trunk", "primitiveIds": ["<实际线段 ID>"]}]
}
```

数字只是格式样例。实际宽度、过孔、间距须按当前电流、压降、铜厚、温升及制造条件确定。每条网络只能属于一个类；priority 越小越先，同级保持输入顺序。可选 routingOrder 必须与排序一致，避免两套优先级冲突。可选 `selectNets` 只选择本次网络范围。

输出 `sequence` 中每组状态都是 planned，不相信输入里的 completed/进度字段。后续执行者按序完成关键组，回读拓扑、线宽、连接和 DRC，再继续普通网络；交接中留相应证据。**有序计划不等于自动布线器执行顺序已设置**。

对已经存在的走线，先用 `pcb-trace-width inspect` 获取真实 ID，再按用途给 `segmentAssignments`：`trunk`、`local`、`signal` 或 `escape`。分别选对应 class 宽度或 qfnEscape 宽度；不从线段长度猜测角色。提供目标 UUID 后，输出 `widthPlanRequest` 可交给 `pcb-trace-width`；class 显式给 color 时输出带类名的 `colorPlanRequest` 可交给 `pcb-net-color`，执行前须确认该网络类已存在且成员完全匹配。`selectNets` 只选择某类部分网络时，不能为该类同时生成配色请求；省略 color 后仍可生成局部布线计划。生成请求不是写入。

本入口不写 EDA 网络类、不创建线路、不调用自动路由器。via、差分间距、逃逸最大长度和敏感性约束保留为设计与后续检查要求；改线宽脚本不会自动执行这些约束。

## 指定线段改宽

```json
{
  "mode": "plan",
  "expectedProjectUuid": "<实际项目 UUID>",
  "expectedDocumentUuid": "<实际 PCB UUID>",
  "rules": [{"net": "PWR", "primitiveIds": ["<主干线段 ID>"], "targetWidthMil": 25}]
}
```

inspect 返回 `state.lines` 中的 ID、网络、层、端点、线宽和锁定状态。必须显式选择 ID，最多 200 段，不接受“全部同网统一加粗”的隐式范围。拒绝重复 ID、网络不符、非铜层对象和锁定线段。可加宽或减窄，因此每次目标值必须有设计依据。

plan 记录当前配置 DRC 的详细问题基线，允许带已有问题制定修复计划。apply 前基线必须仍一致；修改后和保存前允许原问题保留或消失，但拒绝新增或变化的问题。比较完整记录的多重集合，不只比较数量；未知返回仍停止。仍有旧问题时 `drc.passed: false` 如实保留，改宽/保存成功不等于 DRC 全通过。

apply 也检查未选中直线属性。旧请求缺少 `drcBaseline` 时需重新计划；DRC 返回结构或文字变化可能保守地触发对账，不自动忽略。局部读回与 DRC 差异检查不代表全网最窄截面、焊盘、过孔和载流能力已合格。

## PCB 网络配色

```json
{
  "mode": "plan",
  "expectedProjectUuid": "<实际项目 UUID>",
  "expectedDocumentUuid": "<实际 PCB UUID>",
    "rules": [
      {"name": "POWER", "nets": ["VBAT", "VSYS"], "color": "#FF4040"},
      {"name": "CONTROL", "nets": ["ENABLE", "STATUS"], "color": "#5F6673"}
    ]
}
```

`name` 是 PCB 中已有网络类的准确名称，`nets` 必须是该类的完整成员；上例名称和网络仅为示例，使用前替换为项目实际值。只传目标和 `mode: "inspect"` 可读取当前全部网络类。兼容没有 name 的输入，但仅当完整 nets 唯一匹配一个已有类时才生成带明确类名的计划。缺失类、部分成员、成员交叉或归属歧义均停止，不自动建类、移动网络或扩大范围。一次最多 200 个唯一网络。

颜色必须显式为 `#RRGGBB`。它是 RGB 色值，不代表电压、电流、线宽或布线优先级；省略某个类表示不改该类。新版不接受 `null` 恢复默认，也不调用 `setNetColor` 写入或清除单网络覆盖。旧逐网计划不能直接执行，须重新 plan。

执行沿用 FIREFLY AUDIO / 电池项目验证过的网络类机制：仅删除并按原成员重建发生色值变化的类，调用 `createNetClass` 时传 RGB 0–255、`alpha: 255`，`getAllNetClasses` 回读检查 `alpha: 1`。不能把回读的 alpha 原样传回创建接口。建类导致的配置/网络规则重置使用本次快照恢复，再核对全部网络类、规则以及直线/过孔/器件几何；配对或区域规则出现意外变化时停止。类顺序可能因重建改变，不按顺序判断成员变化。

颜色由项目输入决定。下面是可复制的配色示例，沿用上述项目已用过的八色方案；不是脚本内置默认，也不会按网络名自动套用：

| 功能用途 | 示例颜色 | HEX |
| --- | --- | --- |
| 主功率 | 红 | `#FF4040` |
| 输入电源 | 橙 | `#FF9800` |
| 开关节点 | 紫 | `#D500F9` |
| 模拟采样、反馈 | 橄榄色 | `#8C7200` |
| 总线、调试 | 青蓝 | `#007F93` |
| 逻辑电源 | 绿 | `#39803D` |
| 地 | 靛蓝 | `#7986CB` |
| 控制信号 | 灰蓝 | `#5F6673` |

例如功率板可选择红色主功率、橙色输入和紫色开关类；传感器板可选择橄榄色模拟、青蓝总线和绿色逻辑电源类。由项目决定是否沿用这些用途和色值，仅传需要改变的已有类即可。

plan/apply/verify/save 保持分离。源备份和快照检查仍保留；源码序列化不稳定时会只读停止，不绕过检查继续写入。重建中断可能留下缺失类，失败报告保留原成员、颜色、规则、源备份和已尝试操作，不自动重试或回滚。

API 回读成功不等于画布渲染正确。结果显式返回 `visualVerified: false`，首次现场先选一个类，核对画布后再扩展；历史单网络覆盖未被清除，显示异常时应单独核对。脚本不修改编辑器主题、铜层颜色，也不将配色成功当作整板 DRC 通过。

布局移动使用 [PCB_PrimitiveComponent.modify](https://prodocs.lceda.cn/cn/api/reference/pro-api.pcb_primitivecomponent.modify.html)，读取原生 PrimitiveLock；线宽操作复用当前 Provider 的直线属性 API。仅有方法存在不证明当前版本行为，仍执行回读验证。
