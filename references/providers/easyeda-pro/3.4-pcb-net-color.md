# 3.4 PCB 网络配色

实际PCB布局准备中检查并按规则设置网络配色，或预览/修改已有网络类颜色时读取。用户所说“焊盘着色”在本入口采用net-class网络配色辅助识别；不直接修改每个焊盘颜色。共同目标与执行规则见 [0.3](../../0.3-easyeda-pro.md)。已有规则从 [3.6](3.6-pcb-routing-plan.md)生成 `colorPlanRequest`，仅配色可直接提供本页输入。

## 布局前的配色顺序

检查并按既定规则设置网络配色是 [布局准备](../../3.1-pcb-review.md#布局准备)的必做项。已有配色符合规则则保留，需要补充或纠正时按规则设置。配色用于辅助辨识；连接正确性仍由原理图、实际 PCB 与网表回读核对。按下列顺序检查并记录结果，无法执行的部分明确原因与未完成状态。

1. 核对本次PCB目标及实际网名清单，复用项目已有的网络规则配置；不从待检查的分类反向生成网名。
2. 核对类、成员、已确认用途与现场配色，符合既定规则且仍一致时保留，不每轮布局重新分类或改色。需要补充时，从项目已经确认的Contract/接口用途/网络规则取得 `kind` 或已接受的显式色值，不按net名字猜用途。
3. 只处理本次用途明确的完整类。未知类别保持EDA现有/默认显示并标未决，不虚构kind或色值；规划只选择已确认的类，其余网不参与着色写入。类缺失或成员冲突时报告对应缺口，现入口不自动创建分类。
4. 检查现有配色或完成改色后，取得颜色回读并查看当前画布，确认实际可见效果；执行改色时核对保存与回读状态。色值回读与“焊盘已按功能显示”分开记录；显示范围与开关能力按本页边界核验。后续布局/预走线仍使用最新实际 PCB，不把颜色检查当作连接验收。
5. 无法检查、设置、保存回读或确认显示时，报告具体原因、受影响范围和未完成项，不默默跳过或标为完成。未知用途、分类缺失、成员冲突和显示能力限制按本页规则分别记录；部分完成不代表本步全部完成。

上述检查是布局准备的必做项。纯离线计算、只读 prepare/solve 或仅查看任务不附带 `--apply` 或其他 EDA 写入；可根据有来源的当前资料核对已有分类与配色，无法核验现场或执行设置时，须报告具体原因和未完成项。配色必做要求不扩大本次授权。

## 输入与调用

项目决定网络类、完整成员和用途。脚本按固定 `kind` 色表或显式 `color` 执行，不推断用途、不创建或拆分类别。

```json
{
  "mode": "plan",
  "expectedProjectUuid": "<实际项目 UUID>",
  "expectedDocumentUuid": "<实际 PCB UUID>",
  "rules": [
    {"name": "POWER", "nets": ["PWR"], "kind": "power"},
    {"name": "GND", "nets": ["GND"], "kind": "ground"},
    {"name": "CONTROL", "nets": ["CTRL"], "kind": "logic"}
  ]
}
```

名称和成员替换为现场值。项目持久化输入保留完整 `nets`，便于发现成员变化；临时调用可只给类名，只给 nets 时须唯一匹配已有类。类名和 kind 不带首尾空白，color 为 `#RRGGBB`；null 不表示恢复默认。显式 color 优先。

```text
node <skill>/scripts/pcb-edit.mjs --action pcb-net-color --project-root <项目> --window-id <窗口> --input-file <输入.json>
```

默认只预览 EDA，并保存本地计划和报告；加 `--apply` 才执行并保存。结果位于 `evidence/pcb-edit/<运行目录>/result.json`。

直接调用 Action 时，`inspect` 读取类和色表，`plan` 返回冻结成员及颜色的 `applyRequest`，`apply` 执行并回读，`save: true` 才保存。写入使用 `--allow-write`。本 Action 不提供独立 verify/save 或 `--resume-save`。

| 结果 | 主要字段 |
| --- | --- |
| 预览 | `status: planned`、`assignments`、预计 `changedCount`、`applyRequest` |
| Action 执行 | `status: applied` 或 `apply-failed`、`saved`；失败附原状态与已尝试类名 |
| 命令入口 | `ok/status/saved/steps/reportFile`；成功为 `verified`，实际数量仅在执行确认后报告 |

`assignments` 为 `{name, nets, hex, color: {r,g,b,alpha}}`；hex 是大写 HEX，回读 alpha 为 1。目标身份和成员在执行时再次核对。默认命令即使收到 `save:true` 也只预览。

## 执行与失败

当前实现通过重建网络类改色，保留原成员并恢复受影响的规则。写入 alpha=255，回读为 1；首个写入前、每类写入后及保存后核对网络类和规则。它不清除历史单网络颜色覆盖，也不修改布线几何。

失败保留原类、规则和已尝试范围，不自动重试或回滚。未知结果按 [Provider 恢复](../../0.3-easyeda-pro.md#失败与恢复)对账；中断若留下缺失类，先 inspect 并对照原报告恢复。

本 Action 的 `saved:false` 为未尝试，执行结果的 null 为保存未确认，预览的 null 为未检查；共同状态与保存回读判断见 [0.3](../../0.3-easyeda-pro.md#现场边界与验证)。

颜色回读不代表画布效果已确认，结果保留 `visualVerified:false`。现入口改变已有net-class的色值，不控制显示开关，也不提供每pad直接赋色接口；历史单网覆盖、层显示、背景与缩放都可能影响识别。未完成当前画布核验时记录“颜色已回读，显示待确认”，不宣称每个焊盘已着色。缺少建类或显示控制的封装时，按当前原生能力处理并说明范围，不能绕过分类/成员检查。

离线布局SVG/候选预览目前使用固定焊盘色，尚未继承现场NetClass配色。现场颜色与候选渲染是两个接口，不能从离线图推断实际焊盘已按功能显示；把分类颜色贯穿候选报告仍是后续衔接缺口。
