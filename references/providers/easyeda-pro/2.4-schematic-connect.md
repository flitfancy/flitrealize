# 原理图连接与收尾入口

Contract、器件和引脚映射已确认，准备生成端点短线与网络标识，或复核这种原理图的完成情况时读取。入口复用现有 Action，适用于不同器件、网络、功能分组与项目。

```text
node <skill>/scripts/schematic-connect.mjs --project-root <project> --input-file <input.json> --window-id <window>
node <skill>/scripts/schematic-connect.mjs --project-root <project> --input-file <input.json> --window-id <window> --apply
node <skill>/scripts/schematic-connect.mjs --project-root <project> --input-file <input.json> --window-id <window> --check
```

- 默认：只读现场、生成缺项计划和证据，不修改 EDA。
- `--apply`：执行缺少的连接，验证，按配置重排，保存并执行严格 DRC，再对照保存后的实际端点和标签。
- `--check`：对照 Contract 检查已有连接、NC、标签及严格 DRC；配置了重排时也检查布局是否收敛。不会保存，不能据此宣称本次确认了保存。

## 输入

使用嵌入的 `contract` 或 `contractFile` 二选一。文件路径相对于输入 JSON 所在目录。

```json
{
  "expectedProjectUuid": "actual-project-uuid",
  "expectedDocumentUuid": "actual-schematic-uuid",
  "contractFile": "../design/schematic-contract.json",
  "strategy": "endpoint-stubs",
  "stubLength": 8,
  "grid": 1,
  "connectionTolerance": 0.1,
  "deferredComponents": [],
  "providerPinNoConnect": [],
  "reflow": {
    "blocks": [{ "name": "input", "members": ["J1", "R1"], "columns": 1 }],
    "layout": {
      "unit": "easyeda-schematic",
      "componentSpacing": 72,
      "blockSpacing": 210,
      "attachmentSpacing": 140,
      "mainFlow": ["input"],
      "attachments": []
    }
  }
}
```

位号、分组、尺寸、标识类型与参数来自本项目。坐标单位同现有原理图 Action，布局配置直接复用 `schematic-reflow` 的格式。

`designators` 可显式限定本次器件范围；没有该字段时检查整个 Contract。报告记录范围，局部完成不等于整张图所有设计已实现。严格 DRC 仍检查当前整张图。

缺少的契约器件默认报错。确实属于其他阶段的器件可列入 `deferredComponents: [{"designator":"TP1","reason":"PCB 阶段实现的裸露焊盘"}]`；延后项保留在覆盖报告里，不默认忽略所有未放器件。

NC 主要从 Contract 的 `classification: "no-connect"` 及 EasyEDA `pinMap` 派生。符号额外物理引脚可用 `providerPinNoConnect: [{"designator":"SW1","pin":"4","reason":"已核对该型号，此脚为不连接的固定脚"}]` 明确补充。仅在查清用途后填写；当前悬空或已有 NC 状态本身不构成依据。NC 与契约网络端点冲突会阻止写入。

## 哪些步骤保证执行

入口每次计算导线、标识和 NC 的适用性与实际缺项。没有 NC 时记录 `not-applicable`；已有标识通过实际位置、网络与显示属性检查后复用。必需步骤无缺项时不重复创建对象。

```text
Contract + 当前引脚/导线/标识
→ 缺项计划与冲突检查
→ 分批补齐导线与标识、处理声明的 NC
→ 对照端点/网络/NC/可见标签
→ 配置要求的 complete 重排与再次对照
→ 保存 + 严格 DRC
→ 保存后端点与标签复核
```

网络标识创建固定使用 `showName: false`，导线 `NET` 为可见网络名称。已有重复显示会明确报出，布局阶段不承担隐藏或修补职责。

重排使用本项目已有 `reflow` 配置，不猜布局偏好。未提供配置时明确记录未请求重排；也可写 `{"mode":"preserve","reason":"本次只补 NC，保留已确认布局"}`。需要初排时，在连接前调用现有 `schematic-reflow initial`。

自动生成目前支持直端点短线和标识。实际导线更长、连接多个引脚、含总线或层次关系时，会报告当前自动化范围不匹配；可按 [原理图实现](2.2-schematic-workflow.md) 使用相应方法完成。该限制属于这个端点短线入口，不限制 Skill 的电路或画图方法。

## 证据与恢复

每次运行把输入、逐步请求、Action 报告和最终结果保存在项目 `evidence/schematic-connect/`；写入前另存原生源码备份。不会自动重写 Contract 或项目主文稿。

重复运行通过现场重新计算缺项；已有正确导线与标识不会再次生成。已知失败保留已完成结果，下一次只在重新对账后处理缺项。布局已完成但保存/DRC 失败时，仍报告各阶段真实状态，不把 `saved: true` 当成全部成功。

通信丢失或写入终态不明会保留同目标的占用文件，并阻止新的写入批次绕过。按 [Provider 恢复](../../0.3-easyeda-pro.md#失败与恢复) 查询原请求、核对现场后处理；本入口不会自行清除未知写入或整图回滚。`--check` 仍可作只读诊断。

只有所选范围的连接审计、要求的布局检查、保存与严格 DRC 均成功，`--apply` 才返回 `ok: true`。局部范围、明确延后器件及未请求重排仍在结果中保留，电气功能与硬件性能需单独验证。
