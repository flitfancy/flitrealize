# 1.2 Part selection and sources

Read this reference when the design needs exact parts, inventory matching, or datasheets.

Part selection serves circuit design and does not depend on a particular EDA library. Stable decisions enter the "Part decisions" section of `CURRENT_HANDOFF.md`.

## Workflow

```text
AI defines the part role and critical requirements
    |
    v
Read available inventory
    |
    v
Propose an exact part or a small candidate set
    |
    v
Resolver checks the local source library and retrieves missing material
    |
    v
AI reads the parameters needed for the current decision
    |
    v
Accept a part or retain candidates
    |
    v
Enter the schematic Contract
    |
    v
Bind EDA identity last
```

AI owns circuit judgment and the final selection.

Scripts handle:

- local source lookup;
- product-source retrieval from exact identity;
- PDF download and checks;
- source, file metadata, and local-path storage;
- inventory and source-status aggregation.

Scripts return sources and candidates; they do not replace circuit judgment.

## Start from the circuit requirement

Before selecting a part, define its circuit role and the conditions that materially affect the choice, such as:

- voltage, current, power, and frequency range;
- accuracy, efficiency, noise, temperature rise, or timing;
- package, dimensions, and thermal conditions;
- required protection or control behavior;
- supply, inventory, and cost requirements.

Record only parameters needed for the current choice.

Check existing inventory first. Use an inventory part only when its identity is reliable, its parameters meet the requirement, and its package is usable.

When inventory has no suitable part, retain a small set of reasonable candidates and produce a purchase list.

## Part identity

Record identity at the level the design needs:

- **exact:** manufacturer, exact MPN, suffix, and package are confirmed;
- **generic:** value, required ratings, tolerance, package, and allowed range define the part;
- **unresolved:** sources are insufficient or no part satisfying the hard requirements has been found.

Parts that own protection, power conversion, battery management, critical interfaces, or another core function should reach `exact` before complete schematic implementation, with pins, package, and key ratings confirmed.

Ordinary resistors and capacitors may remain `generic`. A connector, switch, or mechanical part should reach `exact` before the stage where it determines pinout or PCB geometry.

Only accepted identities enter the Contract. Candidates still under comparison remain in the part section of the manuscript.

## Local part source library

When the user has configured a shared local library, the resolver checks it first:

```text
parts-database/
|-- C470965/
|   |-- part.json
|   `-- datasheet.pdf
`-- MPN_TPS25221DBVR/
    |-- part.json
    `-- datasheet.pdf
```

An exact local match returns immediately without network access.

When no local source exists, the resolver may retrieve product information and a datasheet from a currently supported source and save them for reuse by later projects.

The library is shared tool data, not the design authority for one project. The adopted model, package, and rationale remain in the current manuscript and Contract.

## Sources

Manufacturer sites, official stores, and authorized distributors may directly confirm:

- manufacturer;
- exact MPN;
- purchasing code;
- package;
- stock and price;
- datasheet link.

When identity does not conflict, do not add more sources merely to prove the same basic information again.

Read manufacturer datasheets for electrical facts on which the design depends. Enter CURIOUS_MODE only for the affected part when:

- store identity conflicts with manufacturer material;
- the exact suffix or package cannot be confirmed;
- the design depends on curves, temperature rise, transients, derating, or mechanical timing;
- the datasheet does not directly answer a question that affects a core function;
- the part owns protection, isolation, or fault shutdown.

Continue ordinary part work after the issue is resolved or converted into a prototype test.

## Use the source resolver

Provide the exact identity and keywords already known whenever possible:

```json
{
  "lcsc": "C536262",
  "manufacturer": "Infineon",
  "mpn": "IM69D130V01",
  "keywords": ["PDM", "4x3mm"]
}
```

Basic invocation:

```text
node <skill>/scripts/parts/parts-resolver.mjs \
  --project-root <project> \
  --database-root <parts-database> \
  --input <project input file>
```

Use the script's current `--help` for exact arguments.

The resolver returns:

- `local`: exact material already exists locally;
- `downloaded`: material was retrieved and saved;
- `needs_lookup`: AI should perform one focused search using the returned identity;
- `error`: exact material was not retrieved in this run.

These results describe source acquisition only. They do not mean the part has passed circuit review.

When a source code is stale, AI may perform one focused lookup using manufacturer, MPN, and keywords, then return the confirmed datasheet URL to the resolver for storage. If the identity still cannot be confirmed, keep it unresolved instead of substituting a similar name automatically.

## Read datasheets

Downloading is not review.

In DEFAULT_MODE, read what the current selection requires, such as:

- ratings and recommended operating conditions;
- pinout and package;
- critical electrical parameters;
- typical application and external parts;
- protection, startup, or fault behavior on which the current circuit depends.

Do not open every PDF in the local library automatically.

In CURIOUS_MODE, inspect only the exact parts and sections involved in the uncertainty.

## Inventory and source aggregation

The source inventory records what the user physically owns.

The local part library records acquired identity and datasheets.

An AI-facing inventory CSV may combine them as a read-only view, for example:

- whether a local source exists;
- its source directory;
- the current exact MPN;
- the most recent source.

The generator derives these fields from the current library. The user does not maintain them manually in the inventory workbook.

After the resolver adds material, the current task can use the returned path immediately. A later inventory CSV refresh incorporates the updated source state.

## Update the project manuscript

For each accepted part, record:

- circuit role;
- manufacturer and exact MPN for an `exact` part, or complete specification for a `generic` part;
- package;
- current purchasing identity;
- key parameters that drove the choice;
- rationale;
- datasheet or local source path;
- allowed substitutions and their conditions;
- remaining prototype checks.

Update "Part decisions" and the current handoff at the top.

When a part enters the schematic, write its accepted identity and required parameters into [2.1-schematic-contract.md](2.1-schematic-contract.md). During manufacturing preparation, select the order MPN only from accepted parts or their allowed substitute range.
