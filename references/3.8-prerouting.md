# 3.8 预走线、出口规划与局部重布

布局候选需要检查出口、跨层通道、相邻引脚竞争、实际铜路径或有限重布时读取。原生 FR 写入入口仍为 [3.8](providers/easyeda-pro/3.8-autorouting.md) 的 `pcb-route.mjs`；本页新增入口只生成离线候选/诊断，不写 EDA。

数值运行依赖按需见[首跑指南](../docs/first-run.md#数值与路由环境)。

```text
node <skill>/scripts/pcb-preroute.mjs --project-root <项目> --input <请求JSON> --mode <模式> --output <项目内目录>
```

通过 manifest 查询“预走线”“联合扇出”“铜路径”“局部回退”即可发现同一入口，不逐轮复制项目脚本或修改源码字符串。

## 最小运行示例

先建立一个空的独立样例目录，再运行随包 [两焊盘请求](../assets/pcb-routing/preroute-request.json)；已有输出也可用冻结输入重放：

```text
node "<skill>/scripts/pcb-preroute.mjs" --project-root "<独立样例目录>" --input "<skill>/assets/pcb-routing/preroute-request.json" --mode prepare --output evidence/preroute-prepare
node "<skill>/scripts/pcb-preroute.mjs" --project-root "<独立样例目录>" --input evidence/preroute-prepare/input.json --mode route --output evidence/preroute-example --python "<数值环境的python>"
node "<skill>/scripts/pcb-preroute.mjs" --project-root "<独立样例目录>" --input evidence/preroute-prepare/input.json --candidate evidence/preroute-example/route-result.json --mode verify --output evidence/preroute-verify
```

样例已按这条链运行，1网全通、独立验收0问题；教学尺寸/规则不代表本项目制造条件。也可直接对样例请求运行 route。真实任务读取自己的board与policy；结果目录保留完整候选，摘要列出连接、未完成网及问题。

| 最小字段 | 来源/用途 |
| --- | --- |
| `board.units/boardMil` | mil及明确零原点矩形尺寸，或已有规范化板边 |
| `board.pads/copper` | 保留物理焊盘ID和归属；prepare按ID复用对应 `copper.shape` |
| `policy.layers` | 声明层ID，公共用途用 `{id,purpose}` 对应；也可用 `options.layerMap` 明确转换 |
| `policy.nets` | 网络、声明线宽、源端与分支规则；已有角色按项目数据提供 |
| `options` | 格点/预算及明确铜边距、孔径/外径和间距 |

样例用 `top-copper/bottom-copper` 映射到声明的11/22层，展示编号可由调用者定义。复用render几何时不重新抄坐标，不凭其他Provider的原生层号猜转换；冻结后沿用该次层映射。

## 输入与模式

通用分析请求使用 `{mode,board,policy,options,...}`，board 为 mil 的焊盘、层、铜线、过孔和边界；保留每个物理焊盘 ID。扫描额外给明确 `outline`，不同板层按数据声明，不固定某项目层号。

| 模式 | 输入与输出 |
| --- | --- |
| prepare | 由 board/policy 的明确 source/branch/preroute 声明构造网络铜岛；输出 frozen input |
| fanout / route | 两层 A* 出口/路径候选，并运行独立几何和端点验收 |
| verify | 读取冻结预走线输入与 `--candidate`，重新检查实际铜接触和规则 |
| diagnose | 可达区域、边界网络与有限试释放诊断；预算失败不等于连续空间无解 |
| scan / joint-fanout | 全层孔位与源线扫描；按候选域大小回溯选择相容出口 |
| transition-plan | 由明确 task/角色生成同层变径或孔后变粗的过渡种子 |
| paths | 从线、孔、焊盘接触构建关键端点铜路径图 |
| repair-plan | 排序阻挡网并给有限角色/整网回退范围 |
| prune / shortcut | 指定普通网的保连通冗余清理和同层绕孔；保护角色及配对网 |
| compose | 相同冻结几何下，各轮完整路径的冲突图与 CP-SAT 相容选择 |
| ground | 潜在地空间诊断，见 [3.3 地空间](3.3-ground-space.md) |

Python A* 输入支持已保存的规范化 `boardMil/pads/segments/vias/nets`，亦可由 prepare 生成。每 pad 的 `shape/shapes/contactShapes` 区分保守障碍与真实端点接触；每 net 的源端、分支宽度、允许层、窄引出限长等由规则提供。新准备输入检查声明线宽，历史输入只回放原几何并报告未覆盖项。A* 严格限两个声明层；全层空位扫描和路径图可用于明确声明的多层板。

prepare消费 `policy.layers[].signalRoutingAllowed:false`：该层不得进入自动trace允许集合，声明角色/分支引用它会拒绝；`ground_plane` 仍委托接地流程。公共用途经 `{id,purpose}` 或 `options.layerMap` 显式转ID，角色 `allowedLayers` 与 `viaTransition` 的用途字段也使用这张映射；不猜其他Provider层号。

两层A*不会因输入含主干过渡字段就取得FR的并联拓扑验收。冻结输入保留 `ruleCoverage.mainViaTransitionTopologyVerified:false`，`mainViaTransitionBackend:'FR'`；多层载流主干的过渡/正整数并联数量与实际铜验收按 [FR说明](providers/easyeda-pro/3.8-autorouting.md#输入和职责)。层映射、预留层检查及A*连通通过分别报告，不能互相替代。

## 规划、预留和过渡

孔扫描需要显式的搜索半径/格点、铜与钻孔间距、板边、孔外径/孔径、源层及引线宽度；这些参数来自项目或搜索设置，不是通用制造常数。孔有空位还须检查源引线、全层占位、目标层接续及其他新出口。

`source-escapes.mjs` 按源焊盘/任务形成有限候选域，以回溯、成本下界和共用预算选组合。不同源不能逐脚占最近位置后才检查邻脚。先审计实际细线和孔已实现对应出口，再释放该出口的规划预留；不相信 completed 标记，不一次取消整网全部预留。

`transition-planner.mjs` 比较完整同层与换层方案；短细段、主干宽度、允许层和并联孔仍用角色规则。孔后寻路保持该角色全部允许层；不能将普通细支路当作载流主干。解算/评价通过注入已有后端连接，未请求时不替换 FR 的默认策略。

## 路径、回退与清理

`copper-path.mjs` 配置关键端点和分组，分别返回直线距离、铜中心线投影、焊盘/接触转移、换层及宽铜偏好。投影不包含孔桶长、真实电流分布或电磁回路，不用凸包或长度代理宣称 EMI/热设计完成。

角色回退保留其他角色共享铜，并清除撤回角色的旧引出授权；整网回退必须恢复完整角色集合。局部修复保护原连接和范围外指纹；局部路径优化另检查目标收益及关键路径回归。粗布局探索不默认把全部旧路径长度变成硬门槛。

compose 只能选择已有路径集合中的相容组合，不能据其最优值宣称整板无解。清理逐项重算全端点接触，功率、Kelvin和配对数据等受保护，后续重新验收全部铜与地空间。

## 预算、续接与范围

同层、孔位、寻路和重布共用任务预算；记录空候选域、有限搜索无解、预算耗尽及规则拒绝。`task-budget.mjs` 冻结 board/policy/options，并保留出口、预留、授权、已接受候选与尝试状态。恢复时不重复加权，不丢选项。

报告区分候选、局部角色、整网全端点和原生保存/工程验证。完整几何留在 result 文件，CLI 只返回摘要。本入口没有原生写入，最终应用必须重新绑定现场并转成现有完整候选/写入计划；不绕过位号、机械、原生 DRC 和保存回读。
