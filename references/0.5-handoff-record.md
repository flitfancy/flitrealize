# 0.5 文稿工具与续接记录

使用事实表生成工具、首次建立结构化记录或排查本地引用时读本页。文稿内容与更新方式见 [0.1](0.1-continuation.md)，面板标记见 [View State](../view-state/README.md#展示合同)。普通文字续接不需要采用下列工具或格式。

## 按需生成原理图事实表

[handoff-sync.mjs](../scripts/handoff-sync.mjs) 只消费已有 Contract v1、可选 Snapshot v1 或成功的 `schematic-inspect` 报告，生成器件、引脚网络、NC／DNC 和延期项表格。它不连接 EDA、不调用连线规划器，也不更新其他项目状态。

```text
node <skill>/scripts/handoff-sync.mjs --project-root <项目> --contract design/contract.json [--snapshot evidence/inspect.json] [--connections design/connections.json]
```

路径从项目根目录解析，须为项目内文件。`--connections` 只读取已有配置的预期目标、`deferredComponents` 和 `providerPinNoConnect`，不读取布局或连线策略。

| 参数 | 行为 |
| --- | --- |
| 默认 | 输出简短预览摘要，不写文稿 |
| `--print` | 在默认预览中输出完整拟生成区，不能与检查或写入模式并用 |
| `--check` | 只比较现有生成区与输入；退出码 1 表示缺失、变化或人工编辑，2 表示输入或调用错误 |
| `--apply` | 本次需要更新时，替换已有文稿中唯一的生成区 |

初次采用时选择插入位置，放入以下空标记；脚本不自动创建文稿或追加区域：

```html
<!-- flitrealize:facts:start -->
<!-- flitrealize:facts:end -->
```

写入保留区域外文字。内容相同不写文件、不刷新时间；生成区被人工编辑时拒绝覆盖。默认预览和检查不产生报告、缓存或状态文件。输入或文稿在生成期间变化时停止写入；项目外输入、链接文稿和异常生成区按现有检查拒绝，写入文稿须为单链接的普通文件。

表格分列设计意图和快照观察，保留输入指纹、目标及快照原始时间。缺少映射、型号、封装或实际网络时显示未提供／未核验；快照未报告网络不等于引脚未连接。工具不解析任意 DRC 或保存报告、不推断库存，也不验证电路语义。

## 可选结构化记录

长流程可在同一份 `CURRENT_HANDOFF.md` 顶部保留一个 `flitrealize-handoff` 块，记录当前入口、输入版本、证据和检查范围。技术字段可折叠；它不代替正文中的设计、引脚和布局表，已有纯文字文稿不必迁移。实际引用检查由 [handoff-check.mjs](../scripts/handoff-check.mjs)完成。

## 最小格式与字段

以下是字段示意，路径、时间、UUID 和哈希须用当前项目的真实值替换；不是可直接执行的样例，也不表示任何检查已经通过。尚未选择 EDA 或脚本时，`target` 或 `entrypoint` 写 `null`，不编造值。阶段名使用能明确当前工作的短名称，不是审批状态机。

````markdown
## 0. 当前交接

```flitrealize-handoff
{
  "schemaVersion": 1,
  "updatedAt": "<本次交接更新时间，带时区 ISO 时间>",
  "projectRoot": "<用户指定的绝对项目路径>",
  "stage": "pcb-layout",
  "objective": "收束布局，本次不布线",
  "target": {
    "provider": "easyeda-pro",
    "projectId": "<实际项目 UUID>",
    "documentId": "<实际 PCB UUID>"
  },
  "entrypoint": {
    "root": "project",
    "path": "design/placement-runner.mjs",
    "sha256": "<已选脚本的实际 SHA256>",
    "args": ["--input-file", "design/placement-input.json", "--plan"]
  },
  "nextAction": "先回读用户手改后的布局，核对受影响坐标并重建计划",
  "openItems": ["保存状态尚未确认"],
  "artifacts": [
    {"id": "source", "path": "design/board-source.json", "sha256": "<源文件实际 SHA256>"},
    {"id": "input", "path": "design/placement-input.json", "sha256": "<输入实际 SHA256>"},
    {"id": "readback", "path": "evidence/layout-readback.json", "sha256": "<回读证据实际 SHA256>"}
  ],
  "checks": [
    {
      "id": "placement",
      "status": "verified",
      "scope": "仅核对本批次 U1、C1 的目标坐标和原有对象保留",
      "checkedAt": "<该检查实际完成时间，带时区 ISO 时间>",
      "inputs": ["source", "input"],
      "evidence": ["readback"],
      "limitations": ["不包括保存、布线和整板 DRC"]
    },
    {
      "id": "save",
      "status": "unknown",
      "scope": "当前文档保存状态",
      "checkedAt": null,
      "inputs": ["source"],
      "evidence": [],
      "limitations": []
    }
  ]
}
```
````

- `entrypoint` 记录实际选中的脚本及调用参数，参数不含密钥或会话令牌；这里只是入口记录，不执行命令。引用的输入文件登记在 `artifacts` 中。多个步骤时记录当前下一步入口，其余编排以原脚本/Workflow 为准，不复制进状态。
- `artifacts` 只登记已有的项目内稳定文件，路径用 `/` 分隔。目录、URL、跨项目路径以及 `.flitrealize` 临时文件不能作为这里的证据。外部资料仍按原资料章节记录；需要指纹比对时使用已取得的项目本地制品。
- `checks` 每项有明确范围、所依据的输入版本和证据 ID。ID 唯一，且引用必须存在。记录工具实际检查的范围，不因工具返回 `ok: true` 把整阶段写成 `verified`。
- `updatedAt` 是交接更新时间；`checkedAt` 是检查发生时间，不随续接自动改成“现在”。未执行的检查填 `null`。
- `target` 是被记录的目标身份，不是现场探测结果。只读脚本不会证明远端文档、报告内部 UUID 或机器事实相符；仍由执行者核对。

## 读取指纹

```text
node <skill>/scripts/handoff-check.mjs fingerprint --project-root <项目绝对路径> --file <项目相对文件>
node <skill>/scripts/handoff-check.mjs fingerprint --project-root <项目绝对路径> --root skill --file scripts/<入口>
node <skill>/scripts/handoff-check.mjs inspect --project-root <项目绝对路径>
```

`inspect` 的退出码 0 表示结构和本地指纹一致，1 表示引用缺失或变化，2 表示旧格式、缺少记录或输入无效。`fingerprint` 只读取指定文件的哈希。这些命令不改写文稿或哈希、不执行记录中的入口、不连接 EDA；本地引用一致不证明检查结论真实。

文件变化后按 [0.1](0.1-continuation.md#信息归属与更新)核对受影响事实，再更新记录。现场变化、保存和未知结果按 [0.3 共同规则](0.3-easyeda-pro.md#失败与恢复)处理。
