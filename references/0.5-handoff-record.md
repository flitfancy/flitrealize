# 0.5 续接记录格式

仅在首次建立结构化续接记录、修改字段结构或排查格式错误时读取。普通续接使用 [0.1 项目主文稿与续接](0.1-continuation.md) 和只读检查结果，不必加载本样例。

这里定义同一份 `CURRENT_HANDOFF.md` 内可选的续接记录，不新增状态文件，也不代替正文中的设计、引脚和布局块表。保留一个块即可，技术字段可放在折叠区；原有纯文字文稿不必为续接强制迁移格式。实际检查由 [handoff-check.mjs](../scripts/handoff-check.mjs) 完成；脚本只核对本地引用，不能证明记录中的验证结论真实。

## 最小格式与字段

以下是字段示意，路径、时间、UUID 和哈希须用当前项目的真实值替换；不是可直接执行的样例，也不表示任何检查已经通过。尚未选择 EDA 或脚本时，`target` 或 `entrypoint` 写 `null`，不编造值。阶段名使用能明确当前工作的短名称，不是审批状态机。

````markdown
## 0. 当前交接

```flitrealize-handoff
{
  "schemaVersion": 1,
  "updatedAt": "<本次交接更新时间，带时区 ISO 时间>",
  "projectRoot": "<用户指定的绝对项目路径>",
  "stage": "pcb-layout",
  "objective": "收束布局，本次不布线",
  "target": {
    "provider": "easyeda-pro",
    "projectId": "<实际项目 UUID>",
    "documentId": "<实际 PCB UUID>"
  },
  "entrypoint": {
    "root": "project",
    "path": "design/placement-runner.mjs",
    "sha256": "<已选脚本的实际 SHA256>",
    "args": ["--input-file", "design/placement-input.json", "--plan"]
  },
  "nextAction": "先回读用户手改后的布局，核对受影响坐标并重建计划",
  "openItems": ["保存状态尚未确认"],
  "artifacts": [
    {"id": "source", "path": "design/board-source.json", "sha256": "<源文件实际 SHA256>"},
    {"id": "input", "path": "design/placement-input.json", "sha256": "<输入实际 SHA256>"},
    {"id": "readback", "path": "evidence/layout-readback.json", "sha256": "<回读证据实际 SHA256>"}
  ],
  "checks": [
    {
      "id": "placement",
      "status": "verified",
      "scope": "仅核对本批次 U1、C1 的目标坐标和原有对象保留",
      "checkedAt": "<该检查实际完成时间，带时区 ISO 时间>",
      "inputs": ["source", "input"],
      "evidence": ["readback"],
      "limitations": ["不包括保存、布线和整板 DRC"]
    },
    {
      "id": "save",
      "status": "unknown",
      "scope": "当前文档保存状态",
      "checkedAt": null,
      "inputs": ["source"],
      "evidence": [],
      "limitations": []
    }
  ]
}
```
````

- `entrypoint` 记录实际选中的脚本及调用参数，参数不含密钥或会话令牌；这里只是入口记录，不执行命令。引用的输入文件登记在 `artifacts` 中。多个步骤时记录当前下一步入口，其余编排以原脚本/Workflow 为准，不复制进状态。
- `artifacts` 只登记已有的项目内稳定文件，路径用 `/` 分隔。目录、URL、跨项目路径以及 `.flitrealize` 临时文件不能作为这里的证据。外部资料仍按原资料章节记录；需要指纹比对时使用已取得的项目本地制品。
- `checks` 每项有明确范围、所依据的输入版本和证据 ID。ID 唯一，且引用必须存在。记录工具实际检查的范围，不因工具返回 `ok: true` 把整阶段写成 `verified`。
- `updatedAt` 是交接更新时间；`checkedAt` 是检查发生时间，不随续接自动改成“现在”。未执行的检查填 `null`。
- `target` 是被记录的目标身份，不是现场探测结果。只读脚本不会证明远端文档、报告内部 UUID 或机器事实相符；仍由执行者核对。

## 读取指纹

```text
node <skill>/scripts/handoff-check.mjs fingerprint --project-root <项目绝对路径> --file <项目相对文件>
node <skill>/scripts/handoff-check.mjs fingerprint --project-root <项目绝对路径> --root skill --file scripts/<入口>
node <skill>/scripts/handoff-check.mjs inspect --project-root <项目绝对路径>
```

这些命令不改写文稿或哈希，也不执行记录中的入口。文件变化后先核对影响，再更新相应派生视图和记录；不能仅刷新哈希把旧验证变成新验证。正文目录与维护方法见 [0.1](0.1-continuation.md)。
