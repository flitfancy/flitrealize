# 0.3 共同执行规则与 Provider

本页单独维护现场目标、写入、保存回读和未知结果恢复。首次现场执行、目标或通道变化、需确认执行边界或出现未决结果时读取；同一任务复用已确认规则，普通离线计算不以连接 EDA 为前置。

当前现场 Provider 为 EasyEDA Pro。Provider 解释原生身份、坐标、层和网表；通用布局、预走线与地空间使用转换后的项目数据。操作支持范围由对应说明和回执给出。

## 先找实际入口

能力查找按 [主 Skill](../SKILL.md#查找能力)。`reference` 和 `entrypoint.file` 相对于 Skill 根目录，Action 的 `file` 相对于 `scripts/actions/`。返回值区分：

- `script`：已有封装入口，负责衔接步骤并保留报告。
- `action-runner`：按结果给出的名称、参数和本次输入调用。
- `workflow-steps`：步骤说明，不是直接执行命令。

单独调用 Action 时使用：

```text
node <skill>/scripts/action-runner.mjs run --action <name> --input-file <input.json> --project-root <项目> --window-id <窗口> --report-file <项目证据路径>
```

写入带 `--allow-write`；高层入口使用其说明中的 `--apply` 等参数，已有用户授权不重复询问。没有适用封装时可使用当前可用 API；新方法先验证再登记为稳定能力。

## 选择执行通道

客户端 CLI 与网页 Bridge 是同一 EasyEDA Provider 的两种通道，仍由原宿主 `eda-host.mjs` 调度，不另建 Skill 或业务入口。

客户端可用时先检查其 `doctor`，再检查或复用会话；不要每次操作重新初始化客户端。注册或临时探测使用原宿主参数：

```text
node <skill>/scripts/eda-host.mjs register --eda easyeda-pro --adapter-root <skill>/adapters/easyeda-pro --channel cli --cli-executable <已确认的客户端CLI路径>
node <skill>/scripts/eda-host.mjs status --eda easyeda-pro --channel cli --cli-executable <已确认的客户端CLI路径>
node <skill>/scripts/eda-host.mjs ensure --eda easyeda-pro --channel cli --cli-executable <已确认的客户端CLI路径> --require-eda
```

`--channel cli|bridge` 和 `--cli-executable PATH` 是宿主层参数；`pcb-layout`、`pcb-edit`、`pcb-route` 等高层命令仍使用原参数，通过已注册宿主配置选择通道。临时环境配置可用 `FLITREALIZE_EDA_CHANNEL` 和 `FLITREALIZE_EASYEDA_CLI`。路径与会话状态属于本机配置，不写入项目 Contract。

网页或明确选用Bridge时才读 [0.4](providers/easyeda-pro/0.4-environment.md)，已有连接直接复用。官方CLI的doctor、会话、只读API和超时后原请求查询已实测；原生写入、保存及DRC仍按本次操作核验代表对象及结果。

## 现场边界与验证

操作前核对本次项目、目标文档、对象范围和预期增量；目标身份、对象归属、引脚、网络、层和几何来自权威源文件或结构化回读，画布只用于视觉检查。目标或现场变化后重新读取，旧快照、旧会话和旧候选不自动代表当前现场。执行期间避免第二个写入者。

现场修改沿已有入口完成 `读取 → 计划 → 修改 → 回读 → 保存 → 保存后核对`。检查本次增量与范围外原有内容；保存必须有独立证据。计划、写入、保存、连通、DRC、电气和样机验证分别记录，检查结果注明对象或版本、范围、时间及证据；一个成功状态不能替代其他验收。只读检查不要求修改或保存。

`saved:true` 表示保存已确认；false/null 的含义由具体操作给出，区分“未尝试”“未检查”与“已尝试但未确认”。保存后的回读失败不抹去已保存事实，verify 也不自动证明保存或整板验收。

操作页仅补充各自的支持对象、锁定与铜限制、DRC 差异策略、事务占用和恢复接口，不重复维护本节规则。

## 失败与恢复

失败、超时或返回不明时保留报告、请求句柄和原会话，先取得原操作终态并对照现场。超时不等于未执行，`running/unknown`、查询不到或没有成功回执均不能证明没有写入；不得重放旧写入或换新批次绕过未决操作。

- 已确认部分结果：按本次对象 ID 和回读证据补齐必要增量，保留用户修改。
- 仅保存失败：确认 apply 已成功且现场仍匹配后，只续保存链，不重做修改。
- 撤销：仅处理能证明由本次创建的对象；来源、目标或恢复完整性不明时不删除、不报告 rolled-back。
- 原操作仍在执行或终态未知：停止冲突写入；各入口的占用记录、续接或关闭机制以操作页为准，不删记录绕过。

原宿主 `eda-host.mjs request --eda easyeda-pro --channel <原通道> --request-id <原ID> --session-id <原会话>` 查询原请求。Bridge细节见 [0.4](providers/easyeda-pro/0.4-environment.md#查询中断的请求)，CLI复用原会话与不可变阶段回执。查询不重放代码，迟到结果作为补充证据，不自动改写旧报告或释放流程占用。源码备份用于对账和有范围的恢复，不整图覆盖后续修改。

## API 与完成范围

补充原生调用时，先用 `scripts/api-reference.mjs search/show` 定向查看签名、类型及限制；内置语料是历史快照，新调用还要核对来源资料和编辑器实际支持。已有 Action 正常运行时不重复加载底层 API 文档；修改工具时才读 [Action 开发](../development/action-system.md)。

只交付本次要求及其验证范围。稳定结论按 [0.1 文稿约定](0.1-continuation.md)同步拥有事实的制品和相关正文，不擅自展开制造或后续阶段。
