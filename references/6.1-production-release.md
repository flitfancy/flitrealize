# 6.1 Productization and formal release

Read this reference only when the user explicitly asks for repeat production, batch PCBA, reproducible delivery, or formal release.

An ordinary personal prototype can move from physical validation into another revision without a separate release process.

## Define the release goal

State what the current release must support:

- repeated production of one hardware revision;
- outsourced PCBA;
- external delivery of manufacturing files;
- a formal product version;
- applicable compliance, traceability, or quality requirements.

Add only the work required by the actual release goal.

## Fix the current version

A formal candidate should pair the same version of:

- requirements and design decisions;
- schematic and PCB source;
- BOM and allowed substitutions;
- Gerber, drill, and assembly files;
- firmware or configuration dependencies;
- prototype validation results;
- production test or calibration method.

See [4.1-production-handoff.md](4.1-production-handoff.md) for manufacturing files and candidate packaging.

## Handle repeat-production needs

Confirm as applicable:

- continuing availability of critical parts;
- long-term substitution range and validation conditions;
- production revision identification;
- power, function, and interface testing;
- calibration, serial number, or result records;
- fixed enclosure, harness, and assembly method;
- repair, rework, and failed-unit handling.

One passing prototype proves only that unit under its tested conditions. It does not remove the need for production testing of later builds.

## Regulation and professional review

For mains, high voltage, battery safety, medical use, radio approval, or another regulated use, identify the current applicable standards and obtain the professional review and tests the product actually requires.

This Skill can organize design and evidence but cannot replace certification or accountable sign-off.

## Release conclusion

State directly:

- the release object and version;
- available physical and production evidence;
- actual blockers;
- accepted limitations;
- remaining production test, certification, or supply work;
- next action.

Limit the conclusion to the declared release goal. Do not create status tables, stage paperwork, or evidence labels that do not change the release decision.
