# 6.1 Productization and formal release

Read this reference only when the user explicitly requests repeat production, volume PCBA, reproducible delivery, or formal release.

An ordinary personal prototype may be revised directly from measurements without entering this stage.

## Define the target

State what this work is preparing to support:

- repeated production of the same hardware version;
- outsourced PCBA;
- external delivery of manufacturing files;
- a formal product version;
- applicable regulatory, traceability, or quality requirements.

Do only the work the current release target needs.

## Fix the current version

Align these items to one version:

- requirements and design decisions;
- schematic and PCB source;
- BOM and allowed substitutes;
- Gerber, drill, and assembly files;
- firmware or configuration dependencies;
- prototype validation results;
- production test or calibration method.

See [4.1-production-handoff.md](4.1-production-handoff.md) for manufacturing files.

## Repeatable production

As the project requires, confirm:

- continued availability of critical parts;
- long-term substitute ranges and validation conditions;
- how production identifies the version;
- how power, function, and interfaces are tested;
- whether calibration, serial numbers, or test records are needed;
- whether enclosure, harness, and assembly method are fixed;
- how repair, rework, and failed units are handled.

Prototype validation does not replace production testing for later batches.

## Regulation and professional review

For mains, high voltage, battery safety, medical, radio certification, or another regulated use, check current applicable standards and obtain the professional review and testing the project requires.

This Skill can organize design and evidence, but it does not replace certification or sign-off responsibility.

## Update the project manuscript

Under section 6.x, record:

- current release object and version;
- available physical and production evidence;
- issues that truly block release;
- accepted limitations;
- remaining production-test, certification, or supply work;
- next action.

Update the current handoff at the top as well.

Conclusions cover only the current release target. Do not add status tables or stage paperwork that does not change the release decision.
