# 0.1 项目主文稿与续接

新建或整理项目文稿、同步稳定结果时读本页。普通续接按[主 Skill](../SKILL.md#项目续接)读已有顶部和本次章节。全流程使用同一份 `CURRENT_HANDOFF.md`，把当前设计、结果、依据和下一步留在项目里。

## 开始与续接

- 新项目先确认用户指定的根目录，从已知目标、需求、器件条件和下一步开始，不继承同级项目的设计状态。
- 已有主文稿时，先读顶部交接和本次相关章节，再查拥有事实的原制品。
- 主文稿缺失时，从本项目需求、设计、EDA、制造和测试制品恢复；缺少依据的内容标明未决。纯查看任务只报告缺口。

新建或首次接管项目时，按 [View State](../view-state/README.md#由-skill-拉起面板)打开项目面板；用户不需要时跳过，后续复用。面板不可用或文稿缺少展示标记时，继续当前硬件工作。

## 文稿里的四部分

| 部分 | 写什么 | 何时更新 |
| --- | --- | --- |
| 顶部当前交接 | 当前方案和结果、卡点、下一步、正文与证据入口 | 工作焦点、稳定结果或下一步变化时 |
| 设计正文 | 采用什么方案、为什么、必要参数与连接、当前检查和未决项 | 对应设计或事实变化时 |
| 按需面板摘要 | 需要在面板展示的章节要点，从正文归纳 | 本次变化影响已有摘要时 |
| 可选结构化记录 | 当前工具入口、输入版本、证据及检查范围 | 采用记录的长流程需要续接或核对引用时 |

顶部便于接手，正文保留完整设计。面板摘要与结构化记录各有用途，按需采用；不要把同一段状态复制到所有章节，也不为同义字段再建一份交接。

## 正文结构

按项目进展填写已有内容，保留稳定章节和目录链接。下面只示意主题；没有进入的阶段不用填空表，特殊项目可以调整小节。项目自己的章节编号可以沿用。Skill 操作页和面板参考树有各自编号，通过标题定位项目主题，不要求三套编号对齐。

```markdown
# <项目名称>

Updated: <时间>
Project root: <绝对路径>

## 0. 当前交接

- 当前方案与结果：<当前采用的方案及已确认范围>
- 卡点：<影响本次任务的未决条件；没有则省略>
- 下一步：<一个可执行动作及必要前提>
- 入口与证据：<本次项目章节、输入版本和相关报告>

## 目录

## 1. 需求、架构与器件

### 1.1 设计意图、使用场景与验收目标
### 1.2 需求、非目标与设计限制
### 1.3 功能框图、电源树与外部接口
### 1.4 器件选择、库存复用、采购缺口与资料依据
### 1.5 默认状态、故障行为与固件/机械依赖

## 2. 原理图设计

### 2.1 电路分块、用途与相互关系
### 2.2 元器件用途、物理引脚与网络
### 2.3 关键计算与设计余量
### 2.4 测试点、调试/烧录接口与样机确认项
### 2.5 当前原理图实现、保存及检查状态

## 3. PCB 设计

### 3.1 板框、层叠与机械约束
### 3.2 布局与空间
### 3.3 网络规则
#### 布线规则与优先级
#### 线宽调整
#### 网络配色
### 3.4 关键拓扑、功率环路与回流路径
### 3.5 预留区、散热、装配与访问限制
### 3.6 当前布局、布线、铺铜、保存及 DRC 状态
```

顶部保留三四个短条目，没有内容的项省略。详细检查、长清单和有价值的历史结果放回对应正文，注明版本和证据。顶部所指章节应能定位当前目标、输入和执行入口；不累积历轮摘要。

### 让正文真正可读

- 说明提供本次判断、动作或交接所需的信息。介绍一个设计部分时，先说明用途、当前方案和关键理由，再展开必要参数、连接与验证依据。按主题展开，不用通用原则代替当前判断，不强套同一段落模板；完整日志引用证据文件。
- 约束注明来源和范围，区分硬性要求、暂定假设与待测项。缺少依据时说明缺口及影响。
- 原理图按功能块说明工作方式，在同文档保留器件用途表和引脚表：`位号｜器件/作用｜物理引脚号｜语义功能｜网络｜默认状态｜必连/NC/DNC`。长表按功能块分组，不只留下 JSON 链接；资料与实际映射有差异时写明。
- PCB 功能块说明 `块名｜成员位号｜位置/朝向｜固定或可移动条件｜必须保持的邻接/环路｜布局理由`。块名与原理图对应，保留跨块关键网络；当前布局图注明来源版本。
- 制造部分对应同一候选的源文件、Gerber、钻孔、BOM/CPL 和检查结果。测试部分保留条件、预期、实测、结论与证据。

### PCB 主题与面板对应

PCB 正文保留“布局与空间”和“网络规则”两个主题。前者解释块、成员、姿态、固定条件、预留与布局理由；后者保留网络名称／线宽／颜色汇总，以及布线顺序和尺寸依据、改宽范围、配色结果、保存及检查范围。计划值、实际回读和历史结果分别注明来源与适用版本。

这两个主题的项目编号不必改变。需要在面板显示网络表格时，按 [View State 文稿格式](../view-state/README.md#网络表格)加展示标记；固定面板槽位与旧标题兼容也由该页说明。

### 给 View State 的简短交接说明

只为需要展示的章节补摘要。顶部摘要讲本次工作焦点，阶段和主题摘要讲各自最值得知道的设计或结果；正文继续保存完整依据。写法、放置位置和读取标记见 [View State 文稿格式](../view-state/README.md#当前阶段与摘要)。

## 信息归属与更新

| 事实 | 来源 | 主文稿中的视图 |
| --- | --- | --- |
| 需求、限制、选择理由 | 用户决定与当前设计依据 | 正文解释和已接受决定 |
| 器件及引脚网络意图 | Contract；物理引脚号核对准确资料与 Provider 映射 | 可读器件/引脚表，注明来源版本 |
| 实际器件、连接与布局 | EDA 源文件及回读 | 已实现范围、布局关系、图与检查结论 |
| 制造与样机表现 | 制造输出、原始测量和测试记录 | 候选、条件、结果与限制 |

先更新拥有事实的制品，再刷新正文对应视图。表格可以完整，但不与 Contract／EDA 各自独立手填。缺少引脚号、映射或回读时标为未知。

稳定设计变更、阶段切换或交接时，按受影响的器件、网络、接口和功能定位正文。更新当前方案、理由、表格与未决项；有价值的旧方案和旧检查标为历史，注明版本、时间及被替代原因。依据有冲突时保留冲突和待核对内容。

更新结束前，只核对本次受影响的顶部、正文、事实表、未决项及已经采用的摘要或结构化记录。已解决事项移出当前未决，未同步部分明确标注；无变化不重写，小批次不重复生成整份文稿或重跑 EDA 检查。文稿更新时间不等于检查时间。执行状态、保存与未知结果按 [0.3 共同规则](0.3-easyeda-pro.md#现场边界与验证)核对，再把结论写回本次章节。

## 按需使用文稿工具

重复维护原理图事实表时，可用 `handoff-sync` 从已有输入刷新选定生成区。长流程需要核对入口和证据引用时，可用 `handoff-check` 检查可选结构化记录。参数、格式、输出及写入保护见 [0.5 工具与记录参考](0.5-handoff-record.md)，普通文字文稿仍可直接续接。

活动问题需要多轮实验时按 [0.2 聚焦调试](0.2-debug-loop.md)保留临时记录；稳定设计和仍有价值的理由回到主文稿。
