# View State

FlitRealize 内置的只读交接网页小窗，随 Skill 仓库和新构建的运行包一起分发。预设 **240 × 840 CSS 像素**，预览空间不足时适应可用高度。浅色半透明面板、小圆角与轻阴影参考 LiteMonitor，强调色沿用 FlitFancy 网页渐变。尺寸集中在 public/app.css 的 --panel-width / --panel-height。Skill 负责写梗概，VS 负责显示。

## 启动

需要 Node.js 22 或更高版本和浏览器，无第三方 npm 运行依赖，无需安装或编译桌面程序。

在 Skill 根目录运行，将 `<PROJECT_ROOT>` 替换为项目绝对路径：

```sh
node view-state/server.mjs --project-root "<PROJECT_ROOT>"
```

打开 [127.0.0.1:49700](http://127.0.0.1:49700)。点击顶部项目名切换目录；也可用 URL 参数 projectRoot 指定项目。`--port` 可更改端口；`--home` 可指定本机 FlitRealize 状态目录，用于读取桥接状态。

```sh
node view-state/cli.mjs --project-root "<PROJECT_ROOT>"
```

源码仓库的统一测试入口同时检查 Skill 与 View State；运行包不包含测试：

```sh
npm test
```

## 由 Skill 拉起面板

1. 使用当前安装的 Skill 根目录和用户指定的项目绝对路径，确认 `node --version` 至少为 22。工程目录与 Skill 目录分开；纯查看时，缺少 `CURRENT_HANDOFF.md` 也不自动创建。
2. 请求默认地址的 `/api/health`。返回 `service: "flitrealize-view-state"`、`schemaVersion: 1`、`readOnly: true` 时复用服务。不同项目共用一个服务，通过页面的 `projectRoot` 参数选择。若无服务则启动；端口已被其他程序占用或无法确认身份时，用其他空闲端口，不终止未知进程。
3. 用本节上方命令启动，必要时加 `--port <端口>`。使用宿主支持的后台进程机制；Windows 的 `Start-Process` 使用 `-WindowStyle Hidden`，含空格的路径分别正确引用。记下本次启动的进程与输出地址，以便后续停止；不要每次续接再启动一份。
4. 确认服务已输出地址或健康检查通过，再用宿主浏览器能力打开 `<服务地址>/?projectRoot=<URL 编码后的项目绝对路径>`。这一步显式指定项目，避免复用服务时误看其默认项目；浏览器不可用时提供可点击地址。
5. 通过 `/api/status?projectRoot=<同一编码路径>` 和页面项目名核对目标。缺少主文稿显示未记录，缺少 `ViewState:` 显示未提供梗概，旧文稿仍可阅读全文；桥接未连接不阻止查看。用户要求更新梗概时才回到[续接说明](../references/0.1-continuation.md)整理实际内容，随后刷新。

停止前台服务用 Ctrl+C。后台服务仅停止本次启动且已确认归属的进程；复用的服务可能仍被其他项目页面使用。

## 数据约定

唯一工程内容来源是项目根目录的 CURRENT_HANDOFF.md。写作规则由 [项目续接说明](../references/0.1-continuation.md)维护：

- 界面采用 skill 的固定编号与分组，项目文稿标题用于定位来源；章节下的 `ViewState:` 独立物理行提供梗概，按原文展示。界面编号不等于项目文稿的小节编号。
- 英文名称以当前 references 文件的英文标识为依据，集中在 public/names.mjs；中文是独立显示映射，缺失翻译时保留英文。分组及运行信息是 VS 自身栏目，明确与参考文档区分。首次使用默认英文，之后记住语言选择；切换语言不改变节点身份、梗概、原文标题或定位。不采用 docs/en-backup 历史备份，也不改变 skill 中文正文的执行源地位。
- `flitrealize:facts:start/end` 自动事实表区域只在原文显示，不把表内标题或文字变成导航与梗概；该区域所属章节可在区域外编写梗概。
- 顶部“当前交接”的 `当前阶段:` 精确对应阶段标题（不含编号），用于标出当前位置。
- 没有梗概就提示“未提供梗概”，不会截取正文补齐；重复标记视为歧义并提示检查。
- 不根据正文、检查日志、器件、文件时间或连接情况判断工程完成度。
- 主树完整保留 0.x～6.x，点击分组原地展开 skill 子项，再点击子项展开梗概和原文链接。5.x 样机验证、6.x 产品化分别保留。当前未决事项放在 0.1 当前交接中。
- 网页小窗用轻量列表展示阶段，展开正文优先显示梗概，再显示未提供的工程状态。子项展开时按需滚入阅读区，阶段标题随滚动保留；“全部收起”返回总览，底部固定提供整份交接入口。时间戳显示本地月日和时分，悬停可查看文稿原始时间，未重新解释为验证时间。
- 0.x 包含项目概况、交接、当前模式、桥接、环境与续接记录；1.x 包含需求与器件；后续子项对应原理图、PCB、制造、样机、产品化的实际 skill 入口。音频已归入 skill 的 D.1 专项参考，不在通用阶段树单列，相关项目内容仍可从交接原文查看。映射集中在 public/navigation.mjs，未映射的主题仍可从对应原文查看。
- 缺少源章节显示“未记录”，已存在梗概不代表完成。模式、工程状态和库存匹配计数目前尚无专用数据字段，这版明确显示“未提供”或“—”；不解析正文猜测，也不显示草图里的示例数字。
- “阅读全文”单独打开主文稿阅读页，按标题和行号定位，支持下载原文件。

旧交接文稿没有标记时仍能浏览标题和原文，需要由 skill 更新交接后才会出现梗概。VS 不生成或回写这些内容。

## 连接与刷新

顶部桥接状态独立检查本机 FlitRealize 会话目录及对应 loopback Bridge 的 /health，仅在服务、协议、会话和 EDA 连接匹配时显示连接。它不代表当前项目已验证。不会返回会话令牌。

前台每 5 秒重新读取文稿与桥接状态，也可手动刷新。无需监听、缓存或后台扫描。刷新保留当前阅读位置；同一项目读取失败保留上次内容并提示，切换失败不显示旧项目数据。

## 实现

- lib/handoff.mjs：固定标记与标题解析。
- lib/project.mjs：只读主文稿、项目目录和路径检查。
- lib/bridge.mjs：独立桥接健康检查。
- server.mjs：仅绑定 127.0.0.1；GET /api/health 确认服务身份，GET /api/status、GET /api/document 和静态页面提供只读视图。
- public/navigation.mjs：导航分组和原文定位。
- public/names.mjs：英文命名来源与中文显示映射。
- public/app.js、app.css：小窗、项目切换、刷新与中英界面。
- public/document.*、format.mjs：独立原文阅读页及安全文本格式化。
- tests/：解析、桥接、导航与 HTTP 边界回归。

服务不会写入项目文件；不包含桌面封装、工程状态聚合、正文摘要提取、Contract/证据扫描、文件监听或演示数据。
